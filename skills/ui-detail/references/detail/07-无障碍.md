# 07 · 无障碍：用键盘和读屏器走完同一条路

> **适用**：自绘下拉、模态、图标按钮或表单刚做完，要在交付前用键盘与读屏器把「查找→编辑→保存」这条真实任务完整走一遍时。
> **本轮不可交付时**：若这一轮只动视觉稿与配色间距、不涉可操作控件与焦点路线，停下并说明「没有可走的键盘路径」，改读 [03-布局与排版](03-布局与排版.md) 或 [04-颜色与对比度](04-颜色与对比度.md)。
> **读完能判定**：该用原生 button/a 还是 role、值不值得承担补齐行为的成本；Tab 顺序是否与任务一致、正数 tabindex 值不值得；模态焦点怎么进、怎么限制、关闭后回哪、危险确认默认是否落在危险按钮；焦点环是否真的可见、是否被自己创建的内容遮住；热区按 24 还是 44、相邻是否误触；播报用 status 还是 alert、是否过量。

试着不用鼠标完成一次“查找项目 → 编辑负责人 → 保存”。如果第二步卡在自定义下拉框，说明页面即使视觉完整，交互仍然没有完成。

## 原生语义能替你承担很多工作

执行动作使用 `<button>`，跳转使用带 `href` 的 `<a>`。原生按钮自带键盘行为和语义；给 `<div>` 加 `role="button"` 后，还要自己补聚焦、Enter、Space、禁用等行为。

`nav`、`main`、标题层级帮助用户定位页面。Skip link 可以让键盘用户跳过重复导航；不要为了“结构整齐”把所有文字都做成无层级的 div。

ARIA 用于补充名称、角色与状态，不会自动实现交互。`aria-expanded` 不会替你打开菜单，`aria-modal` 也不会锁住焦点。

```html
<button type="button" aria-label="关闭项目详情">
  <svg aria-hidden="true" focusable="false"><!-- 图标 --></svg>
</button>
<label for="project-name">项目名称</label>
<input id="project-name" aria-describedby="name-help">
<p id="name-help">2–40 个字符</p>
```

图标按钮需要可访问名称；若按钮本来已有清楚的可见文字，通常不必再用 `aria-label` 覆盖它。

## 焦点是一条有顺序的路线

正常 Tab 顺序应与阅读和操作顺序一致，尽量避免正数 `tabindex`。Tabs、菜单、树等复合控件还可能用方向键在内部移动，需要遵循对应模式，不能让每个选项都随意抢进 Tab 顺序。

模态打开后，焦点移入内部，Tab 与 Shift+Tab 留在其中；关闭后合理返回。长内容可以先聚焦标题等静态元素，危险确认也不应默认把焦点放在最容易误触的危险按钮上。

```css
:focus-visible {
  outline: 3px solid var(--focus-ring, #005fcc);
  outline-offset: 3px;
}
```

这是焦点环示例，仍需在实际背景上检查。`:focus-visible` 使用浏览器启发式判断，不是严格的“鼠标永远不显示”；输入框被点击后也可能匹配。

WCAG 2.2 AA 要求焦点可见（2.4.7），且不被作者创建的内容完全遮挡（2.4.11）。AAA 的 2.4.13 还规定焦点外观的面积与聚焦前后至少 3:1 的变化等条件。不要用一条颜色规则代替全部要求。

## 热区与图标大小分别算

WCAG 2.2 AA 的 2.5.8 通常要求至少 24×24 CSS px，也有间距、等效控件、行内文本、用户代理控制和必要性等例外。间距例外有具体的 24px 直径圆判定，不能简单等同于“相隔 8px”。

AAA 的 2.5.5 通常为至少 44×44 CSS px，也有自己的例外。Apple 常用 44×44pt，Material 常用 48×48dp，这些平台单位不要直接等同于 CSS px。

```css
.icon-button {
  inline-size: 44px;
  block-size: 44px;
  display: inline-grid;
  place-items: center;
}
.icon-button svg { inline-size: 20px; block-size: 20px; }
```

扩大热区后别互相重叠。删除与编辑挨得太近，即使各自够大，也可能造成误操作。

## 动态消息要让人听见，也能回看

保存成功可用 `role="status"`，通常以礼貌方式播报；急需关注的错误可以考虑 `role="alert"`。不是所有错误都应该打断读屏，列表连续更新也不该每条都播。

```html
<div role="status" id="save-status"></div>
```

先在页面上准备区域，再更新其内容，有利于可靠播报。避免同时重复设置多套直播语义造成重复朗读。消息里若有操作，不要只依赖一闪而过的播报；给它稳定的可见入口和合理的键盘路线。

视觉隐藏的辅助文字应采用成熟的 visually-hidden 样式。`display:none` 和 `visibility:hidden` 通常也会从无障碍树隐藏内容，不适合“只给读屏看”的文本。

## 还有两种常漏掉的环境

在 Windows 强制颜色模式下，背景色和阴影可能被覆盖。用 `@media (forced-colors: active)` 检查边界，用系统颜色补必要轮廓；不要无理由全局禁用系统调色。

在 200% 文本放大、窄视口和用户修改行距后，内容仍应可读。WCAG 1.4.10 的常见重排检查是约 320 CSS px 宽的视口，存在二维布局等例外；水平表格可以另行处理，但不能让整个表单横向溢出。

完成键盘检查后，再用实际读屏器听一次名称、状态和错误。自动扫描可以发现缺少 Label 等问题，却不能证明任务顺序合理，也不能证明模态焦点已经处理正确。
