# AI Explore（内联模式）— 深度探索对话

> **模式说明**：回答者和追问者都由主 agent 在同一上下文内扮演。不调用子 agent。
> 优势：速度快、上下文完整不丢失细节、逻辑链连贯。
> 劣势：追问者知道回答者的推理过程，提问可能不够"陌生"和犀利。

## 核心机制

```
用户输入 → [回答者回答] → [追问者提问] → [回答者回答] → ... → 收敛 → 输出完整对话
```

两个角色，始终只有两个：
- **回答者**：提供知识、解释、分析、例子、类比
- **追问者**：专职提问——替你问 + 帮你发现

## 执行模式：内联自演（不调用子 agent）

**主 agent 在同一个上下文里交替扮演两个角色。** 具体操作：

1. 主 agent 以"回答者"身份生成回答 → 写入文件
2. 主 agent **切换视角**，以"追问者"身份审视刚生成的回答，找到最有价值的追问 → 写入文件
3. 主 agent 再切换回"回答者"身份回答 → 写入文件
4. 重复直到收敛

**切换视角时的关键操作**：
- 回答者写完后，**主动反思自己的盲区**——"我刚才的推理跳过了什么？假设了什么？"
- 追问者提问时，**假装自己是第一次读到这个回答的读者**——"哪里没看懂？哪里觉得可疑？哪里觉得值得深入？"
- 追问者**只看回答的文字输出**，不要利用自己推理过程中"知道但没说出来"的信息来提问

## 流式写入 REQUIRED

每轮完成后 **立即 append 到输出文件**，不要等到最后才写。这样即使中途中断，已完成的轮次也不会丢失。

**输出文件路径**：当前工作目录下 `ai-explore-{主题关键词}.md`（英文短横线连接，2-4 个词概括主题）。

**文件初始化**（Phase 0 完成后）：
- 用 `write` 创建文件，写入标题、问题目录表头、`## 完整对话` 标题
- 后续每轮用 `edit` 或 bash `echo >>` append，不要覆盖已有内容

**原文保留规则**（Phase 0 同步执行）：用户的原始输入有独立阅读价值，必须保留在输出文件中，不要丢弃。
- **短原文**（≤500字左右）：在文件标题和问题目录之间插入 `## 用户原文`，用 `<details><summary>点击展开用户原文</summary>` 包裹原文全文，`</details>` 结束。
- **长原文**（>500字）：原文单独存为 `ai-explore-{主题关键词}-source.md`，主文件在标题下方放一行引用链接。

**写入节奏**：
| 时机 | 写入内容 |
|------|---------|
| Phase 0 完成 | 文件头（标题 + **原文折叠/链接** + 目录表头 + 对话标题） |
| 每轮回答者回答后 | 该轮完整内容（追问 + 回答） |
| Phase 2 收敛 | 探索摘要 |
| 最后 | 回填问题目录表 |

## 异常与失败处理 REQUIRED

- context 过长 → 每轮对前序对话做摘要压缩，保留关键论点原文
- 收敛判断不确定 → 倾向多问一轮（保守策略）

---

### Phase 0: 理解输入

1. 读取用户的输入（想法、概念、问题、或一段话）
2. 识别主题领域和复杂度
3. 确定输出文件名：`ai-explore-{主题关键词}.md`，创建文件并写入标题和骨架
4. 如果输入过于模糊 → 问一个澄清问题，然后继续

---

### Phase 1: 第一轮回答

直接以回答者身份给出第一轮回答。回答完成后 **立即 append 到输出文件**。

**回答者的 prompt**：

```
用户提出了以下问题/概念/想法：

「{用户输入}」

请给出第一轮回答。要求：
1. 核心解释——用清晰、准确的语言解释这个概念/回答这个问题
2. 关键前提——你的回答建立在哪些假设之上？
3. 具体例子——至少一个具体案例或类比帮助理解
4. 边界条件——你的回答在什么情况下不成立？
5. 值得知道的意外——有什么反直觉的点？

回答风格：清晰 > 花哨。一句话只说一件事。有歧义时拆成两句。
```

---

### Phase 2: 探索循环

每轮包含：**追问者提问 → 回答者回答**

#### 2.1 追问者提问（内联：主 agent 切换视角）

先读取 [`references/questioner-guide.md`](references/questioner-guide.md) 完整内容。然后**切换到追问者视角**，基于上一轮回答生成问题。

**追问者的 prompt**：

```
你是一个专业追问者。你的职责不是回答问题，而是提出下一个最有价值的问题。

你有两重职责：
1. **替用户问**：填补理解缺口，追究说不清的地方，匹配用户可能的知识基础
2. **帮用户发现**：提出用户未必会想到、但看了会觉得值得的问题

当前对话历史：
{conversation_history}

上一轮回答：
{last_answer}

追问质量要求（详见 questioner-guide.md）：
- 检查：读者可能没真正理解的地方？
- 检查：回答暗含了什么前提？
- 检查：有没有反例或具体例子能帮助理解？
- 检查：如果这是真的，会推导出什么有意思的结论？
- 检查：它和其他已知概念有什么联系？
- 检查：哪个意外的方向值得顺着探索？

反模式（必须避免）：
- 不要重复问已经覆盖的问题（换个说法也不行）
- 不要突然跳到完全不相关的领域
- 不要为了凑轮数不停深挖同一个点

输出格式：
{
  "question": "你的下一个问题",
  "rationale": "为什么这个问题值得问（一句话）",
  "category": "理解缺口/前提追究/反例探索/推导延伸/跨界联系/意外方向",
  "confidence_this_question_is_valuable": 1-10
}
```

**收敛自评**：

如果 `confidence_this_question_is_valuable < 6`，追问者应输出：
```json
{
  "question": null,
  "stop_reason": "没有足够有价值的新问题了",
  "coverage_summary": "已覆盖的主要方向总结"
}
```

#### 2.2 回答者回答

基于追问者的问题给出回答。**回答完成后，立即 append 该轮内容到输出文件。**

**回答者的 prompt**：

```
你正在和一位追问者进行深度探索对话。用户会阅读完整对话记录。

当前对话历史：
{conversation_history}

追问者的最新问题：
{question}

请回答这个问题。要求：
1. 直接回答——先给结论/答案，再展开
2. 具体——用案例、数据、代码、类比，不要纯抽象
3. 诚实——不确定的说不确定，有争议的列出不同观点
4. 衔接——如果和前面的回答有关联，明确指出来
5. 意外——尽量包含一个读者不知道但有价值的信息

回答风格：清晰 > 花哨。一句话只说一件事。有歧义时拆成两句。
```

#### 2.3 用户介入点

每轮结束后：
- 追问者输出问题后，如果用户输入了指令 → 执行（调整方向、深入某点、跳过、结束）
- 用户说「继续」或无回应 → 回答者回答，进入下一轮
- 用户说「结束」→ 进入 Phase 3

#### 2.4 收敛判断

由追问者的 `confidence_this_question_is_valuable` 驱动：

- confidence >= 6 → CONTINUE
- confidence < 6 → CONVERGE
- 达到 10 轮 → 强制 CONVERGE
- 用户要求结束 → CONVERGE

**保守策略**：拿不准时倾向多问一轮。

---

### Phase 3: 收尾输出

1. **回填问题目录表**
2. **Append 探索摘要**（覆盖方向、关键发现、未探索方向、核心结论）
3. **告知用户文件路径**

格式见 [`references/output-template.md`](references/output-template.md)。

---

## 关于追问质量

追问者是整个系统的灵魂。详见 [`references/questioner-guide.md`](references/questioner-guide.md)。

核心原则：
- **不重复**：已覆盖的问题不问第二遍（换个说法也不行）
- **不跳跃**：问题之间有逻辑链条，不要突然跳到完全不相关的领域
- **不凑数**：没有好问题就停，不要为了轮数硬问
- **有价值**：每个问题都应该让读者觉得「这个问得好」
