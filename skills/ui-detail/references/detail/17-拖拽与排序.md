# 17 · 拖拽与排序：拿得起、放得准、退得回

> **适用**：实现或验收可拖拽列表、看板跨列移动或手动排序，要判定拖到哪、能不能放、取消与保存失败分别怎么收尾时。
> **本轮不可交付时**：若界面只是固定顺序展示、没有拖动或跨列移动，停下并说明「无拖动动作」，改读 [11-表格与列表](11-表格与列表.md) 的列表部分。
> **读完能判定**：是否提供不用拖也能完成的替代路径、键盘模式是否写清；拖动各阶段是否保留占位与跟手预览、插入位置是否可辨、无效目标是否不只靠颜色表达；目标位置语义、跨列是否连带改状态与权限、空列能否接收；取消路径是否都回原位且不发隐藏请求；提交按什么身份、保存失败是回原位还是待同步。

## 一、先判

1. **拖拽不是让卡片跟着指针就结束**：用户需要知道哪里能放、放下会发生什么、不想移动时如何退出、保存失败后又会怎样。
2. **先提供不用拖也能完成的路径**：给卡片「移动到」菜单、上移下移按钮或目标位置输入，键盘与触屏用户都能完成同一任务，精细排序也更容易。WCAG 2.2 的拖动动作要求在适用条件下提供无需拖动的单指针替代，只加键盘操作不能认为全部满足。
3. **同时提供键盘拖拽模式时**，要清楚说明拿起、移动、放下与取消的按键，并反馈当前位置；不要随意复用已废弃的 ARIA 拖拽属性，优先选成熟实现并实际用读屏器验证。
4. **准备阶段要区分点击、文本选择、滚动和真正拖动**：用明确手柄与合理移动阈值；触屏长按需要与系统菜单、页面滚动协调，不能一碰卡片就禁止整页滚动。
5. **拖动中保留原占位**，预览跟手，插入线或容器高亮清楚可辨；无效目标明确拒绝，不靠颜色单独表达；放下后位置应与预览一致，不能松手才跳到另一处。
6. **目标位置可预期**：排序列表要说明插在目标上方还是下方；跨列移动要说明是否连带改变状态、权限和字段；空列也要有可接收区域，否则没有卡片就无法拖进去。
7. **边缘自动滚动只在合理区域启动**、限制速度、离开边缘即停止；页面和内部列表都是滚动容器时，明确哪一层接收滚动，防止预览与真实位置分离。
8. **业务会自动排序时不要假装允许手动自由排序**：若按时间或名称自动排序，先改变排序模式，或清楚说明拖动改变的是状态而非永久行序。
9. **取消路径都要有明确结果**：Esc、失去有效指针序列、`pointercancel`、放到无效区域，都回到开始前的位置，不应发出一次隐藏的持久化请求；拖回原位通常无需保存。
10. **提交按稳定对象 ID 与目标身份记录**，不能只提交「数组第 3 项移到第 5 项」；并发更新后下标可能已经改变，持久排序协议可采用邻居 ID、排序键或服务端版本校验，取决于后端契约。
11. **保存失败的收尾二选一**：回到旧位置并说明，或保留待同步状态并提供重试；不要静默回滚覆盖用户之后的另一次移动，新旧操作要有关联和版本管理。对象在拖动期间被别人删除或失去权限，也需要清楚解释。
12. **动画服务于位置理解**：预览追踪指针尽量直接，其他卡片让位可用短过渡，放置与取消可适度回到目标，但逻辑结果不能依赖动画结束；减少动效时仍保留插入位置、目标状态与最终结果。
13. **拖动结束后处理焦点与播报**：把焦点留在移动后的对象或合适入口，播报「已移到已完成，第 2 项」这类简短结果，避免每一像素移动都播报。

## 二、做完的标准

- [ ] 同一张卡片用拖拽和「移动到」完成一次跨列移动，结果一致；只用键盘也能走完同样一步。
- [ ] 拖到空列、无权限列、视口边缘各一次：空列能接收，无权限列明确拒绝且不只靠颜色，边缘自动滚动只在边缘启动并在离开时停止。
- [ ] 过程中按 Esc、滚动页面、切出窗口、触发 `pointercancel`：都回原位，网络面板里没有多出来的写请求。
- [ ] 让保存失败一次：要么回到旧位置并说明，要么显示待同步并可重试，且不会覆盖用户之后的第二次移动。
- [ ] 快速连续移动同一对象，最终位置与服务端最终状态一致，没有停在中间下标。
- [ ] 触屏上整页仍能滚动，长按与系统菜单不冲突，选择手柄行为正常。

## 三、依据与数值

- WCAG 2.2 关于拖动动作的要求是**标准要求**：适用条件下必须提供无需拖动的单指针替代（见篇末 Understanding 链接）。
- 移动阈值、边缘滚动速度与启动区域属**项目起点**，按设备与列表密度调；本篇不给具体数值门槛。
- 并发排序协议（邻居 ID / 排序键 / 版本校验）属**后端契约**，不是平台约定，也没有跨产品统一答案。

## 四、控件、表格与示例

一次拖拽的状态：

```text
静止 → 准备拖动 → 拖动中 → 可放置 / 不可放置
                         → 放下后保存 → 已确认 / 保存失败
                         → 取消 → 回到原位
```

## 五、失败长相与边界

- **松手后卡片才跳到另一处** → 预览与插入位置不同步，或放下后按另一套规则重排；放置结果必须与预览一致。
- **拖到空列放不进去** → 空列没有可接收区域，或接收区域只存在于有卡片的位置。
- **取消之后服务端顺序还是变了** → 取消路径发了隐藏的持久化请求，或回原位被当成一次移动提交。
- **快速连续移动后顺序错乱** → 只提交了下标，并发更新后下标已失效；改用对象 ID 与版本校验。
- **保存失败把用户之后的第二次移动也回滚了** → 失败处理静默覆盖了新操作；要有操作关联与版本管理，或保留待同步并说明。
- **读屏器里拖拽完全不可用** → 没有替代路径，或键盘模式没写清拿起、移动、放下、取消的按键与当前位置。
- **边界**：业务自动排序规则优先于手动排序；拖回原位通常不保存；减少动效只去掉动画，不减少插入位置、目标状态与结果反馈。
