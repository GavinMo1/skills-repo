# 08 · 落地：一套 Token 与一次完整验收

> **适用**：要把前几篇的判断在项目里统一成一套变量，并用同一条真实路径（含保存失败、慢网重复提交、明暗切换）做一次完整交付验收时。
> **本轮不可交付时**：若这一轮还在推敲某个组件内部的交互细节、不到统一约定与整体验收，停下并说明「未到验收」，改读对应的组件篇（[09](09-输入框的手感.md)–[17](17-拖拽与排序.md)），不要用本篇清单代替动手。
> **读完能判定**：哪些重复决策该收进原始值、语义值或组件 Token；一个组件的行为是否写清到足以验收；一次交付检查是否覆盖加载、无结果、键盘、校验错误、慢网重复提交、保存失败重试、未保存关闭、主题切换、窄屏放大与读屏器；「已保存」指哪一次请求的快照；一条验收结论该记成哪一类、记录里缺哪些条件。
> **超限理由**：R3 要求原样保留、且不得改写块内文字的 CSS 变量块占 63 行；剩下的篇幅由三块证据占住——组件行为契约表（R4 的依据）、13 条真实交付路径、保存失败对照表（R5 的症状原话与失败条件），再压只能整块删表，属 §3 禁止的「为数字好看删结论」；其中 13 条路径还与 `stage/06-自查清单.md` 同源（该文件第 7 行把本篇指为同源清单），删掉会让那个指针失效。

## 一、先判

1. **先分这一轮要哪种产出**：要统一约定 → 一套小而明确的 Token（原始值 → 语义值 → 按需组件 Token），示例那套用于普通 Web 应用起步，不是完整设计系统；要交付验收 → 一条含保存失败、慢网重复提交、明暗切换的真实路径。两者都做时，先 Token 后验收。
2. **语义变量名要表达约束**：`border-subtle` 是装饰线，`border-control` 才准备承担控件识别，不要为了少建变量让两者混用；层级变量只约定普通页面中的顺序，不能跨越层叠上下文和浏览器 top layer 的限制。
3. **主题的开关语义先定**：`data-theme` 表示用户的显式选择，`data-theme="light"` 使用默认浅色值，移除该属性即恢复跟随系统；两份深色映射为了让原生 CSS 示例容易直接理解而重复，实际项目可用构建工具生成，避免漏改。
4. **「使用标准 Dialog」不足以交付**：一个组件的行为至少写清打开、模式、提交、错误、关闭、返回焦点、小屏七项（以编辑项目为例，见第四节）。
5. **「已保存」要说清是哪一次请求的快照**：提交时固定本次内容快照；在途只允许一个请求，但输入保持可编辑；失败保留内容；成功只确认请求快照；当前内容与已确认内容不同，就继续提示未保存。
6. **验收走同一条真实路径**：先备好短标题、超长标题、空项目、无权限项目、失败响应和大量列表数据，再从列表进入一路走完——搜索、键盘打开、制造校验错误、日期面板、慢网连续提交、保存失败重试、未保存关闭、切主题、窄屏与放大、200%、减动效、读屏（清单见第四节）。
7. **四种手段回答不同问题**：截图看间距与视觉层次，键盘看焦点路线，读屏器看名称和动态反馈，浏览器工具看性能与对比度，缺一个就有盲区；动效的毫秒数不是验收结论，要看短过渡是否帮助识别变化、有无打断输入、有无增加等待。
8. **结论先归三类再记录**：标准类引用成功准则，平台类记录设计系统与版本，经验类数值记录采用理由——以后从 220ms 调到 180ms，团队才知道改的是项目取舍，而不是违反了某条不存在的规范。记录粒度写全浏览器、设备或视口、主题、数据条件、操作、预期、实际；只写「已测」等于没记。

## 二、做完的标准

- [ ] 重复决策都能指到具体变量：间距落到 `--space-1`–`--space-6`，面板色落到 `--surface-*`，焦点落到 `--focus-ring`；组件 Token 只在确实独立变化时出现。
- [ ] 编辑项目这个组件的七项约定（打开 / 模式 / 提交 / 错误 / 关闭 / 返回焦点 / 小屏）都有具体答案，实现与验收都对着它走。
- [ ] 第四节的 13 条路径在同一条真实路径上连续走完，中间不跳步；按对象抽查则按 `stage/06-自查清单.md` 那张表收口，未采用的组件模式不必为它加实现。
- [ ] 「已保存」只在请求快照被确认之后出现：在途期间请求数仍为 1，输入框可继续编辑。
- [ ] 慢网连续提交、保存失败重试、有未保存修改时关闭，各走一次：没有重复创建，内容没丢，放弃后焦点合理返回。
- [ ] 主题切换与减少动效各复核一次：文字、控件、焦点与状态的必要对比都在，图片没有被无差别改色，交互仍能完成。
- [ ] 一条验收记录写全浏览器、设备或视口、主题、数据条件、操作、预期、实际，结论能按标准类 / 平台类 / 经验类归位。

## 三、依据与数值

- Token 里的 `.25rem`–`1.5rem` 间距、`1rem / 1.6` 正文、`140ms / 220ms` 动效、`10 / 100 / 200` 层级，以及那组颜色值，全是**示例值 / 项目起点**，不是标准要求。
- 减少动效时 `--motion-fast`、`--motion-panel` 归零（`prefers-reduced-motion`）与深色跟随 `prefers-color-scheme` 属**平台约定**，不是可选项。
- 220ms 改 180ms 这类动效时长是**项目取舍**，记理由即可；只有存在可引条款的结论才引成功准则。本篇不展开具体 WCAG 门槛与条号：对比度、焦点与热区的门槛在 04、05、07，链接见篇末。

## 四、控件、表格与示例

一套小而明确的 Token：

```css
:root {
  --space-1: .25rem;
  --space-2: .5rem;
  --space-3: .75rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
  --space-8: 2rem;
  --font-body: 1rem;
  --line-body: 1.6;
  --radius-control: .5rem;
  --radius-panel: .75rem;
  --motion-fast: 140ms;
  --motion-panel: 220ms;
  --ease-standard: cubic-bezier(.2, 0, 0, 1);
  --z-sticky: 10;
  --z-overlay: 100;
  --z-feedback: 200;
}

/* 默认浅色；data-theme 表示用户的显式选择。 */
:root {
  color-scheme: light;
  --surface-page: #f6f7f9;
  --surface-panel: #ffffff;
  --text-primary: #1f1f1f;
  --text-secondary: #595959;
  --border-subtle: #e2e2e2;
  --border-control: #767676;
  --focus-ring: #005fcc;
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    color-scheme: dark;
    --surface-page: #121212;
    --surface-panel: #1f1f1f;
    --text-primary: #e0e0e0;
    --text-secondary: #b0b0b0;
    --border-subtle: #3f3f3f;
    --border-control: #8c8c8c;
    --focus-ring: #8ab4ff;
  }
}
:root[data-theme="dark"] {
  color-scheme: dark;
  --surface-page: #121212;
  --surface-panel: #1f1f1f;
  --text-primary: #e0e0e0;
  --text-secondary: #b0b0b0;
  --border-subtle: #3f3f3f;
  --border-control: #8c8c8c;
  --focus-ring: #8ab4ff;
}
@media (prefers-reduced-motion: reduce) {
  :root { --motion-fast: 0ms; --motion-panel: 0ms; }
}
.panel {
  padding: var(--space-6);
  border-radius: var(--radius-panel);
  background: var(--surface-panel);
  color: var(--text-primary);
}
```

以编辑项目为例，一个组件至少记录这些：

| 项目 | 本例约定 |
|---|---|
| 打开 | 从项目操作按钮进入，初始焦点在名称字段 |
| 模式 | 模态，背景不可交互 |
| 提交 | 前端校验通过后请求服务端，保存中防重复提交 |
| 错误 | 保留输入；字段错误就近显示，系统错误在表单内展示 |
| 关闭 | 关闭按钮或 Esc；有改动时确认是否放弃；遮罩不关闭 |
| 返回焦点 | 回到原项目操作按钮；对象消失时回到合理的列表位置 |
| 小屏 | 单列布局，内容区可滚动，操作区域不遮挡聚焦字段 |

用同一条路径做交付检查：那 13 条逐项清单在 `stage/06-自查清单.md`，本篇不复述，验收时按那张表走，结果记成第二节第 7 条那份记录。

保存失败后继续编辑：用户保存 A 后继续输入 B，若把「任何请求成功」都当成「当前内容已保存」，B 就会被错误标记安全；另一个常见问题是保存失败后清空输入，迫使用户重填。准备一个能强制失败、能延迟返回的模拟请求，从默认状态开始：

| 操作 | 通过表现 | 出现以下情况就失败 |
|---|---|---|
| 将名称改为 A，让下一次请求失败，保存后在名称框按 Enter | 在途期间请求数仍为 1 | 重复发出请求，或清空表单 |
| 等待模拟请求结束 | 显示失败，A 仍在；可重新保存 | 没有错误说明，或按钮永远忙碌 |
| 再次保存 A，结束前立刻把名称改成 B | 已确认区后来变成 A；当前编辑区为 B，并明确仍未保存 | 把 B 标为已保存，或用 A 覆盖 B |
| 再保存 B | 当前与确认内容一致，显示当前内容已保存 | 仍确认旧值或丢失本次编辑 |

取证保留每次请求的版本与结果，连同最终两份内容、状态文字和请求数一起记录；截图展示当前状态，日志解释它怎样形成，并观察焦点是否仍在用户最后操作的位置。

## 五、失败长相与边界

- **保存 A 后继续输入 B，B 却被标成已保存** → 把「任何请求成功」当成了「当前内容已保存」。改回按快照确认，见第一节第 5 条。
- **保存失败后输入被清空，用户被迫重填** → 失败路径没有保留内容，也没说明影响。
- **按钮永远忙碌，或「保存中」时尺寸跳变** → 状态说明缺失；按钮尺寸要稳定，焦点不被结果提示抢走。
- **在途连点发出第二个请求** → 没有在途锁；输入可继续编辑，但请求只允许一个。
- **层级变量用在弹层上失效** → 变量只约定普通页面中的顺序，跨越层叠上下文和浏览器 top layer 就管不到。
- **边界**：模拟请求不涉及真实服务端，因此不能据此宣称生产幂等、离线恢复和版本冲突已通过；人工检查路径不能代替真实设备验证；`data-theme="light"` 与移除该属性是两件事——前者是显式选浅色，后者是跟随系统；只写「已测」不算记录。
- **这篇清单不覆盖的验收**：上传的取消与部分失败见 [14](14-上传与附件.md)，自动保存的旧版本确认见 [15](15-保存与草稿.md)，日期语义与时区见 [16](16-日期与时间.md)，拖拽的取消与失败恢复见 [17](17-拖拽与排序.md)。
