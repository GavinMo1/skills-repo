# 02 · 控件与交互

> **适用**：字段、校验、输入框、按钮、选择器要动手实现或改造时。
> **不适用**：只处理列表上传日期拖拽保存（03），或只查主题与无障碍判定（05）时。
> **读完能判定**：一个字段是否说清三件事；校验从何时起步、错误何时显示；禁用与只读怎么选；输入框三件事是否分开检查；按钮两段反馈与尺寸稳定；选择器的模式与三个值是否分开。

每个控件先回答两件事：它表达什么语义、有哪些状态、失败后如何恢复。只写视觉样式不算完成。

细则与理由：[02 导航与表单](../detail/02-导航与表单.md))、[09 输入框的手感](../detail/09-输入框的手感.md))、[10 按钮与选择器](../detail/10-按钮与选择器.md))。

## 字段：一个字段至少三件事

- 持续可见的 `<label>`（不是 placeholder）、当前值、规则说明（如 2–40 个字符），并用 `aria-describedby` 把说明与错误关联到控件。
- Placeholder 只做示例，消失后不能带走必要信息；辅助文字也不能因为淡而免除对比度。
- 控件按数据语义选：Checkbox 多选独立项、Radio 互斥、Switch 即时开关、Select 有限选项、Combobox 输入 + 建议、Slider 有范围数值。
- Switch 让人期待即时生效；若整页统一点保存，必须显示未保存状态，不能悄悄换一套保存模型。
- "选项超过十个就要可搜索"是伪规则；按选项长度、熟悉度、排序与使用频率判断。
- 日期选择器支持键入并说明格式；出生日期不让人翻几十年日历。
- 上传控件提前说明格式、大小、数量，并提供进度、失败原因与重试。

## 校验与提交

- 时机起点：失焦或提交时报错；错误出现后随输入更新，告诉用户修好没有。
- 错误显示条件是"已触碰或已提交过"，不是 `touched && invalid`——后者会漏掉从未触碰的必填字段。
- 校验失败保留已填内容，把焦点引到错误摘要或第一个错误字段。
- 替换 Helper 显示错误时，保留仍然必要的规则说明；错误不能只靠边框变红。
- 异步查重处理乱序：旧结果不能覆盖新输入；服务端仍要最终校验。
- 禁用 ≠ 只读：原生 `disabled` 不进 Tab 顺序也不提交；支持 `readonly` 的控件可聚焦、可复制、可提交；`aria-disabled` 只是语义，点击与提交要自己拦。
- 暂时不能编辑的内容，优先考虑直接展示可复制文本，而不是一律禁用。
- 表单里的辅助按钮（清空、显示密码、增加一项）设 `type="button"`；主提交走表单标准提交路径，点击与 Enter 行为一致，并处理 IME 组合状态。

## 输入框：三件事分开检查

1. **视觉状态**：默认 / hover / focus / 有值 / 校验中 / 出错 / 只读 / 禁用，可以同时存在（出错后再次聚焦仍要看得见焦点）。
2. **输入响应**：输入值与光标立即更新；搜索、预览、统计、请求可以延后。
3. **异步结果**：结果必须对应当前输入（代次或取消），失败不能伪装成"没有数据"。

硬规则：

- 聚焦过渡 120–180ms 只作用于颜色；焦点环不参与渐变，也不能被裁掉。
- 不在聚焦时把 1px 边框改成 2px：预留同厚度，或用不占布局的 `outline`。
- 不用 `transition: all`，明确列出要变化的属性。
- 浮动标签的收起条件是"聚焦或有值"，要覆盖自动填充、密码管理器回填、程序更新值；名称仍由真正的 `<label>` 提供。
- 错误文字出现不能让下方控件跳动：预留说明区域，或切换同一区域内容；长错误自然换行，不裁。
- 频率高的错误不每个字符都重复播报。
- 不为输入本身防抖：显示的值立即响应，只有请求防抖（远程搜索起点 150–300ms）；新字符一出现就让旧请求失效。
- 受控输入保持 DOM 稳定：不要每字符换 `key` 重建，避免丢焦点、破坏选区、打断 IME。
- 组合输入期间不发请求、不提交、不按字符截断；Enter 可能是在确认候选词，不能一律当提交。
- 格式化输入（金额、手机号）要测中间插入、选中替换、粘贴、删除、撤销；不要拦所有按键，`inputmode` 也不替代校验。
- 字符计数说清口径（UTF-16 码元 / 字素簇 / 字节），前后端一致；超限不切坏 Emoji。
- 清除按钮用真实按钮并提供名称，预留尾部空间，清除后焦点回到输入框，并更新筛选、校验与请求状态。
- 密码显示切换保留值与合理选区，说明当前是显示还是隐藏，并配好 `autocomplete` 与字段名。
- 多行自动增高：即时贴合内容、设最大高度、之后内部滚动，删除与粘贴时保持编辑位置可见。

## 按钮

- 反馈分两段：按下（按压态）+ 进行中（保存中 / 已保存 / 失败）。接口再快也要有第一段。
- Loading 不改变按钮尺寸：保留文案或预留图标位；不按中文四字硬编码宽度。
- 进行中阻止本页重复提交；正确性靠服务端幂等，禁用按钮只防连点。
- 一个页面不必每块都有主按钮；危险按钮写明对象与动作，确认框里不靠颜色区分"保留"与"删除"。
- 图标 + 文字时，整个按钮一个热区、一个可聚焦元素；Split button 是两个动作，两个名称。
- 原生 `disabled` 与 `aria-disabled` 的选择要看焦点策略：前者影响 Tab 顺序，后者要自己拦鼠标、键盘与提交；两种都要给忙碌原因与完成反馈。

## 选择器

- 先决定模式：只选已有项 / 输入筛选 / 允许自由输入 / 多选。模式决定键盘行为与"输入值 vs 选中值"的关系。
- 三个值必须分开：已选值、查询输入、当前高亮项。方向键高亮不等于已选中。
- 常见 Combobox 契约：输入筛选、方向键移动活动项、Enter 接受、Esc 关闭、Tab 正常离开（不强迫逐项 Tab 穿过候选）。
- `aria-activedescendant` 模式下 DOM 焦点留在输入框，活动项必须存在于 DOM 且滚动可见；不要同时把每个选项做成独立焦点。
- 防"按了没选上"：触发器与列表是同一交互区域；不要在 `pointerdown` 阶段就卸载选项；不把全局 `pointerdown preventDefault` 当通用补丁（会破坏触屏滚动）。
- 活动项、已选项、悬停项视觉要可区分，不能只靠两个接近的灰；首次方向键导航不等动画。
- 远程选项区分四种状态：未输入 / 加载中 / 无匹配 / 请求失败。失败不能显示成"没有这个人"。
- 多选标签：删除按钮带对象名（"移除张三"）、输入位置保持可见、Backspace 规则明确、删除聚焦标签后焦点交给相邻标签或输入框。
- 禁用项说明原因；长名称可完整阅读；虚拟化列表要同步处理活动项挂载、滚动与读屏。
