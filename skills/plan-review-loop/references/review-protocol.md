# 评审协议：快照、记录与工具恢复

冻结或派发时读“版本与快照”和“派发材料”。需要审计、换人或故障恢复时读对应章节。路线选择、轮次和通过条件以 [SKILL.md](../SKILL.md) 为准。

## 版本与快照

为冻结正文指定唯一版本号，例如 v1、v2。版本与轮次分开记录：补路或换人不自动产生新正文版本。

将完整正文保存为冻结副本，或写入派发消息。将状态和评审记录与正文分开，不强制使用特殊标记。同一轮各路收到相同内容。如果派发消息引用可编辑的共享文件，另保留一份本轮不再修改的副本。在全部结果返回前，不覆盖正文。

影响行为、约束、前提、步骤或验收的修改必须新建版本。仅排版或错字修复可注明差异，但必须确认技术含义不变。用户中途改要求时保留已评版本，新要求进入下一版本，不混用不同版本的通过结论。

**契约精度修订**的定义与计入方式见[主文件](../SKILL.md)第 1 节，本协议只补一条操作性判据：改动若让某个既有断言从红变绿，或改变了任何默认值、阈值、拒绝条件，就按实质修改处理。它仍新建版本并重算哈希，并按普通复评处理，不设快速通道。

可只保留一份当前冻结副本；当前轮结束并记录结果后再覆盖，不要求逐轮存档。

## 审计快照与哈希

涉及多文件、异步交接或明确审计要求时增加 SHA256。用户禁止落盘时使用完整对话快照，明确未生成文件哈希，不为满足本协议违规写文件。

单文件可用各占一行的 `<!-- plan:start -->`、`<!-- plan:end -->` 分隔正文与记录。若使用标记，各出现一次且顺序正确。对标记行之间的正文计算哈希；CRLF 或 CR 统一为 LF，以 UTF-8 无 BOM 编码，不额外去除空白，记录末尾换行口径。无标记时明确被哈希的正文范围，不强改已有格式。

多文件记录相对路径、版本及逐文件哈希，采用相同文本口径。向各路提供同一份清单和完整内容。将原始依据与方案文件分开记录。如果依据或环境改变，复核受影响的结论。

哈希只用于确认内容身份，不证明 Agent 已阅读或方案正确。不得只留版本号或哈希而丢失正文。

## 派发材料

每路获得以下材料，并按本路职责检查：

```text
目标：用户要求、硬约束、已确认决策与授权。
职责：本路重点检查范围。
版本：轮次、冻结版本；适用时附哈希或文件清单。
方案：完整正文、核心任务与前提、依据及状态。
原始资料：可读取的需求、实现、配置和文档入口。
复评材料：复用路附旧问题、修改说明、处置依据和影响范围；扫描路只附改动清单与改动面，不给旧意见。
输出：结论；**一句话收口判断（可收口／还需一轮，附依据：本轮新发现里有没有一条会改变实施动作）**；高/中/低计数；问题稳定ID、严重度、位置、触发条件、后果、证据及建议；旧问题处置**以闭环表给出（逐条：已关闭／部分关闭／未关闭 + 依据位置）**，这条义务归复用路；扫描路未收到旧问题时写“本路无旧问题”；未核实项、待决策项及限制。**禁止照抄旧结论充作本轮结论**：未受影响部分可在注明原版本与覆盖范围后沿用证据，但不得原样复述已关闭条目的细节。
边界：只读评方案，不改文件、不执行拟议实现、不再派Agent，不代替用户授权。
```

派发时有五条硬要求：

1. **每路至少一个定向追问**，且必须能用具体输入构造（“请攻击：目标 busy 时投递是否会……”）。泛泛的“请评审”命中率明显更低。定向追问会收窄视野，所以最多三个，并同时写明“本路职责外的新发现同样必须报告”（复用路按[主文件](../SKILL.md)第 2 节的完成标准执行，不因这句话被要求全量扫描）。
2. **扫描路的复评消息必须写“请重新读取冻结文件全文，不要依赖你记忆中的版本”**；复用路至少读闭环表所引的位置，同样不得凭记忆。靠记忆的复评会漏掉条号漂移、常量不一致这类只有全文搜索才能发现的缺陷。
3. **复用的 Agent 不得声称盲评**。它对旧版本的记忆就是已暴露材料，记录里要写明“本路为复用评审者，已见历次版本”。
4. 复评时先给“**改动清单 + 改动面**”，再给全文。改动面是作者自报的改动量，口径见[主文件](../SKILL.md)第 3 节；评审者仍须自行判断交界处的交叉。
5. **每条缺陷必须给证据锚点四件套**：①`文件 :: 符号名`（行号仅作提示，版本间会漂移）②该符号内的原文片段 ③**可证伪条件**（写成“若在该符号内找不到 X，则本条不成立”）④若结论依赖调用／引用／配置关系，给出足以判定该关系存在的锚点（不必穷举）。作者的核验动作固定为“打开该锚点符号读全文，并逐个核对关系锚点”——片段只用于确认定位，**不替代阅读**：同文件相邻位置的代码完全可能推翻片段支持的结论。

替代路的**甲档**在首次启用时做一次盲评：只给候选方向所需材料，不提供当前方案；形成方向后再补共同正文与未决意见，此后复用同一评审者更新比较，不重复从零探索。**乙／丙档**不做隐藏：直接给完整正文与该决策点的候选列表。

## 复评与证据沿用

向本轮全部评审路提供新全文和修改说明。扫描路据全文判断改动影响，复用路据闭环表所引位置判断；都不只接受作者的影响判断。

对于受影响部分，检查新内容、关联前提、关键步骤之间的关系和旧问题。对于未受影响部分，可以沿用证据，但须注明原版本、覆盖范围及仍适用的原因。

各路给出当前版本的完整检查结论，不只复制旧计数。尚未完成的首次检查不能记为证据沿用。不要缩小职责来避开本路完成标准内的新问题（两种完成标准见[主文件](../SKILL.md)第 2 节）。

为问题保留稳定 ID。关闭旧问题时说明依据；新问题另记 ID。未解决的事实或严重度争议记录双方依据、已做核实和缺少证据，不以作者裁定或反复要求重评代替解决。

## 最小记录

复用方案记录区或已有项目日志，不另建审批文件。记录：

- 当前版本、已完成轮次与进行中轮次；适用的哈希或清单；评审状态与实现状态分别记。
- 各路身份、职责与状态（未开始／进行中／已完成／失败），附检查覆盖、沿用证据的原版本与限制、问题计数。
- 稳定问题 ID、处置依据、未决项及其归属。
- **本轮改动面**：口径见[主文件](../SKILL.md)第 3 节，并写明是否靠新增条款回应了新发现、本轮新增机制数。
- **未核实项台账**：每条写“谁发现的／为何不能核实／由谁在什么时候核实”，处置列只能取“转实施期必办（带验证步骤）／已代跑核实（附结果）／仍开放（附恢复条件）”三者之一；不允许连轮原样重复。
- 下一步可执行动作，或退出原因与恢复条件。

记录区常在哈希边界之外：凡含影响信任的断言（“已执行”“主要修法来自评审”），须附可核证据，否则标注“仅供参考”。

同一目标下换路不重置预算。用户实际替换核心任务时，记录新循环及依据，不通过改名重置轮数。

## 并发与故障恢复

按工具能力并发或顺序完成各路。如果 Agent 名额不足，先保存已完成的意见，再用客户端支持的方式释放资源。如果没有释放接口，顺序继续剩余评审，或报告能力限制。不得省略评审路，也不得把顺序执行说成并发。

某一路明确失败，或有限等待后确认无进展时：

1. 先核对实际状态，正常运行且有进展不算失败。
2. 同一路同一轮最多追加2次恢复尝试，换人和重连共用预算，不新增轮次。
3. 向接续的评审者提供原职责、共同快照、已完成检查和未决项。该评审者不能把他人未核实的结论记成已完成检查。
4. 恢复用尽或环境无法完成所需路线时，保存结果并按“评审未完成”退出。未完成不记为0问题。

完全没有独立 Agent 能力时，可交草案或明确标注的自查，状态写“未独立评审”，不伪造评审通过。

## 交付核对

确认最终正文与各路最新结论属于同一版本；纯排版或错字差异已注明且不改变技术含义。哈希模式重新核对正文范围、清单及哈希，变更后须留下更新记录，不能冒称旧哈希匹配。

存在未复评的实质修改时进入下一轮；预算已用尽时，交付未复评状态，不宣布通过，也不再开只核差异的复评。
