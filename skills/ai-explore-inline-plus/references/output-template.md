# 探索输出模板

> 本文件在 **Phase 0 建文件之前** 就要完整读一遍：文件结构、轮次格式、回答排版规则、局限与来源的写法都在这里。
> **「回答排版七条」是唯一维护处**，SKILL.md 只做指向，不重复。

## 交付物是什么

一份**给人读的讨论记录**，不是摘要报告。

- 主体是对话本身：谁问了什么、为什么问、被问的人怎么答、哪里卡住了。
- 读者是要**读下去的**，不是来查结论的。结论留在对话里说清楚。
- 末尾给一段**后记**：摘要 → 可以接着往哪走 → 生成信息与来源。
- **不要把结论前置成一页纸**——那等于告诉读者过程可以跳过，正好废掉这份记录的价值。

## 输出路径

文件写在 **当前工作目录**，命名规则：`ai-explore-{主题关键词}.md`
- 主题关键词优先取用户原话里的名词，英文短横线连接，2–4 个词
- 示例：`ai-explore-ai-agent-strategy.md`、`ai-explore-rust-error-handling.md`
- **同名文件已存在 → 追加 `-2`、`-3`，禁止覆盖**

## 文件结构总览

```
标题
一行元信息（自演 · 轮数 · 收敛原因）
用户原文（折叠；过长则外置）
问题目录（索引表）
完整对话（第 1 轮 … 第 N 轮）      ← 主体
探索摘要（后记）
可以接着往哪走（后记）
生成信息与来源（折叠，最后一节）
```

**第一屏只放一行元信息。** 局限说明、来源清单、检索细节全部收进文末折叠块——
读者打开文件看到的应该是记录本身，不是免责声明。

## 轮次格式的三个要点

1. **标题必须带问题**：`### 第 3 轮：{问题概括}`，不是光秃秃的 `### 第 3 轮`。
   10 个同名标题在任何编辑器大纲里等于没有导航；带问题后跳转和回顾才成立。概括取该轮 `question` 的 ≤20 字。
2. **追问者行：一行元信息 + 问题 + 为什么问**。
   - 第一行：`**追问者**` + 中文类型标签（反引号）+ 未解清单压在同一行
   - 接着：问题本体用引用块，两句以内，**一次只问一件事**
   - 最后：`*为什么问这个：…*` —— **这条一定要留**，它是这份记录比"问答列表"好看的地方
3. **回答者：第一段就是答案**，然后按下面的排版七条展开。

## 回答排版七条（唯一维护处）

每一轮回答落盘前，按这七条检查：

1. **第一段直接给答案**——不写"这是个好问题""让我从几个方面说"这类开场
2. **超过三段就分层**——用 `**加粗小标题**` 领起，**不要用 `####`**（会搅乱编辑器大纲，破坏轮次标题的导航）
3. **关键句独立成段**——一段不超过 5 行
4. **列举 ≥3 项写成列表**——不要塞进逗号长句
5. **代码、命令、路径、参数、具体数字用行内代码**
6. **术语首次出现跟一句 ≤10 字解释**
7. **不写"综上所述""总而言之"式收尾**——那是报告腔，对话里没人这么说话

**另加两条（对话特有）**：

8. **指代具名**——不写"你刚才说的那个""上面提到的"，写"第 2 轮的复杂度论证"。
   任何一段被单独摘出来读都要自洽，也要能被搜索到
9. **推断单独成引用块**——`> 【推断】…`，让读者一眼看出哪句没有出处

**回答写太长不是"该压缩内容"，是"该让下一轮把问题收窄"**——判据见 `questioner-guide.md` 的「密度检查」。

## 局限行的三种写法

`局限` 行写在**文末** `## 生成信息与来源` 折叠块里，**按本文件的性质选一种，不要含糊带过**：

1. **纯概念/机制题（未检索）**
   `局限：追问未经独立质疑；文中标为"推断"的内容未查证；本题不涉外部事实，未做检索。`
2. **走过 Phase 0.5，取到了正文**
   `局限：追问未经独立质疑；文中标为"推断"的内容未查证；外部事实来自检索到的公开报道（见下方来源），未见{原始材料，如原始 Lean 代码 / 原始声明 / 论文全文}。`
3. **走过 Phase 0.5，但没取到可用正文**
   `局限：追问未经独立质疑；外部事实仅有检索结果层面的线索，未能取到任何可提取的正文来源，相关数字与人名均属未核实。`

要点：**"来自公开报道"与"未见原始材料"必须分开写**——前者说的是搬运了什么，后者说的是没看到什么。两者混成一句会让读者误判证据等级。

## 来源（仅当走过 Phase 0.5）

同样写在**文末** `## 生成信息与来源` 折叠块里，只列**实际取到正文**的链接，通常 1–3 条：

```markdown
**来源**（仅列出实际取到正文的链接）
- [报道标题](URL) — {一句话：提供了哪条事实}
- [报道标题](URL) — {一句话}
```

硬规则：
- **抓取失败的 URL 不得出现在文件任何位置**，包括正文、来源清单、脚注。失败情形包括 `HTTP 422` /
  `Unable to extract content`、门户或移动端的"正在进行安全检测"页、只返回导航/页脚的空正文页。
- 原来的主源抓不到时，换成同题材的**可提取转载源**（通讯社稿转载、报纸网站、机构官网、arXiv/DOI 页），
  文件里只写换源后的 URL。
- 一条来源都取不到时，不写来源清单，改在局限行按第 3 种写法声明"均属未核实"。

## 长原文的处理

原文超过一屏（约 500 字）**或**含代码块/表格时，另存为 `ai-explore-{主题关键词}-source.md`，
主文件改为在标题下放一行：

```markdown
> 用户原文较长，见 [`ai-explore-{主题关键词}-source.md`](ai-explore-{主题关键词}-source.md)
```

## 质量标准

### 对话记录
1. **忠实于原始回答**：不歪曲、不简化关键论点
2. **保留关键原文**：重要的解释用原文，不用摘要替代
3. **问题目录完整**：每条追问都列出，方便跳读
4. **rationale 与 open_issues 保留**：让读者看得见追问是怎么挑出来的
5. **更正可见**：后续轮次推翻前面的说法时，写「更正：第 N 轮…」，不改前面已有文字
6. **轮次标题带问题**：不允许出现连续多轮同名标题
7. **输出位置**：文件写在当前工作目录，不是 `local://` 内部路径
8. **来源可点开**：文件里出现的每个 URL 都曾成功取到正文；没有死链，没有"安全检测"页
9. **第一屏干净**：开头除标题与一行元信息外，不出现局限说明、来源清单、检索细节

### 探索摘要（后记）
1. **不替代对话**：摘要是导航与回顾，不是替代品
2. **位置在末尾**：不做成开头的一页纸，不前置
3. **每条发现可回指**：必须带 `（第 N 轮）`；回指不出来的发现删掉，不要留在摘要里
4. **诚实**：未探索方向如实列出，不假装已覆盖；收敛是"清单空了"，不是"都答完了"
5. **结论有依据**：核心结论必须能从对话中推导出来，不能凭空产生
6. **外部事实标等级**：检索来的写"据报道"并带链接；没有正文支撑的写"未核实"，不得写成定论
7. **生成方式可见**：文末折叠块必须写明单模型自演、无外部视角、推断未查证
