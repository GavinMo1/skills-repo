# 05 · 主题与无障碍

> **适用**：要交对比度结论、做深色主题、走键盘与读屏、定热区尺寸、处理播报与放大/强制色时。
> **本轮不可交付时**：若容器与控件结构还没定，停下并说明「结构未定」，改读 [01-结构与排版](01-结构与排版.md) 或 [02-控件与交互](02-控件与交互.md) 后回来；若这一轮只处理交互时序与动效，改读 [04-状态与动效](04-状态与动效.md)。
> **读完能判定**：每对颜色在各状态与明暗下过不过门槛；深色表面与强调是否重排过；Tab 顺序与焦点可见是否成立；热区按哪一档、相邻是否重叠；播报是否必要且不重复；200% 放大与强制颜色下是否仍能用。

这两块常被当收尾，其实决定"能不能用"。判定依据是标准与门槛，不是观感。

细则与理由：[04 颜色与对比度](../detail/04-颜色与对比度.md)、[05 深色主题](../detail/05-深色主题.md)、[07 无障碍](../detail/07-无障碍.md)。

## 对比度（WCAG 2.2）

| 对象 | AA | AAA |
|---|---|---|
| 普通文字 | 4.5:1 | 7:1 |
| 大号文字（≥18pt，或 ≥14pt 粗体；约 24px，或 18.67px 粗体） | 3:1 | 4.5:1 |
| 识别控件与状态所需的非文字信息 | 3:1 | 不另设更高数值 |

- 对比度是一对颜色的关系，单个色号没有"通过 AA"。
- 半透明先按通道合成（`C = α·前景 + (1−α)·背景`）再算；`opacity` 会连子元素一起削弱。
- 渐变、图片、多层透明、其他色彩空间上按实际渲染取样，检查文字经过的最差区域。
- 4.49 不能四舍五入成 4.5 后算通过；不要把门槛配色贴着边给。
- 占位文字、辅助说明不能用"次要"作为不达标的理由；禁用态有豁免，但要有其它线索说明它禁用。
- 不是所有边框都要 3:1：填充与文字已能识别按钮时，装饰边框的适用情况不同。装饰分隔线不能承担识别输入框、选中标记这类必要信息。
- 状态（错误、成功）要配图标或文字，不只靠红绿；hover、pressed、selected、focus 分别检查。
- 逐一检查"默认、悬停、选中、错误、聚焦 × 明暗主题"，记录"哪个前景在什么表面上"，而不是一张通过的色板。
- APCA 的 Lc 与 WCAG 比值不是同一单位，不作为合规判定替代。

## 深色主题

- 先定义表面层级（页面背景、卡片与浮层、选中区域），深浅两套都要能辨认层级。
- 深色常用逐层变亮表达抬升；浅色可能多个表面同为白色靠边界与阴影区分——不存在"抬升必须变暗"的统一规则。
- 阴影在暗底难辨，可联合表面差、描边与遮罩，但不必一律加倍透明度。
- 品牌色按职责拆分：填充按钮文字、文字链接、浅底强调色不是同一个值；深色下链接通常需要更亮。
- 不给所有图片统一加 `brightness(.85)`：会篡改照片、图表、截图的事实呈现。插画给主题版本，透明 Logo 换资源，亮截图加容器边界。
- 提供"跟随系统 / 浅色 / 深色"三档并保存显式偏好；首屏尽早应用，避免先白后黑；有 SSR 时处理服务端与客户端初始主题一致。
- `color-scheme` 只影响原生控件，自定义颜色要自己按同样规则映射 Token。
- 同一路径明暗各走一遍：列表、详情、菜单、错误、禁用、截图；再查原生输入控件、滚动条与强制颜色模式。

## 键盘与焦点

- 动作 `<button>`、跳转 `<a href>`；给 `<div role="button">` 要自己补聚焦、Enter、Space 与禁用。
- 提供 skip link；`nav`/`main` 与标题层级可用，不把所有文字做成无层级 div。
- Tab 顺序等于阅读与操作顺序，避免正数 `tabindex`；Tabs、菜单、树、列表等复合控件用方向键在内部移动，不让每项都进 Tab 顺序。
- 模态打开后焦点进入内部并循环；关闭后返回触发元素；危险确认不默认聚焦危险按钮。
- 焦点必须可见（2.4.7）且不被作者内容完全遮挡（2.4.11）；AAA 2.4.13 另有面积与聚焦前后 3:1 变化的要求。
- 焦点环示例：`outline: 3px solid var(--focus-ring); outline-offset: 2–3px`，并在真实背景上检查；`:focus-visible` 是浏览器启发式，不是"鼠标永不显示"。
- 长内容进入时可先聚焦标题（`tabindex="-1"`，不进日常 Tab 顺序）；不要在每次后台刷新时抢焦点。

## 热区与尺寸

- AA 2.5.8：至少 24×24 CSS px，含间距、等效控件、行内文本、用户代理控件与必要性等例外；间距例外有 24px 直径圆的判定，不等于"相隔 8px"。
- AAA 2.5.5：至少 44×44。Apple 44pt、Material 48dp 是平台单位，不等于 CSS px。
- 扩大热区后不能相互重叠：删除与编辑挨太近，各自够大也会误触。
- 视觉对齐的光学补偿不得缩小热区、不得裁掉焦点环。

## 播报与文本

- 保存结果用 `role="status"`（礼貌播报）；急需用户处理的错误可考虑 `role="alert"`。不是所有更新都播报，列表连续更新也不逐条读。
- 先在 DOM 里准备区域再更新内容；不要同时挂多套 live 语义造成重复朗读。
- 带操作的消息不只靠一闪而过的播报，要给它稳定可见入口与键盘路线。
- 只给读屏看的文字用成熟的 visually-hidden 样式；`display:none` 与 `visibility:hidden` 会从无障碍树移除。
- 图标按钮必须有可访问名称；按钮已有清楚可见文字时不要用 `aria-label` 覆盖。
- ARIA 只补语义：`aria-expanded` 不会替你打开菜单，`aria-modal` 不会锁焦点。

## 两种常被漏掉的环境

- 强制颜色模式（`@media (forced-colors: active)`）：背景与阴影可能被覆盖，用系统颜色补必要轮廓；不要无理由全局禁用系统调色。
- 200% 文本放大、约 320 CSS px 窄视口、用户修改行距后，内容仍可读；水平表格可单独滚动，整页不得横向溢出。
- 自动扫描查不出任务顺序是否合理、模态焦点是否处理正确；必须再用真实键盘与读屏器走一遍名称、状态与错误。
