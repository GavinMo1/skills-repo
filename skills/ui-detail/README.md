# 界面细节：从认得组件到做对交互

写给没系统学过设计、但需要把界面做出来的人。你可能能写出页面，却说不清该用抽屉还是对话框，也可能照着规范填了数值，页面仍然显得松散、拥挤或难用。

这个系列从一个具体场景出发：**做一个项目管理页面，用户在列表里查找项目、编辑信息、上传文件，并在明暗主题下工作。** 每篇解决其中一类问题。术语跟着问题出现，数值跟着用途出现。

## 这个目录同时是一个 skill

本目录就是 `ui-detail` skill 的本体（母版在这里，`~/.agents/skills/ui-detail` 是指向它的 junction，不做拷贝）。AI 从这里加载：

| 路径 | 作用 | 谁读 |
|---|---|---|
| [`SKILL.md`](SKILL.md) | 唯一入口：阶段 / 症状 / 对象三条路由，十条硬规则压缩版，交付格式 | AI 常驻 |
| [`references/stage/`](references/stage/) | 执行层 6 篇 + 阶段总表：只写做什么、怎么判定做完 | AI 按需取 2–3 篇 |
| [`references/detail/`](references/detail/) | 详解层 17 篇：为什么、证据、代码 | AI 需要下潜时取 |
| [`references/index.md`](references/index.md) | 症状原话与对象名词的反查表，附 24 个文件的行数 | AI 定位用 |
| [`scripts/check-links.py`](scripts/check-links.py) | 校验全部相对链接与锚点 | 维护用 |

- **加载预算**：一次任务最多 `SKILL.md + 2–3 篇`。改这套材料时请守住这条，否则下个 agent 会把 references 全读一遍。
- **改材料等于改 skill**：在 `references/` 里改，junction 立刻生效，没有第二份副本要同步。
- **每次搬动或改链接后跑一次**：`python scripts/check-links.py .`（0 个坏链才算通过）。

## 要动手做界面时，用行动纲要

不想读完全部 17 篇、或要让 AI 直接改界面时，用[行动纲要](references/stage/README.md)：同一套判断的**执行版**，按"结构 → 控件 → 数据与任务 → 状态 → 主题与无障碍 → 自查"分文件，每条都能打勾，末尾附验收清单与报告格式。它只写做什么；证据、边界与代码仍回本目录对应文章。

## 检查组件有没有讲透

不能只列术语和推荐数值。对每个组件，继续追问六件事：**有哪些状态、怎样过渡、输入如何响应、异步失败如何恢复、布局与焦点怎样保持、不同设备如何操作。** 这六问偏交互，另外还要看对齐：同一区块的边是否收敛到少数几条对齐线（[几何对齐](references/detail/03-布局与排版.md)#几何对齐让边缘替你分组)），数值对齐之后眼睛是否也认（[视觉对齐](references/detail/03-布局与排版.md)#视觉对齐坐标对上了眼睛还要认)）。例如输入框的聚焦渐变只是状态过渡，中文输入法和光标稳定属于输入响应，两者缺一都会影响手感。

当前系列覆盖普通 Web 项目页的输入、选择、提交、列表、浮层、上传、草稿、日期与拖拽。富文本编辑、图表交互与原生移动端手势等尚未专篇展开；日期与拖拽篇也不代表已经穷尽专业排期、协同编辑与直接操作的所有问题。系列会按实际问题继续扩充，不能以篇数判断是否已经覆盖所有界面细节。

## 数值怎么用

文章区分三种依据：

- **标准要求**：例如 WCAG 2.2 的成功准则，必须连同适用条件、例外和目标等级阅读。
- **平台约定**：例如 Apple 的 pt、Material 的 dp、组件库默认高度；换平台或版本要重新核对。
- **项目起点**：例如 8px 间距、200ms 动画，只是帮助开始的取值，需要用真实内容验证。

CSS px、pt、dp 属于不同坐标体系，不能仅因数字相近就直接互换。正文中的 Web 示例使用 CSS 单位。

文末链接提供查证入口；本系列没有把各设计系统所有版本的 Token 逐项在线核验。代码是说明对应问题的局部示例，集成时仍需补齐应用逻辑并测试。
