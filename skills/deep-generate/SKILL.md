# Deep Generate — 全新主题深度系列生成器

## 任务与边界

用户给出主题，需要从零生成一套深度解析系列文章时，使用本技能。先确定读者需要解决的问题，再梳理知识、设计章节、分工撰写与独立评审，最后整合交付。不用于仅分析现成文档或回答一个普通问题。

默认中文、Markdown；用户另有语言要求时遵从用户。章节数量和篇幅由必要问题、解释难度和阅读用途决定，不设置内容配额。保留足够的依据、推导、例子和限制，使读者能够理解结论、作出判断或执行适用的操作。

## 执行约定

- **主协调者**负责结构、任务分配、文件核对、跨章整合和交付状态。**撰写者**负责章节与自检。**评审者**独立检查章节，不能由该章作者或修改者担任。
- 使用环境提供的子 Agent 和并行能力。独立任务在可用并发容量内并行；有依赖的任务先等必要输入。不要依赖某个平台专有的参数或工具名称。
- 给子 Agent 提供任务范围、必要上下文、可访问的参考文件路径、输入版本、输出路径和完成条件。同一文件同时只由一个执行者修改。
- **当前状态只维护一份。** 主协调者使用 `scripts/state.py` 初始化和更新 `_work/本次任务标识/任务状态.json`，登记产出、冻结评审输入、收录报告并更新试读与下一步。执行者提交正文与报告，不修改总清单。**手工编辑清单仅限**修正 `files[].path`、恢复真实 `revisions` 历史、为旧账本补 `schema_version`；`actors`、`contributors`、评审结论与各类计数不得手改（会让机械门与独立性检查失真），任何手工编辑后都必须通过 `check-state.py`。首次登记、派发评审或恢复任务前，读取[状态协议](references/state-protocol.md)中的命令与输入格式。快照、原始报告和正文是判断依据；不另写任务专用管理脚本，不另建需要人工同步的近义清单。
- 如果独立 Agent 不可用，先完成不依赖该能力的准备工作。向用户说明无法独立评审；只有用户接受后，才改为顺序撰写与自检，并标明未完成独立评审。不得把自检称为盲审。
- 主协调者首次执行前读取 [异常处理](references/error-handling.md)；出现异常时查阅对应规则，无须每一步重复读取。

## 1. 明确目标与建立知识图谱

根据请求确定目标读者、已有知识、阅读用途、主题范围和时效要求。可合理推定的信息写入任务说明；只有缺失信息会实质改变内容或结构时才询问。用户未要求确认的阶段可连续推进，不增加固定确认节点。

输出到用户指定目录，未指定时使用当前工作目录下的主题目录。先确认路径可用。将本次知识图谱、结构设计、资料记录、版本快照和评审放入主题目录的 `_work/本次任务标识/`；任务标识应与已有运行区分。不要覆盖其他任务的文件。

开始搜集资料和建立知识图谱前，读取 [资料与证据规则](references/research-protocol.md)。需要记录知识图谱和章节结构时，读取 [输出模板](references/output-templates.md) 的对应部分。

主题包含多个子领域时，安排独立分析者分别梳理核心问题、易忽略内容、前置知识和子领域关联。主协调者合并同义问题，核对缺口和依据，形成知识图谱。不要把初次列出的目录当作完整领域地图。

按当前读者目标标记问题优先级：

- **P0：必要问题。** 缺失会导致核心结论不成立、无法理解主线或无法完成目标操作。
- **P1：重要问题。** 影响读者作出适用性判断、理解权衡或识别主要限制。
- **P2：扩展问题。** 不阻断当前目标，可留作选读或后续探索。

停止梳理的条件：P0、P1 问题已有依据或明确缺口，均有章节归属或排除理由；关键争议已处理或披露；继续检索主要增加不影响当前目标的扩展内容。前置依赖追溯到读者已知基础或够用解释为止，不扩展成整门学科。分析者熟悉某个领域，不构成将其升级为必要内容的理由。

完成条件：范围明确；必要问题及其依赖已记录；关键依据与证据缺口可追踪。证据不足但影响关键结论的问题，应继续查证、缩小范围或明确列为未解决项。

## 2. 设计系列结构

将 P0、P1 问题映射到章节。每章记录核心问题、前置知识、应覆盖内容、读后能力、主要依据及与其他章节的关系。未纳入的问题说明原因，不能静默遗漏。

按理解依赖和阅读用途排序，不强套“基础到前沿”的固定层次。每章围绕独立问题组织内容；独立价值不等于无需前置知识。指定共享概念的主讲章节，其他章节只保留理解当前问题所需的回顾，并链接完整解释。

并行前稳定共享的解释基础：核心解释框架、共享场景与示例、版本和基本假设、已有依据的结论及未决争议。说明关键概念由哪章建立，以及后续章节可以假定读者知道什么。强依赖章节先等基础章节初稿或足够明确的解释约定，不只靠术语相同判断含义一致。

将跨章术语、来源、章节职责和链接约定提供给所有撰写者。文件名使用可排序的 `XX-标题.md`；正文标题不必重复文件序号。默认使用标准 Markdown 相对链接；用户的阅读工具需要 wikilink 时再使用，并核对目标。

完成条件：必要问题都有明确归属；章节边界与依赖清楚；结构设计写入工作目录。章节数量不足以形成有意义的系列时，说明适合合并的原因，而不是为了凑数拆章。

同时确定主阅读路线和用途：连续学习、建立理解或掌握操作的系列，整合后安排主路线试读；只作跳读参考或用户明确跳过时，记录不安排的原因。

## 3. 分工撰写与自检

主协调者按章节安排分工明确的撰写者，提供任务说明、系列结构、共享约定、该章资料和输出路径。有必要依赖其他章节的实际内容时，等待对应初稿；其余章节可并行。

撰写者开始前读取 [写作与自检](references/self-check-list.md)。资料规则同样适用于撰写阶段；新增事实必须记录依据。按章节目标写作，不用代码、图表数量或文字长度代替深度。

初稿完成后按适用项自检并修改。必要检查完成且没有新的实质发现时结束；缺少依据、能力或资源而无法解决的问题随稿提交，不反复改写措辞来冒充进展。主协调者批量核对本批输出：文件存在、非空、属于本次任务，正文覆盖章节职责，且未混入其他章节或评审内容。文件存在不等于内容合格。

## 4. 独立评审与修订

### 评审输入与独立性

每章安排独立评审者，使用不包含该章写作或修改过程的新上下文。评审前读取 [评审标准](references/scoring-rubric.md) 与 [输出模板](references/output-templates.md) 中的评审格式。

首轮评审不提供作者自评分、作者辩护或其他评审结论。提供判断必需的材料：目标读者、任务范围、系列结构、章节职责、共享术语、当前章节、来源记录，以及涉及衔接或重复问题的相邻或相关章节。盲审隔离既有判断，不隔离必要证据。

要求评审者依据可核对内容报告问题；不要求凑问题或给出赞扬。不能核实的内容标为待核实，不作已证实错误处理。报告记录实际读取的版本和检查范围。

### 通过与修订

按评审标准区分高、中、低影响问题。没有未解决的高、中影响问题，且必要检查完成，才可标记“通过”。检查或证据不足时标记“待核实”；未完成独立评审时标记“未评审”。总分仅辅助比较，不能抵消实质问题。

主协调者将原始报告按轮次保留，在任务状态清单登记实际输入、覆盖范围、结论和问题 ID。批量核对报告是否覆盖预期章节、是否对应当前版本、是否有具体问题依据。逐轮汇总仅在需要时从清单与报告生成，并注明生成时点，不作为第二份可编辑状态。

对需要修订的章节，安排非评审者的修改者。修改前保存输入快照，交代问题、涉及文件、当前版本与完成条件；同一文件只能有一个修改者。修改后记录实际输出和问题处理结果，再由独立评审者复核。复评可以提供旧问题与处理记录，不能称为首轮盲审。

保留文件实际作者、历史修改者和输出版本；更换负责人不清空历史。按环境可核实的执行实体判断独立性，不以角色名代替。评审记录实际输入及检查范围；输入改变后，先将相关结论标为待核实，由独立评审者确认沿用范围或复查，不自动继承通过。

默认每章进行两轮问题修订与复评，可按用户要求调整。只在实际产出针对评审问题的新版本后计一轮；派发、失败重试和同一提交续接不重复计数。初稿写作、正常跨章整合和其必要检查不占问题修订轮次，但不能借“整合”重置已经消耗的修复预算。读者试读发现的问题也按实际修复对象登记。具体计数见[状态协议](references/state-protocol.md)。

轮次是执行预算，不是质量标准。达到上限时，根据新证据、收敛程度和剩余资源，说明是否需要继续的理由；超出既定预算需用户调整，不能自动无限重审，也不能因为轮次用完就标为通过。

比较版本时检查问题是否解决、是否引入新问题、原有正确内容是否丢失。不能只因分数下降就回退，也不能以最高分作为保留版本的唯一依据。确认实质退化时，从快照恢复受影响内容并复核；保留有依据的有效修复。

达到轮次上限仍有问题时，保存依据最充分、实质问题最少的可用版本，记录遗留问题及影响。未完成章节若阻断后续理解或关键结论，暂停依赖它的部分；其余部分可以继续。

## 5. 跨章整合与索引

主协调者读取当前章节并对照结构设计；资料超出上下文容量时分批读取，保留章节职责与问题索引，避免强行一次装入全部内容。

- 核对共享术语、前置知识、引用和结论。按含义与领域惯例统一术语；不同含义不能机械合并。
- 按解释作用处理重复。完整解释集中在主讲章节，保留当前章节必要的简短回顾。仅在帮助读者定位信息时添加交叉链接，不对每次概念出现都插链接。
- 核对跨章示例、数据、版本假设和边界条件，避免各章单独成立但组合后冲突。
- 扫描 `TODO`、`FIXME`、`待补充`、`xxx`、`placeholder`、`TBD` 等候选标记。逐项判断是否为未完成内容、引用原文或有意展示的代码。只修复真实缺口，保留必要示例。
- 检查本地链接文件与锚点。外部链接的可访问性和内容真实性分别检查；未能访问的链接说明限制。

生成 `00-阅读指南.md`，说明系列目标、适用读者、阅读路线、章节链接、前置知识、选读分支及重要限制。来源可随章记录或集中放入 `来源与说明.md`，但必须能定位到支持的论点。

### 主阅读路线试读

需要试读时，在初步整合与阅读指南完成后，按环境提供的位置读取配套技能 `reader-review`，由其规定读者画像、独立派发、模拟判断、误读处理和复读方法。不要在本技能维护第二套试读规则。技能无法定位或读取时，说明缺失与对交付的影响，继续不依赖试读的工作，不声称已完成试读。

提供必要画像、目标、正文入口、主路线和实际范围，首轮不传作者辩护或旧判断。协调者将报告存入本次工作目录的 `读者试读/`；本生成任务的留档约定优先于单独试读时默认不留档的规则。

区分阅读障碍与技术疑点：前者按读者目标修订，后者交内容评审核实。采纳修改后按改动影响进行定向复查或重新试读。试读不代替事实评审，记录真实覆盖与未验证范围；阻断目标的障碍未解决时，按部分交付披露。

整合后复核所有受影响部分：路径和格式改动核对相应链接与格式；改变事实、结论、示例、章节职责或理解依赖的改动，由独立评审者复查相关内容。正常整合不占问题修订轮次；若本次修改用于解决已登记评审问题，仍按该章实际修订计数，不因换阶段重置。预算耗尽时报告遗留问题，不无限循环。报告注明对应最终版本，不能沿用已失效的通过状态。

## 6. 交付

交付前读取 [交付检查](references/delivery-checklist.md)，逐项记录已完成、未完成或不适用及原因。

核对清单与实际文件后，运行 `python <本技能目录>/scripts/check-state.py --root <主题目录> --state <任务状态.json路径> --final`；中途恢复检查可不加 `--final`。脚本需要 Python 3.9 或更新版本，只读检查结构、版本、身份登记与修订记录一致性，不判断内容正确性。**`--final` 退出码 0 才算机械门通过**；非 0 时按 `failed`／`unchecked` 分别处置——`failed` 不得以披露代替修复；其中「没有可交付内容」属 type 分类问题（工具无法修），「实际文件哈希与登记不符」转状态协议的『存量诊断与处置』且**不要重写正文迎合哈希**。写前自检不带 `--final`，零信号不代表无缺陷；`freeze` 不受完整自检约束。正文、来源、本地链接与锚点等仍按交付检查核对，不能用脚本通过替代。最终摘要从清单与原始报告生成，不另立账本。

交付阅读指南、最终章节、来源与必要限制。存在未解决问题时，同时交付 `交付状态.md`，说明受影响章节、阅读或使用影响、未完成检查和后续所需条件。聊天中给出入口链接和关键状态，完整正文与报告保存到文件。

默认保留工作目录中的知识图谱、结构、来源、评审和快照。只自动删除本次创建且明确可丢弃的临时文件；不清空已有目录，不删除评审证据。用户要求精简包时，打包阅读材料并说明工作记录的位置。
