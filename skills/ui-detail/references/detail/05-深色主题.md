# 05 · 深色主题：重新安排表面与强调

> **适用**：新做或改造深色模式：白底换黑底后卡片边界消失、按钮刺眼、截图变灯箱，或要接「跟随系统/浅色/深色」三档与首屏防闪白时。
> **本轮不可交付时**：若这一轮只核某个色值过不过 AA，停下并说明「不涉主题重排」，改读 [04-颜色与对比度](04-颜色与对比度.md)；若只查深色下浮层的开合定位与动画，改读 [01-浮层](01-浮层.md) 或 [12-浮层的开合与定位](12-浮层的开合与定位.md)。
> **读完能判定**：这个界面需要哪几层表面、深浅两侧的抬升方向怎么走；该不该用纯黑纯白；深色浮层靠表面差、描边、遮罩还是阴影交代边界；品牌色是否按职责拆成不同值；图片该不该统一调亮度；三档偏好怎么存、首屏怎么早应用、SSR 下初始主题怎么对齐。

## 一、先判

1. **先列表面，再选颜色**：页面背景、卡片、浮层、选中区域要能被辨认；深色界面常用逐层变亮的表面辅助表达层级，浅色界面则可能多个表面都用白色、通过边界和阴影区分——不存在“抬升必须变暗”的统一规则。
2. **深色浮层的边界先看阴影还够不够**：阴影在暗底上通常更难辨认，可以联合表面差、描边和遮罩；阴影仍可能有用，没必要一律加倍透明度。
3. **纯黑还是近黑，看用途**：纯黑可用于 OLED、媒体浏览或产品特定风格，采用近黑则更方便用亮度划分多个表面，两者都有成立场景；“OLED 会不会拖影”还与面板和刷新行为有关，不能作为一律禁用纯黑的理由。
4. **纯白文字要不要压暗，看压完还达不达标**：某些暗环境下纯白会让人感觉刺眼或有光晕，降低前景亮度可能改善舒适度，但不能把文字调到不达标。
5. **品牌色按职责拆，不共用一个“品牌蓝”**：按钮背景上的文字、文字链接、轻色容器里的强调色承担不同职责；深色主题的链接可能需要更亮，填充按钮则要同时检查按钮文字与背景的组合。
6. **图片按类型分开处理，不统一调亮度**：给所有图片统一加 `brightness(.85)` 会改变照片、图表和截图的事实呈现；可针对插画提供主题版本、给透明 Logo 换适合的资源、为亮截图加容器边界，媒体查看场景一般应保留原图显示方式。
7. **三档偏好存在用户的显式选择里**：提供“跟随系统 / 浅色 / 深色”，保存用户显式偏好；首屏尽早应用主题，避免先白后黑。
8. **有服务端渲染就先对齐初始主题**：处理服务端与客户端初始主题一致性，否则首帧会和用户选择打架。
9. **`color-scheme` 只声明原生控件配色**：它不会替你把自定义卡片和文字改色，自定义颜色还要按相同选择规则映射 Token。

## 二、做完的标准

- [ ] 表面清单定下来并写成 Token：页面背景、卡片/浮层、选中区域各有深浅两侧取值（示例起点见第四节表）。
- [ ] 用同一条路径在深色下走一遍：进入列表、打开详情、展开菜单、触发错误、禁用按钮、查看截图。
- [ ] 三个常漏的位置补上检查：原生输入控件、滚动条、系统强制颜色模式。
- [ ] 深色浮层的边界线索不止一种：表面差、描边、遮罩里至少另有其一成立，不只靠阴影。
- [ ] 三档偏好可切换、刷新后保持用户显式选择，且首次进入没有先白后黑。
- [ ] SSR 场景下服务端输出的初始主题与客户端首帧一致。
- [ ] 图片逐类确认：插画、透明 Logo、亮截图、媒体查看各用了自己的处理方式。
- [ ] 装饰分隔线没有被拿去承担输入框识别或选中标记这类必要信息。

## 三、依据与数值

- **项目示例（项目起点）**：第四节两表的色值不代表某个设计系统的当前默认值，按项目品牌重取。
- **示例值**：`.6` 遮罩透明度只是一个可能起点，不是标准要求，应在复杂页面上观察效果；`brightness(.85)` 用于说明“统一调亮度”的做法，不是建议参数。
- **无此标准要求**：没有“所有深色浮层必须加 `1px` 亮边”的统一规定，阴影与描边要不要用按第一节第 2 条判。
- 装饰分隔线不能直接拿去承担输入框识别、选中标记等必要信息，后者需要另行检查对比度（门槛见 [04-颜色与对比度](04-颜色与对比度.md)）。

## 四、控件、表格与示例

表面分层与深浅两侧的起点：

| 语义 | 浅色起点 | 深色起点 |
|---|---|---|
| 页面背景 | `#F6F7F9` | `#121212` |
| 卡片/浮层表面 | `#FFFFFF` | `#1F1F1F` |
| 主文字 | `#1F1F1F` | `#E0E0E0` |
| 次文字 | `#595959` | `#B0B0B0` |
| 装饰分隔线 | `#E2E2E2` | `#3F3F3F` |

原生控件的配色声明：

```css
:root { color-scheme: light; }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) { color-scheme: dark; }
}
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"] { color-scheme: dark; }
```

这里仅演示原生控件的配色声明，自定义颜色还要按相同选择规则映射 Token。

## 五、失败长相与边界

- **白底换黑底后卡片边界不见了** → 表面之间没有亮度差，也没补边界与阴影线索。回第一节第 1 条重列表面。
- **蓝色按钮显得刺眼** → 品牌色没有按职责拆值，填充色与按钮文字没有一起检查。
- **上传截图像一块灯** → 对图片统一调了亮度，或没有为亮截图加容器边界。
- **首屏先白后黑** → 主题在客户端才应用，或服务端与客户端初始主题不一致。
- **深色下浮层看不出边界** → 只靠阴影；补表面差、描边或遮罩，并保证文本本身清楚。
- **Tooltip / Toast 与周围糊在一起** → 可以用浅底深字制造对比，也可以沿用深色表面，但要检查与周围区域能否区分，以及文本本身是否清楚。
- **错误只靠突然反色** → 最好靠位置、图标和明确文案表达；模态遮罩的目标是降低背景干扰，还要配合真实的背景交互阻断。
- **边界**：“浅色像纸、深色像暗场”可以帮助理解视觉风格，不能当作两种真实物理模型，更不能据此推导通用的字号或字重补偿；屏幕在明暗主题下都在发光，字体、字号、显示器、环境与用户视觉状况都会影响体验。

参考：[MDN color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/color-scheme)、[MDN prefers-color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-color-scheme)、[Material 颜色角色](https://m3.material.io/styles/color/roles)。
