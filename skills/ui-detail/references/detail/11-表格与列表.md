# 11 · 表格与列表：数据变化时，保住位置和上下文

> **适用**：用户从第 3 页进详情再返回却回到第 1 页、刷新后行高变了刚要点的目标滑走、或跨页选择与批量操作结果对不上，需要保住位置与上下文时。
> **本轮不可交付时**：若这一轮的列表只有十几条、不用排序筛选、没有分页与跨页选择，停下并说明「没有位置与上下文要保」，改读 [03-布局与排版](03-布局与排版.md) 的排版部分。
> **读完能判定**：每列按阅读方向还是尾侧对齐、未知与未填与零是否被混成一个状态；行内动作与行导航怎么分开、要不要为此上 role=grid；排序、筛选、刷新、从详情返回各要恢复什么、哪些写进 URL；全选范围是当前页还是筛选后全部、跨页选择按什么键保存；批量任务记录什么、只重试失败项怎么做；固定表头与批量栏会不会挡住行内控件；各种空与失败各自落在哪里、末页删空后页码怎么算。

## 一、先判

1. **列按数据形态对齐**：文字列通常按阅读方向对齐，数值列通常向尾侧对齐；金额还要统一小数精度、货币单位和缺失值表达。等宽数字有助于列内比较，但不会自动对齐不同长度的小数部分。
2. **同一字段要稳定表达**：未知、尚未填写和数值零不是同一个状态，不要都用空白或 `0` 代替；日期列说明时区或使用场景，不能让排序规则与展示格式互相矛盾。
3. 超长项目名可以换行或截断，取决于扫描密度；重要信息若被截断，应提供键盘和触屏也可用的完整阅读方式，仅给鼠标 Hover Tooltip 不够。
4. **点击项目名进详情就用真正的链接**，保留新标签打开、复制地址等浏览器行为；整行可点击可以作为辅助，但不能让行内复选框、菜单按钮点击时又触发导航。
5. 不要把整行做成一个链接，再往里面嵌套按钮——语义和事件都会变复杂。对常规数据表，原生 `<table>`、`<th>`、合适的 `scope` 和可辨识标题往往足够；仅因“表格可操作”就加 `role="grid"`，会承担额外的键盘导航义务。
6. 行操作可以在 Hover 或行内 Focus 时加强显示，但关键动作要能被发现并在触屏使用；不可见的按钮不应悄悄挡住文字，移除焦点入口时也不能让键盘用户找不到功能。
7. **排序、筛选、清空、刷新、返回各要保留什么**（对照表见第四节）：排序按钮应有清楚的名称，在排序列的表头上表达 `aria-sort` 等状态；若有多列排序，还需说明优先级，不能只放几个小箭头。
8. 搜索和筛选条件可写入 URL 或历史状态，便于刷新与分享；不是所有临时界面状态都必须写 URL——关键是定义哪些状态能恢复，并让浏览器返回行为符合预期。
9. 异步更新时可以保留旧行并标明正在更新，但要处理旧数据对应的操作：若查询已改变、结果尚未返回，不能让用户误以为旧行已经符合新筛选条件。必要时暂缓行操作，并避免旧响应覆盖新查询。
10. **“全选”到底是当前页的 20 项，还是筛选后的 2,000 项**要说清：勾选表头后显示“已选当前页 20 项”，若支持跨页全选，再提供明确的“选择全部 2,000 项”动作。
11. 跨页选择要按稳定的业务 ID 保存，不能按数组下标保存——排序或删除后，下标会对应别的对象。切换筛选是否清除选择、隐藏的已选项目是否仍参与操作，也应明确提示。
12. 部分选中时表头复选框显示半选状态：原生 Checkbox 的 `indeterminate` 通过 DOM 属性设置，不是写一个同名 HTML 属性就会生效，同时要确保状态能被辅助技术正确感知。
13. 批量操作区出现时尽量不把列表整体突然推下去：可以预留工具栏区域或在原区域切换内容；不要为了视觉稳定把大量空白永久占在小屏上。
14. **批量任务不能只记成败**：选中 100 项归档、83 项成功、17 项失败时，不能只弹“操作失败”然后把选择清空——一次批量任务至少记录操作对象快照、任务标识、逐项结果与失败原因（对照表见第四节）。
15. 任务执行中改变筛选，不应改变已经提交的对象集合；若允许用户继续工作，应保留稳定的结果入口，明确“这是刚才那 100 项的结果”。服务端也应处理重试幂等，不能让“仅重试失败项”重复执行已经成功但未收到确认的操作。
16. 跨页全选可能由查询条件代表，执行前应约定集合是请求时的快照，还是执行时动态匹配；有高风险后果时，确认数量和范围尤其重要。结果明细不能只显示错误码，要让人知道哪些对象需要下一步处理。
17. 固定行高便于快速扫描和部分虚拟化实现，却不能裁掉放大后的文字；多行内容应采用可容纳的行高，支持动态行高的虚拟化还要处理测量更新与滚动位置修正。
18. Sticky 表头和固定列要有不透明背景、清楚的层级，并验证交叉区域；横向滚动时给出可继续滚动的线索，阴影可以辅助但不是唯一说明。
19. 键盘聚焦行内按钮时，它不能被吸顶表头或底部批量操作栏挡住：可结合 `scroll-padding`、`scroll-margin` 和布局调整，检查真实滚动容器，而不是仅给整个页面设一个偏移。
20. 返回列表、加载更多或后台插入新行时，尽量保持用户正在看的对象位置；用户在中段阅读时，可以提示“有新项目”供其主动加载，避免自动往顶部插入一批内容把阅读位置挤走。
21. 少量手动重排行可以用短位移动画帮助追踪去向；大量排序结果逐行飞动会造成视觉噪声，也可能阻塞判断——优先保证结果尽快可用，减少动效时直接呈现新顺序。
22. 删除一行后，若焦点原本在该行操作按钮，应交给相邻对象的合理入口，或稳定的列表控件，不能落回文档开头；若支持撤销，要说明恢复的是哪条数据以及恢复位置。
23. 更新单行状态时避免整表卸载重建，否则滚动、选区和焦点都会受影响；虚拟化也应采用稳定键值，它减少节点数量，却会带来浏览器查找、读屏与活动项挂载的额外工作。
24. **空、错误与部分结果各有位置**：首次加载失败可以在表格区域显示重试；加载更多失败应保留已加载行，只在尾部提供重试；某列依赖的附加数据失败，可以在相关单元格或区域提示，不必把整页清空。
25. 分页最后一项被删除后，若当前页变空，应重新计算合理页码；加载状态与“筛选后无结果”也要分开，不能每次请求都先闪一次空状态。

## 二、做完的标准

- [ ] 选中几行后依次排序、翻页、改变筛选、删除；再从第 3 页进入详情并返回，对象、选择范围、焦点与当前位置都仍然可信。
- [ ] 放大文字后横向滚动、只用键盘操作固定列按钮、让加载更多失败，三种情况行内控件都没被吸顶表头或批量栏挡住。
- [ ] 界面写明了“全选”的范围（当前页 20 项 / 筛选后 2,000 项），跨页选择保存的是业务 ID 而不是下标。
- [ ] 一次 100 项批量任务的结果页能看到逐项结果、失败原因与“仅重试失败项”入口。
- [ ] 未知、未填、零在同一个字段里是三种可区分的呈现。

## 三、依据与数值

- `20` 项（每页）与 `2,000` 项（筛选后全部）是示例值，只用来说明全选范围的两种可能，真实值按接口与页面容量定。
- `100` 项 / `83` 项 / `17` 项是示例任务规模，用来演示“部分成功”的结果怎么记。
- 本篇不涉及 WCAG 门槛；`aria-sort`、`indeterminate`、`role="grid"`、`scope` 都属平台约定（ARIA / HTML 语义），不是数值标准。

## 四、控件、表格与示例

| 变化 | 应明确的行为 |
|---|---|
| 点排序 | 当前列、升降序、是否支持多列排序 |
| 改筛选 | 展示生效条件，按约定回到合理页码 |
| 清空筛选 | 清掉哪些条件，默认排序是否保留 |
| 刷新数据 | 保留当前查询与排序，处理页码越界 |
| 从详情返回 | 恢复查询、页码，尽量恢复滚动与焦点位置 |

| 结果 | 后续行为 |
|---|---|
| 成功 | 从待处理选择中移除，按当前视图规则更新行 |
| 可重试失败 | 保留失败对象，提供仅重试失败项的入口 |
| 权限失效或对象状态变化 | 解释具体原因，不能无限循环自动重试 |
| 超时、结果未知 | 查询任务或逐项最终状态，先确认再重试 |

## 五、失败长相与边界

- **从第 3 页进详情再返回，回到第 1 页** → 页码与查询没写进 URL 或历史，也没有恢复动作。
- **刷新后行高变了，刚要点的“详情”滑到下一行** → 行高不稳定或整表重建，滚动位置没有按对象锚定。
- **跨页选择与批量操作结果对不上** → 选择按数组下标保存，排序或删除后下标指向了别的对象。
- **表头写着“全选”，实际只选了当前页** → 全选范围没有在界面上说清，也没有“选择全部”的独立动作。
- **批量失败只弹“操作失败”，选择还被清空** → 没有逐项结果、失败原因与“仅重试失败项”的入口。
- **点行内按钮，顺手进了详情** → 整行可点击吞掉了按钮的点击。
- **键盘按到行内按钮却看不见** → 被吸顶表头或底部批量操作栏挡住。
- **边界**：不是所有临时界面状态都必须写 URL；固定行高不能裁掉放大后的文字；`role="grid"` 不是“表格可操作”的默认答案；阴影不是横向可滚动的唯一说明；虚拟滚动不是把普通列表套进去就算完成。
