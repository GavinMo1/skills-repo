# 04 · 颜色与对比度：把“看着还行”变成可检查

> **适用**：有人问「这个灰能不能用」「这个按钮文字够不够清楚」，或要拿具体色值核对 AA/AAA、算半透明叠加后的实际效果、给色板分语义层时。
> **不适用**：正在做整套深色主题的表面与强调重排（05），或要谈焦点外观的面积与前后对比（07）时。
> **读完能判定**：一对前景/背景在普通文字、大号文字、必要图形三种对象下是否过 AA 或 AAA；大号文字成不成立、装饰边框与禁用态是否在豁免里；半透明是否先按通道合成；一个色值该叫色板格子还是语义用途；错误与成功是否只靠了红绿；APCA 能否当合规结论。

[系列目录](../../README.md) · 上一篇：[布局与排版](03-布局与排版.md) · 下一篇：[深色主题](05-深色主题.md)

同一个灰色放在白色页面上能读，放在浅灰输入框里可能就不够。对比度描述的是一对颜色的关系，单独一个色号没有“通过 AA”这件事。

## 先分清检查对象

以下为 WCAG 2.2 的相关门槛摘要，完整适用条件见原文：

| 对象 | AA | AAA |
|---|---|---|
| 普通文字 | 至少 4.5:1 | 至少 7:1 |
| 大号文字 | 至少 3:1 | 至少 4.5:1 |
| 识别 UI 组件与状态所必需的视觉信息、必要图形 | 与相邻颜色至少 3:1 | 不另设更高数值 |

大号文字指至少 18pt，或至少 14pt 粗体；通常换算约为 24 CSS px，或 18.67 CSS px 粗体。判断时需同时看字号与字重。

不是所有边框都必须 3:1。若填充和文字已能清楚识别按钮，装饰性边框的适用情况不同。禁用组件有相关豁免，但正常的占位文字、辅助说明不能用“次要”作为不达标的理由。

焦点也不是一个孤立的“3:1”数字：AA 要求焦点可见、且不被作者内容完全遮挡；AAA 的 Focus Appearance 另有面积与聚焦前后对比要求，见第 07 篇。

## 算法可以复算

把每个 8 位 sRGB 通道除以 255 得到 `c`，再线性化：

```text
c ≤ 0.04045：c_linear = c / 12.92
其他：c_linear = ((c + 0.055) / 1.055) ^ 2.4

L = 0.2126 R_linear + 0.7152 G_linear + 0.0722 B_linear
contrast = (较亮 L + 0.05) / (较暗 L + 0.05)
```

| 前景 / 背景 | 近似比值 | 普通文字 AA |
|---|---|---|
| `#1F1F1F` / `#FFFFFF` | 16.48:1 | 通过 |
| `#595959` / `#FFFFFF` | 7.00:1 | 通过 |
| `#767676` / `#FFFFFF` | 4.54:1 | 通过 |
| `#8C8C8C` / `#FFFFFF` | 3.36:1 | 不通过 |
| `#E0E0E0` / `#121212` | 14.19:1 | 通过 |

显示值做了四舍五入。实际判定不能把 4.49 向上显示成 4.5 后算通过，也不要只贴门槛配色，给状态变化留些余地。

## 半透明要先合成

对普通 sRGB 页面中的不透明底色，可以先按通道近似合成 `C = α × 前景 + (1−α) × 背景`，再用最终颜色算对比度。比如 87% 白叠在 `#121212` 上，每通道约为 224，即 `#E0E0E0`。

`rgba()` 只改变指定颜色的透明度；`opacity` 影响整个元素及子树的合成结果。若卡片整体半透明，文字也会被一起削弱。

有渐变、图片、多层透明或其他色彩空间时，应根据实际渲染取样，检查文字经过的较差背景区域。只算 CSS 里声明的两个色值可能失真。

## 给颜色按用途命名

把 `gray-600` 当色板格子，把 `text-secondary` 当“次要文字”的语义。组件使用后者，切主题时再为语义映射不同值。

| 原始色 | 语义用途 | 组件用途 |
|---|---|---|
| `gray-950` | `text-primary` | `dialog-title` |
| `blue-700` | `action-primary` | `button-primary-bg` |
| `red-700` | `text-danger` | `field-error` |

色相、饱和度、明度可以帮助调整外观，但 HSL 的明度百分比不等于 WCAG 相对亮度。Material 的 tone 也不能直接当成 HSL 百分比。不要把“浅色用 tone 40、深色用 tone 80”推广为任意品牌色的换算公式。

错误和成功状态还要配图标或文字，不能只靠红绿。hover、pressed、selected、focus 也要分别检查；状态覆盖层能统一算法，不能自动保证每个状态都达标。

## APCA 与色域该怎么理解

APCA 会考虑文字极性等因素，输出的 Lc 与 WCAG 2.x 比值不是同一单位。它的使用建议还涉及字体大小和字重，不能写成“超过 Lc 90 一律过曝”。本系列以 WCAG 2.2 作为明确的核查基线，不用 APCA 替代其合规判定。

普通 hex 色值通常表示 sRGB。Display P3 能表达更宽色域，但要显式使用对应颜色表示法；同一个 hex 在不同屏幕上观感有差异，也涉及校准、亮度和环境，不能全部归因于色域。

验收时逐一检查默认、悬停、选中、错误和聚焦状态，分别覆盖明暗主题。记录的是“哪个前景在什么表面上”，而不是只记录一张通过的色板。
