# 02 · 导航与表单：让用户知道自己在哪、改了什么

> **适用**：页面同时有「跳区域、切内容块、切查看方式」三种看起来一样的切换；或要定字段语义、必填、校验时机、保存模型，以及从列表进详情再返回的落点。
> **本轮不可交付时**：若这一轮的改动只在输入框的聚焦过渡与中文输入法手感，停下并说明「不涉字段语义」，改读 [09-输入框的手感](09-输入框的手感.md)；只在按钮 Loading 与选择器点选时序，改读 [10-按钮与选择器](10-按钮与选择器.md)；只处理未保存与切对象的冲突，改读 [15-保存与草稿](15-保存与草稿.md)。
> **读完能判定**：某个切换控件到底是导航、Tabs 还是分段控件，该不该有独立 URL；导航后标题与焦点落在哪；字段该用哪种控件、保存模型是什么；校验从何时起步、错误显示条件是否会漏掉必填；这块「暂时不能改」该用 disabled、readonly 还是直接显示可复制文本。

## 一、先判

1. **切换控件三选一**：用户的问题是「我去哪个区域」→ 导航链接 / Sidebar / Navbar；「当前区域看哪一块内容」→ Tabs；「同一份内容用哪种方式看」→ Segmented control / 单选组。控件实际是导航，就优先保留链接语义与浏览器行为，别为「切换」牺牲新标签打开与地址复制。
2. **Tabs 可以同步路由。**「切换不改变上下文」只是帮助理解，不能推导出「Tabs 不许改 URL」；它甚至可以每个标签对应一个地址。
3. **Breadcrumb 表达信息层级，不是浏览历史**（例如「项目 / 官网改版 / 设置」）；App bar 常承载页面标题、导航和操作，不必与 Navbar 完全等同；Stepper 表达流程位置，允许回退有助于修正信息，但付款、签署等已完成步骤可能无法直接重开——应解释可改范围，而不是承诺所有步骤都能点回。
4. **列表入口按数据形态选**：需要定位、核对、回访 → 分页；连续浏览 → 无限滚动，但要维护返回位置、加载状态和页脚可达性；节奏要可控 →「加载更多」，它也不自动保证位置恢复。
5. **展开类控件按层级选**：有实际层级的数据 → Tree；一组展开区域、可单开也可多开 → Accordion；单个展开收起 → Disclosure。展开时先保持当前位置，不要无理由自动滚动。
6. **聚合入口克制用**：Split button 只给「常用动作 + 变体」（如「创建项目」与「从模板创建」）；FAB 强调一个主要动作，是否采用服从平台和任务，桌面端未必需要；汉堡菜单会降低导航的直接可见性，空间充足时可展示常用入口。
7. **路由变化后按顺序做三件事**：更新页面标题 → 按路由约定把焦点放到页面标题或主区域（静态标题可用 `tabindex="-1"` 接受程序聚焦，不必进入日常 Tab 顺序）→ 必要时播报新页面已到达；避免焦点移动与直播区域重复朗读相同内容。
8. **首次进入详情从内容顶部开始；浏览器返回列表则恢复原筛选、滚动和合理焦点。** 不要在所有路由变化时一律滚到顶部，也别在每次后台刷新时把焦点抢到标题。
9. **慢加载要说清「正在进入哪个项目」**：URL 已变成项目 B、主体却还显示可操作的项目 A，会造成误编辑——可以展示清晰的加载区域，或保留旧内容并明确标为暂不可操作；旧请求不能在新路由下写回旧项目。
10. **深链接对象已删除、权限已失效**：显示具体原因和返回入口，不要悄悄跳到首页。
11. **字段控件按数据语义选**（表见第四节）：Checkbox 表达独立选择、可多选、同意条款；Radio 一组互斥选项；Switch 某个状态的开与关；Select 从有限选项中选；Combobox 输入并选择建议项；Slider 调整有范围的数值。Combobox 可以限制只能选已有项；Autocomplete 指补全行为，两者并不总能互换。
12. **保存模型先定，再选控件**：Switch 通常让人期待即时生效；若整个设置页统一点击保存，需要清楚显示未保存状态，不应悄悄让开关承担另一种保存模型。
13. **「选项超过十个就必须可搜索」过于机械**：十二个月容易扫读，八个陌生部门反而可能需要搜索；判断依据是选项长度、熟悉程度、排序与使用频率。
14. **校验起点**：合理起点是失焦或提交时提示；错误已经出现后，随输入更新能及时告诉用户问题是否修好。错误显示条件可以是「已触碰或已经提交过」；只写 `touched && invalid` 会漏掉从未触碰的必填字段。
15. **「暂时不能改」按三档降级**：能直接展示可复制文本就不用禁用；要保留焦点与取值用 `readonly`；确实不该进 Tab 顺序、不该随表单提交，才用原生 `disabled`。

## 二、做完的标准

- [ ] 三种切换各自成立：要 URL 的那个是链接（可新标签打开、地址可复制），切面板的键盘走标签模式，换看法的值是互斥的且不产生导航。
- [ ] 路由变化后标题、焦点、播报各发生一次且互不重复；返回列表时筛选、滚动、焦点回到原处。
- [ ] 每个字段三件事齐全：持续可见的 `<label>`、当前值、规则说明，并用 `aria-describedby` 等方式把说明与错误关联到控件。
- [ ] 走一次异常流程：不填必填项直接提交，确认能找到错误；修正一个字段，确认错误及时消失；断网保存，确认内容仍在；恢复网络再保存，确认没有重复提交；再刷新页面，确认「已保存」是真的持久化成功。
- [ ] 每个「暂时不能改」的位置写明了为什么选可复制文本 / `readonly` / `disabled`。
- [ ] 保存模型与控件承诺一致：Switch 即时生效，或整页保存时显式显示未保存。
- [ ] 列表入口的位置恢复经一次真实返回验证：第 3 页进详情再返回，不回第 1 页。

## 三、依据与数值

- `2–40 个字符` 是示例规则（项目起点），不是标准：真实上限按接口定，字符口径（UTF-16 码元 / 字素簇 / 字节）要前后端一致。
- 「选项超过十个就必须可搜索」属项目起点的经验判断，不是标准要求，判据见第一节第 13 条。
- 断点续传不是默认选项：需按文件规模与网络场景决定（项目起点，不是标准要求）。
- 本篇不涉及 WCAG 门槛；对比度、焦点与热区的门槛在 04、05、07。

## 四、控件、表格与示例

三种看起来相似的切换：

| 问题 | 通常使用 | 行为约定 |
|---|---|---|
| 我去哪个区域？ | 导航链接、Sidebar、Navbar | 可以有独立 URL，支持返回、刷新、分享 |
| 当前区域看哪一块内容？ | Tabs | 有对应面板，键盘操作遵循标签页模式 |
| 同一份内容用哪种方式看？ | Segmented control、单选组 | 选择列表/网格等互斥值 |

表单控件承担的是数据语义：

| 控件 | 适合表达 | 需要明确的事 |
|---|---|---|
| Checkbox | 独立选择、可多选、同意条款 | 是否必选、是否有全选和半选 |
| Radio | 一组互斥选项 | 初始是否已选，是否允许不选 |
| Switch | 某个状态的开与关 | 即时保存还是整表提交 |
| Select | 从有限选项中选择 | 选项是否容易扫读 |
| Combobox | 输入并选择建议项 | 能否输入列表外的值 |
| Slider | 调整有范围的数值 | 当前值、步长、精确输入方式 |

一个字段至少说清三件事：

```text
项目名称                         ← Label：这是什么
[官网改版                    ]   ← 输入内容
2–40 个字符                      ← Helper：规则
```

出错后显示「项目名称不能超过 40 个字符」，并用 `aria-describedby` 等方式把说明、错误与字段关联；错误不能只靠边框变红表达，替换 Helper 时也要保留仍然必要的规则。Placeholder 只做示例，不能替代持续可见的标签：填写后它会消失，它若承载必要说明，也不能因为颜色淡就免除对比度要求。

## 五、失败长相与边界

- **三处切换都画成一排按钮** → 用户很难知道自己是在跳转、切视图，还是修改数据。回第一节第 1 条重选控件。
- **点标签页整页刷新、地址栏没变** → Tabs 被做成了按钮式导航。控件实际是导航就换回链接；是 Tabs 就补面板与标签页键盘模式。
- **从详情返回，筛选与滚动全丢了** → 状态没写进 URL 或历史，也没有恢复动作。
- **表单报错了但没说是哪个字段** → 错误文字没有与控件关联，或只靠边框变红。补关联与就地文案，并把焦点引到错误摘要或第一个错误字段。
- **刚打一个字就红一片** → 校验起点错在输入过程中，改到失焦或提交。
- **置灰的输入框被读屏直接跳过去** → 用了原生 `disabled`，而这个位置需要被读到；改成 `readonly` 或直接展示可复制文本。
- **整页点保存，但开关看起来已经生效** → 两套保存模型混用；要么即时保存，要么显式显示未保存。
- **提交失败后表单被清空** → 失败路径没有保留已填数据。
- **异步查重把旧结果盖在新输入上** → 没有处理请求乱序；不能让较早的结果覆盖新输入，服务端仍要做最终校验。
- **边界**：`select` 没有原生 `readonly` 属性；`aria-disabled="true"` 只是状态语义，点击、键盘与提交要自己拦；日期选择器尽量支持键入并说明格式，出生日期不适合让人翻几十年日历；标签输入要支持键盘删除与带对象名的删除按钮（如「移除张三」）；上传控件要提前说明格式与大小限制，并提供进度、失败原因和重试。
