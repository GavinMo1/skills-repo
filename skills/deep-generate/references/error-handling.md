# 异常处理

主协调者首次执行前读取；出现异常时查阅对应规则。修复不得绕过授权、伪造检查结果或无限重试。

| 条件 | 恢复动作 | 停止或继续条件 |
|---|---|---|
| Agent 长时间无新输出 | 检查工具状态、错误及可见进展；按环境的超时信息判断。确认为失败时，保留可用输出并重试一次，可缩小独立任务或减少并发 | 再次失败时记录未完成任务。继续不依赖它的工作，暂停被它阻断的部分；不以统一秒数判定失败 |
| 独立 Agent 不可用 | 完成资料与结构等可独立推进的工作，说明独立撰写或评审能力缺失 | 用户接受替代方式后再顺序写作与自检，报告中保留“未独立评审”状态 |
| 资料不可获取或来源冲突 | 使用可访问材料，查找相关原始来源；记录适用条件与证据差异 | 核心结论缺证时缩小论点或保留待核实状态，不补造依据 |
| 知识图谱为空或过于宽泛 | 回到读者目标与核心问题，检查题目范围、检索条件及分析输入，再做一次针对性分析 | 仍无可用依据时报告缺口；可记录临时结构，但不能宣称已完成知识梳理 |
| 文件缺失、为空或内容错位 | 核对路径、任务标识和输入版本；让对应执行者重写或补交一次 | 仍失败时标明缺口，暂停依赖该文件的任务；不把文件存在当作覆盖完整 |
| 写入失败 | 检查目标目录与权限，在已授权位置创建必要目录后重试一次 | 用户指定路径仍不可用时说明具体失败与原因，不静默更换位置；继续不依赖写入的准备工作 |
| 术语冲突 | 比较定义、领域惯例和来源，区分同义词与不同概念，再修改受影响内容 | 存在会改变结论的歧义且资料无法解决时，保留争议并询问所需信息，不按频率替换 |
| 评审意见冲突 | 对照位置、依据、章节目标和适用条件，由主协调者记录采纳或不采纳理由 | 缺少决定性证据时标待核实，不用投票或平均分代替判断 |
| 修订引入退化 | 比较修改前快照、问题处理记录与新稿，定位丢失或错误内容 | 恢复受影响内容并复核有效修复；不单纯按分数回退 |
| 问题修订达到既定预算 | 保存可用版本与全部记录，说明仍存问题、影响和依赖 | 预算是执行限制，不是通过标准；继续需调整预算，不重置预算无限重审；交付不受影响的内容，明确部分完成状态 |
| 主题不足以支持多个有价值章节 | 按核心问题合并或缩小结构，解释原因 | 不为凑章数拆分内容；实际范围与用户明确要求冲突时询问 |
| 上下文不足以容纳全部章节 | 分批读取正文，维护章节职责、版本与问题索引，需要时重读相关段落 | 不根据截断内容声称完成全系列检查 |
| 清单损坏或更新中断 | 保留损坏副本，读取上一有效清单，对照实际文件、Agent状态、报告、快照和修订处理记录重建；按状态协议运行机械检查 | 无法核实的版本、身份和预算标未知或待核实，不凭旧完成标记接受输出，不重复派单 |
| 评审输入变化 | 按覆盖目标把受影响条目标为pending；由原独立评审者确认沿用或复查，保留旧报告为历史依据 | 当前版本未获确认前不沿用通过；单纯哈希变化不等于内容错误 |
| 历史修订不明 | 对照实际输出、问题处理记录和任务历史恢复已完成修订；派发与失败不计轮次，同提交续接不重复计数 | 无法核实则标未知，不凭空补全历史；暂停需要依赖剩余预算的新修订，报告限制 |
