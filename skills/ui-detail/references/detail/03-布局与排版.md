# 03 · 布局与排版：让信息自然成组

> **适用**：页面「看着乱」但说不上哪错：间距没有尺度、同一区块对齐线太多、图标与文字总差一点、字号行高行宽不成套，或要定断点、紧凑模式与安全区。
> **本轮不可交付时**：若这一轮只是颜色不达标、要算对比度，停下并说明「不涉间距与对齐」，改读 [04-颜色与对比度](04-颜色与对比度.md)；若只是对齐之后焦点环与热区被裁，改读 [07-无障碍](07-无障碍.md)。
> **读完能判定**：这处「乱」是间距问题还是对齐线太多，先减线还是先调值；这处该做几何对齐还是视觉补偿、补偿上限在哪；图标配多大字、viewBox 留白要不要计入；字号行高行宽是否成套、中文一行多少字；断点取在哪、容器查询还是媒体查询；紧凑行高会不会裁字。
> **超限理由**：R3 要求原样的 4 个代码块共 46 行（15+7+9+7 内容行）与 3 张表共 28 行（间距 7、视觉对齐 11 种错位、字号 5）已占 74 行，加结构 20 行是 94 行；R1 的 28 个数值与 R6 的错位边界几乎全部落在这 3 张表里，删表只能改写成散文，行数不减反增。压到 110 行以内必须删掉一张表或两个代码块，即丢 §4 证据，故超限；正文已无 §5 命中形态可删。

## 一、先判

1. **先分这处「乱」是哪一种**：同一区块里有的元素贴 16px、有的贴 24px、有的自己居中 → 对齐线太多，先减线；间距本身没有尺度 → 先按关系定值。间距再标准，线太多也还是散。
2. **间距按关系定，不按整齐定**：名称、负责人、截止日期的字号都一样，也依然可以有清晰层次——先让用户看出哪些内容属于一组，再用字号和颜色表达组内关系。Label 到输入框 8px、字段之间 24px、区块之间 40px 是一组可尝试的起点；读者把相近元素感知为一组（亲密性 proximity），若字段间距反而小于 Label 到输入框的距离，用户容易认错归属。同级元素优先用父容器的 `gap`，减少外边距抵消与首尾例外。
3. **4px 基准与 8px 节奏只管选取统一**：它们不保证任意缩放下都不出现半像素；1px 边框、字号、视觉微调这类奇数值不天然错误。
4. **对齐先问「有没有一条共同的边」**：人对 1–2px 的偏差很敏感，成排元素里那点偏差会被看成歪了。一个区块通常一到两条纵向对齐线就够，多一条往往不是需要，而是没想清楚哪个是主角；对齐还要有参照物（容器内边距、栅格、相邻元素），对齐到容器边缘比各自居中更稳，长文本居中会让右缘参差、每行起点都不固定。
5. **参照系按位置选，不统一成一套**：Label 上置对齐左缘，左栏式表单可右对齐 Label 去贴近输入框，表格文字列随阅读方向、数值列向尾侧；混用参照系才会乱。行首有列表符号、序号、悬挂标点时，缩进对齐到正文首字，不是符号边缘。
6. **三层的顺序不能反**：先问这条边该不该存在 → 再让数值收敛到少数几条对齐线（几何）→ 最后才问墨迹是否也齐（视觉）。跳过前两步直接微调，得到的是好看的偏差，不是对齐。
7. **坐标对上了眼睛还不认，先看盒子里那些看不见的空白**：侧栏星标与标题左缘同为 8px、三角图标与文字共用一套居中规则、主按钮上下 padding 相等、卡片嵌套圆角按同心公式算过——数值都在，放大到 200% 却看到星标像是往里缩、三角形看着偏左、按钮文字略微偏上、卡片角上厚薄不均。这类问题叫**视觉对齐**（optical alignment）：行盒的 ascent / descent 与字母侧边距、图标 viewBox 的内边留白、三角与圆的墨迹本来就不铺满外接框，都让包围盒与墨迹分离；此时按墨迹与视觉重心对齐，而不是按盒子坐标。
8. **补偿有上限**：通常 0.5–1px，最多 2px，约合 0.02–0.05em。超过这个量级，多半是间距或参照系选错了，应该回去改布局，而不是继续挪元素。
9. **三层处理，先规律后单点**：字体的 overshoot 已经内置，不要自己再加；图标视觉尺寸、圆角内缩、描边补偿是可复用规则，写进组件或 Token 让一批元素一起对上；字面与字身框的差异、viewBox 留白，优先统一内边距与画布，改一处对一片；只剩单点补偿才动 1px 级，并写清理由——说不出理由的偏移是随手调，不是对齐。
10. **一次只改一个自由度**：先横向后纵向，改完立刻和相邻元素一起看；字体或字号一变就重看，因为以 em 表达的补偿跟字号走、以 px 表达的不跟，换字体后侧边距全部改变，旧偏移直接作废。
11. **布局工具按职责选**：行列协同 → Grid，沿主轴排布 → Flex，两者可嵌套，不必按「一个页面只能选一种」理解；组件在主区与侧栏之间复用时按实际容器宽度变化，用容器查询，页面级导航与整体布局切换仍用媒体查询。
12. **字号、行高、行宽一起看**（表见第四节）：中文正文先试每行约 30–40 个汉字，再按字号、内容和屏幕调整；`ch` 基于数字「0」的字形宽度，不等于汉字数，支持时用 `ic` 近似全角字宽并配最大宽度兜底。
13. **密度与视口按实机定**：紧凑模式把表格行从 44px 改到 36px 可以保持字号，但触屏仍要查热区，多行内容不能被固定行高裁掉；`dvh` 跟随动态视口，要更稳时考虑 `svh`；Sticky 失效常与祖先滚动容器、可滚动空间有关，不要看到 `overflow` 就断定失效。
14. **底线不因视觉补偿让步**：热区、焦点可见性、文字对比与语义不变；为了「看着齐」把点击区域缩到 24×24 以下、或让焦点环被容器裁掉，是拿可用性换观感。视觉对齐是最后一层修整，不是可用性的替代品；它也依赖人眼，不同人、不同屏幕的敏感度不一样，宁可少调、写明理由，不必追求把每个像素都调到理论最优。

## 二、做完的标准

- [ ] 这一区块的纵向对齐线数得出来，且不超过两条；新加的元素落在已有线上，不是自己居中。
- [ ] 间距全部取自同一套 Token（4 / 8 / 12 / 16 / 24 / 32 / 40 中的值），字段间距大于它内部 Label 到控件的距离。
- [ ] 每处偏移（星标、三角、按钮文字、圆角嵌套处）都有注释写明原因；单个补偿不超过 2px，横向与纵向分别验证，不与相邻元素的原有对齐线冲突。
- [ ] 在 1x 与 2x DPR、200% 缩放各看一遍：半像素、小数宽度与非整数缩放的偏差在这里暴露。
- [ ] 用 `O`、`上海`、`100%`、`（3）` 这类边缘不规则的真实内容替掉占位文本，眯眼扫一遍，仍跳出来的那个元素就是没对齐的。
- [ ] 沿元素墨迹的边缘拉一条参考线，看同一组元素是否共用一条线；临时加的辅助 `outline` 或参考线，检查完就删掉。
- [ ] 补偿后复测热区、焦点环与文字对比：点击区域不小于 24×24，焦点环没有被容器裁掉。
- [ ] 断点处放真实项目名与长按钮文案，以内容开始挤压的位置为准；设计系统现成的断点只帮助统一，不是设备分类的自然定律。
- [ ] 字号表每个角色各走一遍中英文混排：长标题换行不重叠，辅助文字不被低对比度进一步削弱。
- [ ] 中文正文在每行 30–40 个汉字下读完一段，换行可追踪；金额与计时器上的等宽数字生效。
- [ ] 紧凑模式下多行内容没有被固定行高裁掉；水平数据表可单独滚动，页面其他内容正常重排。

## 三、依据与数值

- 4px 基准、8px 节奏，以及 4 / 8 / 12 / 16 / 24 / 32 / 40 这套间距，都是**项目起点**，不是标准要求；取舍看真实内容与缩放。
- 0.5–1px（最多 2px，约 0.02–0.05em）的视觉补偿是**项目起点**，须在真实字体与 1x / 2x DPR 下核对。
- 正文字号与行高、每行 30–40 个汉字、紧凑模式 44px → 36px，都是**示例值 / 项目起点**。根字号若为默认 16px，1rem 对应 16px；不要为了换算方便把根字号固定成很小的值。
- 20px 图标配 16px 界面文字、24px 图标配 20px 小标题，是**平台与项目的常见起点**，不是标准要求；13、15、17px 的字号并不违规，数字统一是为了让相同角色表现一致——模数比例只是建立阶梯的一种方法，也可以按语义角色直接定义。
- `24×24` 是触控目标的下限约定；对比度、焦点可见性与热区的具体门槛不在本篇，见 [07-无障碍](07-无障碍.md) 与篇末两个 WCAG 链接。

## 四、控件、表格与示例

间距先表达关系：

| Token | 起点 | 用途示例 |
|---|---|---|
| `space-1` | 4px | 紧凑的图标与文字 |
| `space-2` | 8px | 标签与控件 |
| `space-3` | 12px | 小容器内边距 |
| `space-4` | 16px | 列表项、紧凑卡片 |
| `space-6` | 24px | 字段组、标准卡片内边距 |
| `space-8` | 32px | 区块分隔 |
| `space-10` | 40px | 大区块分隔 |

Gutter 是栅格栏间距，Margin 是元素外距，Padding 是内距。

### 几何对齐：让边缘替你分组

判据在第一节第 4、5 条：一个区块收敛到一到两条纵向对齐线，参照物取容器内边距、栅格或相邻元素。

### 视觉对齐：坐标对上了，眼睛还要认

几何对齐做完，还剩一层「线对上了却仍然歪」的偏差，可先对号入座：

| 情况 | 只做几何对齐会怎样 | 可以先试的做法 |
|---|---|---|
| 圆弧字形 O、o、C、S 与直边字形 H、E 并排 | 圆弧的墨迹离边更远，看着内缩 | 字体本身已有 overshoot，通常不必额外补；要补的是自定义图形与图标 |
| 汉字与拉丁字母用同一字号 | 汉字字面率更满，看着更大更重 | 按字号角色统一，不逐字调；混排标题可微调字重或字距，看真实字形再定 |
| 圆形头像、圆形图标与方形元素同一左缘 | 圆心离边更远，看着缩进 | 对齐圆的最左墨迹点，或统一按圆形的视觉外框给容器定内边距 |
| 三角形播放图标、对勾、箭头、徽标 | 重心偏向底边或一角，看着偏 | 用 `translate` 做 0.5–1px 补偿，并在注释里写明原因 |
| 图标与文字水平并排 | 图标盒子留白不同，间距看着不等 | 按视觉尺寸选图标（如 20px 图标配 16px 文字），先用 `gap` 统一，再考虑单点微调 |
| 单行按钮、标签、输入框的文字垂直居中 | 行盒 ascent 与 descent 不对称，中文看着偏上 | 先做对称 padding 与稳定行高，再试 `text-box-trim`，最后才微调 1px |
| 卡片圆角内嵌子元素 | 内外圆心不重合，角上出现厚薄不均 | 用 `内圆角 = max(0, 外圆角 − 间距)`，并把边框宽度算进间距 |
| 2px 描边与 1px 描边并排 | 描边更重的那侧看着更大、更靠外 | 减 padding，或让描边向内（`inset` 阴影、负的 `outline-offset`） |
| 文字下方的下划线、分隔线 | 几何等距，视觉上要么贴住字脚要么离太远 | 用 `padding-bottom` 决定线的位置，而不是拿负 margin 硬拉 |
| 有阴影与无阴影的元素并排 | 阴影让元素看着更重、更大 | 统一阴影层级，或给无阴影一侧留出等量空间 |
| 0.5px 边框、奇数宽度、非整数缩放 | 1x 下糊成一片，2x 下才清楚 | 用整数档的 1px 或 2px；小数宽度只在确认过的 DPR 下使用 |

图标与文字混排看尺寸和位置：尺寸按视觉大小配，不看几何边长，常见起点是 20px 图标配 16px 界面文字、24px 图标配 20px 小标题；viewBox 里若有 1–2px 内边留白，实际看起来会更小，要么放大，要么裁掉留白。位置看重心，横向先用 `gap` 统一，纵向只在某个图标确实看着偏上偏下时才单点补偿；补偿只改绘制，不改命中区域与焦点环。

按钮、标签与输入框里的文字：上下 padding 相等不等于视觉居中，因为行盒里 ascent 与 descent 不对称，中文字形通常略微偏上，带 descender 的字母又会往另一边拉。先做对称 padding 与稳定 `line-height`；支持时让 `text-box-trim` 裁掉行盒上下多余空白，盒高等于字面高时垂直居中对齐的就是墨迹；不存在时退回对称 padding + 1px 微调。

```css
.primary-button {
  display: inline-flex;
  align-items: center;
  gap: .5rem;
  padding-block: .5rem;
  line-height: 1.5;      /* 固定行高，避免字体回退时高度漂移 */
  min-block-size: 2.5rem; /* 保证热区，而不是靠 padding 撑出来 */
}

@supports (text-box-trim: trim-both) {
  .primary-button {
    text-box-trim: trim-both;
    text-box-edge: cap alphabetic; /* 按大写字母高与基线裁，中文需实机核对 */
  }
}
```

形状的重心：三角形播放图标重心偏向底边，光学中心比包围盒中心略高，按盒子居中时看着偏下；同尺寸的圆和方并排，圆看起来更小，圆形按钮里的图标可以比方形按钮里的略大一点。对勾、箭头、加号、圆点各有各的重心，品牌图形与徽标同理，补偿写成带注释的变量：

```css
:root {
  /* 视觉微调：数值是项目起点，需在真实字体与 1x/2x DPR 下核对 */
  --optical-icon-y: -.5px;    /* 星标重心偏上，向下半像素 */
  --optical-glyph-start: -.04em; /* 超大标题首字 O 的左侧留白 */
}
.icon-button > svg { translate: 0 var(--optical-icon-y); }
.display-title { margin-inline-start: var(--optical-glyph-start); }
```

圆角嵌套与描边：`内圆角 = max(0, 外圆角 − 两者间距)` 要把边框宽度也算进间距，否则角上差一条边；它只是一层近似，圆角较大时内外弧的视觉厚度仍可能不均，可以用嵌套容器或调整 padding 再看。描边本身影响视觉尺寸，`box-sizing` 管的是布局尺寸，视觉重量得单独平衡——常见做法是减 padding，或让描边向内（`inset` 阴影、负 `outline-offset`）。字面与字身框的差异，应该靠容器内边距成批统一，而不是逐字挪；只有超大标题、品牌字这种一字一议的场合，才用 `-0.02em` 到 `-0.06em` 的负边距把首字拉到视觉边缘，并且只在字体确定之后做，换字体、换语言就失效。

```css
.project-layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 18rem;
  gap: 1.5rem;
}
.actions { display: flex; flex-wrap: wrap; gap: .5rem; }
@media (max-width: 52rem) {
  .project-layout { grid-template-columns: minmax(0, 1fr); }
}
```

52rem 是示例断点。

字号、行高与行宽要一起看：

| 角色 | Web 起点 | 需要观察什么 |
|---|---|---|
| 辅助文字 | .875rem / 1.5 | 是否被低对比度进一步削弱 |
| 界面正文 | 1rem / 1.5–1.7 | 表单和短文本是否拥挤 |
| 中文长文 | 1rem / 1.7–1.9 | 换行是否容易追踪 |
| 小标题 | 1.25rem / 1.4 | 与正文能否区分 |
| 页面标题 | 1.75rem / 1.25 | 长标题换行是否重叠 |

表中斜线后是无单位行高。

```css
.reading {
  max-inline-size: 42rem;
  max-inline-size: 36ic;
  line-height: 1.8;
  overflow-wrap: anywhere;
}
.amount { font-variant-numeric: tabular-nums; }
```

等宽数字适合金额和计时器，但前提是字体支持；小数点对齐还要靠表格布局或拆分数值列。字体也不是一个 font-size：Font stack 是后备字体列表，x-height 影响拉丁小写字母的视觉大小，cap height 影响大写字母对齐，Tracking 对应整体字距，leading 对应行高，kerning 调整特定字形对，中文还有标点挤压等排版问题，不能简单归为「没有字偶距问题」。系统字体加载快、平台差异大；Web font 可控，但要衡量体积、子集和缓存，中文网络字体可以子集化使用；可变字体可提供字重和光学尺寸等轴。正文可从 400 字重开始，标题试 600，细字重并非禁用项，但小字号中文在部分设备上确实更难读，需要实机比较；不要全局强加非标准字体平滑属性，macOS Mojave 移除次像素抗锯齿也不是仅发生在深色模式。长文要留意孤行寡行，截断内容时提供查看完整内容的方法，关键金额、错误原因不能只剩省略号。

## 五、失败长相与边界

- **「整体看着乱」但每个值都合规** → 对齐线太多。先减线（第一节第 1、4 条），不要继续调间距。
- **成排元素里 1–2px 的偏差被看成歪了** → 没有共同的边，或参照系混用。
- **星标像是往里缩、三角看着偏左、按钮文字略微偏上、卡片角上厚薄不均** → 包围盒对齐了，墨迹没对齐；按第一节第 7 条处理，先确认这条边该不该存在。
- **越调越多，最后说不清为什么** → 已经越过 2px 量级还在挪元素，间距或参照系选错了。
- **改了字体或字号，之前调好的全歪了** → px 偏移没跟着字体走，旧偏移作废，需要重看一遍。
- **图标与文字总差一点** → 只对齐了包围盒；先按视觉尺寸选图标、用 `gap` 统一，再考虑单点补偿。
- **0.5px 边框在 1x 糊成一片、2x 才清楚** → 用整数档的 1px 或 2px，小数宽度只在确认过的 DPR 下使用。
- **紧凑模式下行被切掉半截** → 固定行高裁掉了多行内容；密度表里的「行高」要区分 CSS 文本行高与整行容器高度。
- **边界（不该动的时候）**：数据密集的表格不逐列微调，会让人以为数值不等，该靠对齐线与等宽数字；多语言界面不为中文调偏移，为中文调好的偏移换到英文、阿拉伯文会反向出错，用与方向相关的 padding 处理，别写死 px 偏移；字体、字号、真实文案都没定下的早期界面不调；语义与替代文本缺失时视觉再齐也不成立，那是 [07](07-无障碍.md) 的事。
- **边界**：`内圆角 = max(0, 外圆角 − 两者间距)` 是同心几何的近似规则，不是所有视觉效果的定律；`text-box-trim` 的支持范围仍然有限，`text-box-edge` 对中文需实机核对；移动端安全区与视口按实机验，`dvh` 与 `svh` 的取舍取决于那块容器要不要铺满当前可见区域。
