# 12 · 浮层的开合与定位：动画期间也要能操作

> **适用**：日期面板跟着页面滚走了留在原地、抽屉关掉 Tab 还能走进去、点面板内部外层也跟着关，需要把画面、坐标与交互状态一起对齐时。
> **本轮不可交付时**：若全部浮层都用原生 dialog 或成熟组件、不改写其生命周期，也没有自定义锚点定位，停下并说明「生命周期未自写」，只读 [01-浮层](01-浮层.md) 与 [07-无障碍](07-无障碍.md)。
> **读完能判定**：开合各阶段里焦点、背景阻断、可访问性与 DOM 挂载分别在哪一刻切换、关闭时先移焦点还是先失活；快速开关时新意图是否取代旧过渡、transitionend 该过滤什么、零时长与被取消时如何收尾；定位要考虑哪些量、Portal 不解决什么；软键盘下用 dvh 还是 Visual Viewport；滚动锁怎么补偿、嵌套浮层关闭时外层锁能不能解；外部关闭是否按一整次手势判定。

日期面板从输入框下方淡入，看起来很好；页面向下滚动后，它却留在原地。另一种情况是抽屉已经滑出屏幕，Tab 仍然能走到其中的按钮。浮层的完整实现需要同时照顾画面、坐标和交互状态。

## 开合不只有 true 和 false

画面上通常经历“关闭 → 进入中 → 打开 → 离开中 → 关闭”。但焦点、背景阻断、可访问性和 DOM 挂载，不必在同一时刻切换。

| 阶段 | 需要处理的事情 |
|---|---|
| 开始打开 | 记录触发位置、挂载并定位、按模式阻断背景、安排初始焦点 |
| 进入中 | 内容已经可用，不等待整段动画才响应键盘 |
| 打开 | 维护定位、焦点范围和外部点击规则 |
| 开始关闭 | 防止继续激活旧内容，按约定处理子浮层与焦点 |
| 关闭完成 | 清理挂载、事件监听和滚动锁，保证焦点有合理落点 |

关闭时可以先把焦点移到安全位置，再让旧内容失去交互能力。不要给仍含有焦点的区域直接设置 `aria-hidden="true"`，也不要只靠 `pointer-events: none`：它不阻止键盘聚焦。

模态关闭期间是否继续阻断背景，应与焦点转移和滚动锁协调。使用原生 `<dialog>` 或成熟组件时，先遵循其生命周期，不要在其内部再叠一套互相打架的锁焦点逻辑。

## 快速开关不能把状态机弄乱

用户可能在进入动画结束前按 Esc，或关闭动画没结束就重新打开。应让新意图取代旧过渡，避免旧的动画完成回调把刚打开的浮层卸载。

如果用 `transitionend` 收尾，要过滤目标和属性，并考虑零时长、过渡被取消、元素提前移除等不会正常收到预期事件的情况。减少动效时生命周期也要正常完成，不能永远卡在“离开中”。

离场动画往往只需短暂保留外观，不应该延迟业务结果；保存成功不必等抽屉彻底滑走才更新列表。复杂的动画生命周期优先用经过验证的实现，避免把卸载时机散落在多个定时器里。

## 锚点定位要能持续更新

Popover、下拉菜单和 Tooltip 通常需要依附某个元素。定位至少要考虑：

- 锚点在视口中的位置、面板实际尺寸、页面和祖先容器滚动。
- 视口边缘空间不足时翻转方向或平移避让。
- 面板内容异步增长、字体变化、窗口缩放和布局变化。
- 锚点被移除、滚出可见区域或被虚拟列表回收。

`getBoundingClientRect()` 返回相对视口的坐标；若把结果用于另一个坐标系的绝对定位，需要正确换算。祖先 `transform` 也可能改变固定定位元素的包含块。不要只在第一次打开时测一次，之后假设位置永远不变。

可用适合目标浏览器的 CSS Anchor Positioning，或有碰撞检测和自动更新能力的定位库；采用前仍需验证支持范围与退路。Portal 可以绕开部分裁剪问题，但不会自动解决坐标、模态焦点和 top layer 问题。

面板翻到上方后，动画原点也应跟随实际位置，避免看起来从错误方向长出来。小幅位移与透明度过渡通常足够，范围过大会让锚点关系更难追踪。

## 移动端键盘出现后

地址栏与软键盘会影响可见空间，具体视口变化依赖浏览器和配置。`100dvh` 有助于处理动态视口，但不能假设它在所有环境下都等于键盘上方的剩余高度。

需要时利用 Visual Viewport 信息处理定位，并在真实设备上验证。目标是聚焦字段、候选列表与主要动作仍然可达；不能一打开键盘就无条件滚到页顶。

底部面板要为安全区留空间，长内容提供可滚动区域。主按钮固定在底部时，要避免盖住最后几个字段；有时把操作放进正常内容流比复杂吸底更可靠。

## 滚动锁也会影响“顺滑”

模态打开后锁住背景滚动，桌面滚动条消失可能让页面横向跳一下。可以根据支持情况使用 `scrollbar-gutter: stable` 或补偿滚动条空间，并检查固定定位的导航栏是否一起偏移。

手机上的滚动锁需同时考虑页面位置恢复与面板内部滚动。`overscroll-behavior` 能帮助控制滚动链，但不能单独替代所有背景交互阻断。嵌套浮层关闭时，也不能提前解除外层仍需要的滚动锁。

## 子浮层、外部点击与 Esc

Dialog 里打开日期面板时，“点在日期面板上”不应被外层当作点击对话框外部而关闭。Portal 挂载后，DOM 祖先关系与视觉从属关系可能不同，外部交互判断要纳入所属浮层。

Esc 通常先由最上层、当前相关的浮层处理，避免一次按键把菜单和对话框全关掉。处理过事件后，应按组件契约协调传播，而不是在整个应用到处拦截 Esc。

上下文菜单、Popover 和模态 Dialog 的键盘模式也不同。层级管理器可以协调打开顺序，但不能用一套统一焦点陷阱套所有浮层。

Tooltip 和 Hovercard 还需允许指针从触发器移动到内容区域，不因中间的小缝隙立即消失。短关闭延迟或安全路径判断可以改善体验，但不能让已经不相关的提示长期遮住页面。Tooltip 的可关闭、可悬停与持续要求见第 01 篇。

## 外部关闭应识别一整次手势

在面板内按下鼠标、拖动选择文字、移到框外松手，不应被简单解释成“点了外面”。一种保守约定是：主指针在外部开始、在外部结束，且没有被判为拖动、滚动或取消，才作为外部关闭候选；也可遵循成熟组件库已经验证的约定。

需要记录本次 `pointerId`、按下来源、移动与取消状态，处理 `pointercancel`。右键、滚动条操作、触屏滚动、多指输入和嵌套浮层也不能混成同一种点击。

在 `pointerdown` 就卸载浮层，后续指针事件可能进入背景，造成关闭后误触背景动作。采用什么关闭时机、是否阻止该手势后续激活，应与组件事件模型一起验证；不要靠全局拦截所有点击解决。

验收至少包括：框内拖选到外面松手不误关；外部正常点击按约定关闭；滚动候选列表不误关；关闭手势不同时触发背景删除按钮。

## 检验完整生命周期

连续快速开关；进入中按 Esc；关闭中重新打开；打开子面板再关闭；滚动祖先容器；改变窗口大小；面板里加载一段长内容；在手机上弹出键盘；关闭动画后连续按 Tab。

最后确认：浮层仍跟着正确对象、背景没有误滚、内容不被边缘裁掉、旧浮层不再接受焦点，回到页面后滚动与焦点位置合理。把动画关闭后再走一遍，不能因动画事件消失而破坏流程。
