# 07 · 无障碍：用键盘和读屏器走完同一条路

> **适用**：自绘下拉、模态、图标按钮或表单刚做完，要在交付前用键盘与读屏器把「查找→编辑→保存」这条真实任务完整走一遍时。
> **本轮不可交付时**：若这一轮只动视觉稿与配色间距、不涉可操作控件与焦点路线，停下并说明「没有可走的键盘路径」，改读 [03-布局与排版](03-布局与排版.md) 或 [04-颜色与对比度](04-颜色与对比度.md)。
> **读完能判定**：该用原生 button/a 还是 role、值不值得承担补齐行为的成本；Tab 顺序是否与任务一致、正数 tabindex 值不值得；模态焦点怎么进、怎么限制、关闭后回哪、危险确认默认是否落在危险按钮；焦点环是否真的可见、是否被自己创建的内容遮住；热区按 24 还是 44、相邻是否误触；播报用 status 还是 alert、是否过量。

## 一、先判

1. **执行动作用 `<button>`，跳转用带 `href` 的 `<a>`**：原生按钮自带键盘行为和语义；给 `<div>` 加 `role="button"` 后，还要自己补聚焦、Enter、Space、禁用等行为——先算这笔成本再决定。
2. **ARIA 只补充名称、角色与状态，不实现交互**：`aria-expanded` 不会替你打开菜单，`aria-modal` 也不会锁住焦点。
3. **定位与跳读先看结构**：`nav`、`main`、标题层级帮助用户定位页面；Skip link 可以让键盘用户跳过重复导航；不要为了“结构整齐”把所有文字都做成无层级的 div。
4. **图标按钮需要可访问名称**（例见第四节）：若按钮本来已有清楚的可见文字，通常不必再用 `aria-label` 覆盖它。
5. **正常 Tab 顺序应与阅读和操作顺序一致，尽量避免正数 `tabindex`**；Tabs、菜单、树等复合控件还可能用方向键在内部移动，需要遵循对应模式，不能让每个选项都随意抢进 Tab 顺序。
6. **模态打开后把焦点移入内部**，Tab 与 Shift+Tab 留在其中，关闭后合理返回；长内容可以先聚焦标题等静态元素；危险确认不应默认把焦点放在最容易误触的危险按钮上。
7. **`:focus-visible` 不是“鼠标永远不显示”**：它使用浏览器启发式判断，输入框被点击后也可能匹配；焦点环样式是示例，仍需在实际背景上检查。
8. **焦点可见与焦点被遮挡是两个条号**：WCAG 2.2 AA 要求焦点可见（`2.4.7`），且不被作者创建的内容完全遮挡（`2.4.11`）；AAA 的 `2.4.13` 还规定焦点外观的面积与聚焦前后至少 `3:1` 的变化等条件——不要用一条颜色规则代替全部要求。
9. **热区先分 AA 还是 AAA**：AA 的 `2.5.8` 通常要求至少 `24×24` CSS px，也有间距、等效控件、行内文本、用户代理控制和必要性等例外；AAA 的 `2.5.5` 通常为至少 `44×44` CSS px，也有自己的例外。
10. **间距例外不等于“相隔 `8px`”**：`2.5.8` 的间距例外有具体的 `24px` 直径圆判定。
11. **平台单位不要直接等同于 CSS px**：Apple 常用 `44×44pt`，Material 常用 `48×48dp`。
12. **扩大热区后别互相重叠**：删除与编辑挨得太近，即使各自够大，也可能造成误操作。
13. **播报先分等级**：保存成功可用 `role="status"`，通常以礼貌方式播报；急需关注的错误可以考虑 `role="alert"`；不是所有错误都应该打断读屏，列表连续更新也不该每条都播。
14. **直播区域先在页面上准备好，再更新其内容**，有利于可靠播报；避免同时重复设置多套直播语义造成重复朗读；消息里若有操作，不要只依赖一闪而过的播报，给它稳定的可见入口和合理的键盘路线。
15. **“只给读屏看”的文本用成熟的 visually-hidden 样式**：`display:none` 和 `visibility:hidden` 通常也会从无障碍树隐藏内容。
16. **强制颜色模式要单独查**：在 Windows 强制颜色模式下，背景色和阴影可能被覆盖；用 `@media (forced-colors: active)` 检查边界，用系统颜色补必要轮廓，不要无理由全局禁用系统调色。
17. **放大与重排要单独查**：`200%` 文本放大、窄视口和用户修改行距后，内容仍应可读；`1.4.10` 的常见重排检查是约 320 CSS px 宽的视口，存在二维布局等例外，水平表格可以另行处理，但不能让整个表单横向溢出。

## 二、做完的标准

- [ ] 每个执行动作是 `<button>`、每个跳转是带 `href` 的 `<a>`；用了 `role="button"` 的地方补齐了聚焦、Enter、Space 与禁用行为。
- [ ] 每个图标按钮都有可访问名称，且没有把已有的可见文字用 `aria-label` 覆盖成另一个说法。
- [ ] 不用鼠标走完一次「查找 → 编辑 → 保存」：Tab 顺序与任务顺序一致，没有正数 `tabindex`。
- [ ] 模态打开时焦点进入内部并留在其中，关闭后回到合理位置；危险确认的初始焦点不在危险按钮上。
- [ ] 焦点环在每类实际背景上都可见（浅底、透明底或图片上各看一次），且没有被自己创建的内容完全遮住。
- [ ] 每个触控目标按等级核对：AA 至少 `24×24` CSS px（或用间距例外并通过 `24px` 直径圆判定），AAA 至少 `44×44` CSS px；图标视觉尺寸（示例 `20px`）与热区分开记。
- [ ] 保存成功与错误各触发一次，读屏各听到一次、没有重复朗读；列表连续更新时不逐条播报。
- [ ] 强制颜色模式走一遍，`200%` 放大与 `320 CSS px` 宽视口各走一遍，表单不横向溢出。
- [ ] 自动扫描之后，用实际读屏器再听一次名称、状态和错误。

## 三、依据与数值

- **标准要求**：`2.4.7` 焦点可见、`2.4.11` 焦点不被作者内容完全遮挡、`2.4.13` 焦点外观（含面积与聚焦前后至少 `3:1` 的变化）、`2.5.8` AA 热区（至少 `24×24` CSS px）、`2.5.5` AAA 热区（至少 `44×44` CSS px）、`1.4.10` 重排（约 320 CSS px 宽视口）——均为 WCAG 2.2 门槛，各有例外，完整适用条件见原文。
- **平台约定**：Apple 常用 `44×44pt`、Material 常用 `48×48dp`，不要直接等同于 CSS px；`2.5.8` 的间距例外用 `24px` 直径圆判定，不能简化为“相隔 `8px`”。
- **示例值**：第四节的 `3px` 焦点环、`outline-offset: 3px`、`20px` 图标尺寸都是示例，按实际背景与品牌调整；`2–40 个字符` 这类字段文案是项目示例，真实规则按接口定。

## 四、控件、表格与示例

一个图标按钮、一个带说明的输入框：

```html
<button type="button" aria-label="关闭项目详情">
  <svg aria-hidden="true" focusable="false"><!-- 图标 --></svg>
</button>
<label for="project-name">项目名称</label>
<input id="project-name" aria-describedby="name-help">
<p id="name-help">2–40 个字符</p>
```

焦点环示例，仍需在实际背景上检查：

```css
:focus-visible {
  outline: 3px solid var(--focus-ring, #005fcc);
  outline-offset: 3px;
}
```

热区与图标尺寸分开设置：

```css
.icon-button {
  inline-size: 44px;
  block-size: 44px;
  display: inline-grid;
  place-items: center;
}
.icon-button svg { inline-size: 20px; block-size: 20px; }
```

先准备区域，再更新内容：

```html
<div role="status" id="save-status"></div>
```

## 五、失败长相与边界

- **用鼠标走完很顺，不用鼠标就卡在自绘下拉框** → 页面视觉完整但交互没完成：查该控件是不是原生 `<button>` / `<a>`，复合控件有没有遵循对应模式。
- **`aria-expanded` 写了，菜单还是不展开** → ARIA 不实现交互，行为要自己写。
- **模态关闭后 Tab 还能走到背景里，或焦点丢回页首** → 焦点没有合理返回，背景没有真正失活。
- **焦点环加了却看不出来** → 被自己创建的内容遮住，或在那个实际背景上对比不足。
- **删除与编辑按钮各 44px 仍误触** → 热区互相重叠，即使各自够大。
- **保存成功的消息读屏没听到，或者同一句话读两遍** → 直播区域没有先准备好，或同时设了多套直播语义。
- **`display:none` 藏“只给读屏看”的文字** → 内容从无障碍树一起消失，改用 visually-hidden 样式。
- **强制颜色模式下按钮没边界** → 背景色与阴影被覆盖，需要用系统颜色补轮廓，而不是全局关掉系统调色。
- **边界**：`1.4.10` 的重排检查存在二维布局等例外，水平表格可以另行处理，但整个表单不能横向溢出；自动扫描可以发现缺少 Label 等问题，却不能证明任务顺序合理，也不能证明模态焦点已经处理正确；`role="status"` 与 `role="alert"` 是播报等级，不是“都必须播”的要求。
