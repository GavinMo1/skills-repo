# 证据、发布状态与清场

**读取时机：** 见 [SKILL.md](../SKILL.md) 第四节第 2 步与第二节清场门禁；本文件不重复触发条件。

发布与清场是两种任务；非发布任务不要求合并或部署。

## 结论与最低证据

| 结论 | 需要的证据 |
|---|---|
| 本地文档链接有效 | 对应路径、目标内容；有锚点时核对锚点 |
| 远端链接可用 | 获准访问时的实际响应；未访问则标未核实 |
| 规则已同源并生效 | 目标或导入关系，以及环境的加载依据 |
| 代码实现了某行为 | 目标版本代码、配置和相关证据；不能据此推断线上行为 |
| PR 已合并 | 实际合并状态和对应提交 |
| 已部署 | 部署记录或版本标记对应目标版本，相关服务状态正常 |
| 用户访问到新版本 | 真实用户入口的响应；必要时核对源站、缓存和异步进程 |
| 可删除某个对象 | 对象身份、用途、引用、唯一改动与恢复条件已核对，且授权条件满足 |

记忆、提交说明和历史文档用于定位，不能单独证明当前部署状态。文档描述与代码不一致时，先确认目标版本和外部合同；不要自动将代码视为正确实现。

## 差异记录

对影响用户行动的每条差异，记录：

```text
topic: 事实主题及适用版本
source: 依据及核对时间（状态会变化时）
surfaces: 代码、运行态、文档或其他受影响位置
status: verified-current | changed-and-verified | pending | out-of-scope | not-applicable
access: 只读 | 获准编辑 | 机器生成只读
action: 修改动作，或未修改的理由
verification: 实际完成的检查及剩余限制
```

状态含义以 [SKILL.md](../SKILL.md#五事实面与状态) 为准。读写权限不代替事实状态。用户无需收到全量矩阵，但必须知道影响结论的未完成项。

## 发布检查

只有发布请求或生效规则要求时，核对本次适用的阶段：

实现 → 本地检查 → 推送或 PR → 必需检查 → 合并 → 部署 → 用户入口核实 → 知识同步。

不同项目可以采用不同流程。记录实际到达的阶段和未完成项，不强迫无 PR 项目创建 PR，也不强迫本地项目部署。此清单不授权执行推送、合并或上线。

对缓存、索引、异步任务或多个客户端，先明确哪些用户路径受影响。按本次范围核对源站、真实入口及相关进程。临时绕过缓存的 URL 只能用于诊断，不能单独证明普通用户已看到更新。

## 清场顺序

本节是清场执行顺序的唯一出处。门禁句（先完成知识核对、汇报、取得对象明确的确认，才可删除）在 [SKILL.md](../SKILL.md#二权限与边界)，此处不重复。执行时按下列顺序核对：

1. 列出候选对象的准确路径或标识、用途和删除理由。
2. 检查引用、未提交文件、未推送提交、唯一改动，以及未跟踪或忽略的必要文件。可恢复快照也可能不含忽略文件，不能据此跳过检查。
3. 如果该对象属于发布任务，核对本次变更已按项目要求集成并部署；非发布任务核对其工作成果已保留即可。
4. 完成相关知识同步，记录项目实际要求的凭证，不额外发明格式。
5. 汇报结果和候选，保留现场，按 [SKILL.md](../SKILL.md#二权限与边界) 的门禁取得确认。
6. 删除前复核实际目标。若路径、内容或唯一改动状态发生变化，暂停受影响删除。Windows 下确认解析后的绝对路径仍在授权范围，避免通过另一个 shell 拼接删除。
7. 只删除明确授权对象。若部分失败，记录实际成功和失败项，不扩大删除范围。
8. 检查应保留的成果仍存在，补充报告清场结果。

目录名、年龄、会话关闭和 Git 干净都不能独立证明对象可删除。分支清理还需确认它不是他人仍在使用的工作入口。

## 失败处理

- 证据缺失：保留 pending，列出缺少的依据和下一步。
- 命令失败：检查工具、环境、参数及前置条件；没有新依据时不重复同一命令。
- 检查要求有格式化凭证：按已有要求修复，不降低门禁或伪造通过。
- 发布过程中失败：报告当前实际版本和失败阶段；恢复动作按项目规则和既有授权处理。
- 清场失败：保留尚未处理对象，报告结果；不以“全部干净”概括部分成功。
