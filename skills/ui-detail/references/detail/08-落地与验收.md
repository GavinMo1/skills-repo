# 08 · 落地：一套 Token 与一次完整验收

> **适用**：要把前几篇的判断在项目里统一成一套变量，并用同一条真实路径（含保存失败、慢网重复提交、明暗切换）做一次完整交付验收时。
> **本轮不可交付时**：若这一轮还在推敲某个组件内部的交互细节、不到统一约定与整体验收，停下并说明「未到验收」，改读对应的组件篇（[09](09-输入框的手感.md)–[17](17-拖拽与排序.md)），不要用本篇清单代替动手。
> **读完能判定**：哪些重复决策该收进原始值、语义值或组件 Token；一个组件的行为是否写清到足以验收；一次交付检查是否覆盖加载、无结果、键盘、校验错误、慢网重复提交、保存失败重试、未保存关闭、主题切换、窄屏放大与读屏器；「已保存」指哪一次请求的快照；一条验收结论该记成哪一类、记录里缺哪些条件。

[系列目录](../../README.md) · 上一篇：[无障碍](07-无障碍.md) · 组件篇入口：[输入框的手感](09-输入框的手感.md)

前面讨论了很多判断，落到项目里不该变成每个开发者随手记一组数字。先把重复决策收进变量，再用同一个真实任务检查组件之间能否配合。

## 先建立小而明确的 Token

以下用于普通 Web 应用起步，不是完整设计系统。原始值提供材料，语义值描述用途；只有组件确实需要独立变化时，再引入组件 Token。

```css
:root {
  --space-1: .25rem;
  --space-2: .5rem;
  --space-3: .75rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
  --space-8: 2rem;
  --font-body: 1rem;
  --line-body: 1.6;
  --radius-control: .5rem;
  --radius-panel: .75rem;
  --motion-fast: 140ms;
  --motion-panel: 220ms;
  --ease-standard: cubic-bezier(.2, 0, 0, 1);
  --z-sticky: 10;
  --z-overlay: 100;
  --z-feedback: 200;
}

/* 默认浅色；data-theme 表示用户的显式选择。 */
:root {
  color-scheme: light;
  --surface-page: #f6f7f9;
  --surface-panel: #ffffff;
  --text-primary: #1f1f1f;
  --text-secondary: #595959;
  --border-subtle: #e2e2e2;
  --border-control: #767676;
  --focus-ring: #005fcc;
}
@media (prefers-color-scheme: dark) {
  :root:not([data-theme]) {
    color-scheme: dark;
    --surface-page: #121212;
    --surface-panel: #1f1f1f;
    --text-primary: #e0e0e0;
    --text-secondary: #b0b0b0;
    --border-subtle: #3f3f3f;
    --border-control: #8c8c8c;
    --focus-ring: #8ab4ff;
  }
}
:root[data-theme="dark"] {
  color-scheme: dark;
  --surface-page: #121212;
  --surface-panel: #1f1f1f;
  --text-primary: #e0e0e0;
  --text-secondary: #b0b0b0;
  --border-subtle: #3f3f3f;
  --border-control: #8c8c8c;
  --focus-ring: #8ab4ff;
}
@media (prefers-reduced-motion: reduce) {
  :root { --motion-fast: 0ms; --motion-panel: 0ms; }
}
.panel {
  padding: var(--space-6);
  border-radius: var(--radius-panel);
  background: var(--surface-panel);
  color: var(--text-primary);
}
```

`data-theme="light"` 使用默认浅色值，移除该属性即恢复跟随系统。两份深色映射为了让原生 CSS 示例容易直接理解而重复；实际项目可用构建工具生成，避免漏改。

语义变量的名字表达约束：`border-subtle` 是装饰线，`border-control` 才准备承担控件识别。不要为了少建变量让两者混用。层级变量只约定普通页面中的顺序，不能跨越层叠上下文和浏览器 top layer 的限制。

## 为一个组件写清行为

“使用标准 Dialog”还不够。以编辑项目为例，至少记录：

| 项目 | 本例约定 |
|---|---|
| 打开 | 从项目操作按钮进入，初始焦点在名称字段 |
| 模式 | 模态，背景不可交互 |
| 提交 | 前端校验通过后请求服务端，保存中防重复提交 |
| 错误 | 保留输入；字段错误就近显示，系统错误在表单内展示 |
| 关闭 | 关闭按钮或 Esc；有改动时确认是否放弃；遮罩不关闭 |
| 返回焦点 | 回到原项目操作按钮；对象消失时回到合理的列表位置 |
| 小屏 | 单列布局，内容区可滚动，操作区域不遮挡聚焦字段 |

这样的约定能指导实现和验收，也能让需求变更有具体讨论对象。

## 用同一条路径做交付检查

准备短标题、超长标题、空项目、无权限项目、失败响应和大量列表数据，再走下面这条路径。本节清单与 `stage/06-自查清单.md` 同源，两处有出入时以 06 为准。

- [ ] 进入项目列表：加载与失败有区别，图片和字体加载时无明显意外跳动。
- [ ] 搜索不存在的名称：提示无结果，可清除筛选，输入没有丢失。
- [ ] 仅用键盘打开项目：名称清楚、焦点可见，顺序符合任务。
- [ ] 编辑并制造校验错误：错误有文字说明、能定位，修正后及时更新。
- [ ] 打开日期选择器：子浮层可操作，关闭后焦点回到正确位置。
- [ ] 慢网下连续提交：立即显示保存状态，没有重复创建。
- [ ] 保存失败再重试：保留输入，说明影响，恢复后可继续。
- [ ] 有未保存修改时关闭：不会因误点丢失内容，放弃后焦点合理返回。
- [ ] 切换明暗主题：文字、控件、焦点与状态的必要对比均检查，图片没有被无差别改色。
- [ ] 窄屏、放大与长文案：主要内容可重排，重要文本和操作不被裁掉。
- [ ] 放大到 200%、1x 与 2x DPR：图标、按钮文字、圆形与斜角元素没有肉眼可辨的偏移，圆角嵌套处厚薄均匀。
- [ ] 减少动效与强制颜色模式：交互仍能完成，必要边界依然可见。
- [ ] 使用读屏器：能听懂字段名称、错误和保存结果，没有重复或过量播报。

截图适合检查间距与视觉层次，键盘适合检查焦点路线，读屏器适合检查名称和动态反馈，浏览器工具适合检查性能与对比度。它们回答的问题不同，需要一起使用。

## 组件细节也要走一遍

下面对应第 03 篇的视觉对齐，以及第 09–13 篇。除非项目采用了相关组件或增强，不必为未使用的模式增加实现；采用之后，要按真实行为验证。

| 对象 | 操作与条件 | 检查结果 |
|---|---|---|
| 排版与视觉对齐 | 放大 200%、1x 与 2x DPR、中英混排、圆形与三角图标、描边与阴影并排 | 同一区块收敛到少数几条对齐线，墨迹也齐；偏移有注释可依，热区与焦点环没有因此缩小 |
| 输入框 | 聚焦、失焦、切换错误态 | 边框变化不挤文字，焦点即时可辨，错误不遮挡内容 |
| 输入框 | 有初始值、自动填充、长标签、放大文字 | 标签不覆盖内容，名称与值都可读 |
| 输入框 | 中间插入、选中替换、粘贴、撤销、中文选词 | 字与光标跟手，不丢选区，Enter 不误提交 |
| 搜索 | 快速输入、组合输入、清空、旧请求晚返回 | 输入立即更新，旧结果不覆盖新查询，失败不伪装成无结果 |
| 多行输入 | 粘贴长文、删除、达到最大高度 | 高度与滚动合理，当前编辑位置可见 |
| 平滑光标（若启用） | 高频输入、跨行、选区、IME、字体与宽度变化、内部滚动 | 装饰光标跟随真实插入点，不排队追赶；测量失效立即恢复原生表现 |
| 平滑光标（若启用） | 首次聚焦、失焦、空闲、减少动效、强制颜色模式 | 不从原点滑入，输入时无额外闪断，空闲与降级行为明确；测量成本有性能记录支持 |
| 按钮 | 慢请求、快速连续激活、不同长度文案 | 尺寸稳定、状态有说明、焦点合理、无重复业务操作 |
| 选择器 | 键盘选项、触屏滚动、点选、Esc、Tab | 不因失焦吞掉选择，不误选，退出路线明确 |
| 数据列表 | 排序、跨页选择、筛选、删除、详情返回 | 选择按对象保存，范围明确，分页、滚动与焦点按约定恢复 |
| 浮层 | 进入中关闭、离开中打开、嵌套、零动效 | 生命周期不被旧回调破坏，关闭内容不再可聚焦 |
| 浮层 | 滚动、缩放、长内容、软键盘 | 定位跟随、避让边缘，背景与内部滚动各自正确 |

动效的毫秒数不是验收结论。观察短过渡是否帮助识别变化、有无打断输入、有无增加等待，并在减少动效模式下重复关键任务。以上是人工检查路径，不能代替真实设备验证。

## 一个完整案例：保存失败后继续编辑

**问题**：用户保存 A 后继续输入 B。若把“任何请求成功”都当成“当前内容已保存”，B 就会被错误标记安全。另一个常见问题是保存失败后清空输入，迫使用户重填。

**行为约定**：提交时固定本次内容快照；在途只允许一个请求，但输入保持可编辑；失败保留内容；成功只确认请求快照；当前内容与已确认内容不同，就继续提示未保存。按钮不因“保存中”改动尺寸，焦点不被结果提示抢走。

准备一个可控的模拟请求（能强制失败、能延迟返回），从默认状态开始：

| 操作 | 通过表现 | 出现以下情况就失败 |
|---|---|---|
| 将名称改为 A，让下一次请求失败，保存后在名称框按 Enter | 在途期间请求数仍为 1 | 重复发出请求，或清空表单 |
| 等待模拟请求结束 | 显示失败，A 仍在；可重新保存 | 没有错误说明，或按钮永远忙碌 |
| 再次保存 A，结束前立刻把名称改成 B | 已确认区后来变成 A；当前编辑区为 B，并明确仍未保存 | 把 B 标为已保存，或用 A 覆盖 B |
| 再保存 B | 当前与确认内容一致，显示当前内容已保存 | 仍确认旧值或丢失本次编辑 |

**如何取证**：保留操作记录中每次请求的版本与结果，连同最终两份内容、状态文字和请求数一起记录；截图展示当前状态，日志解释它怎样形成。观察焦点是否仍在用户最后操作的位置，不因收到回包而跳到页首。

这条路径要在真实浏览器里实际走过一遍：首次失败、在途防重、A 保存时继续编辑 B、旧回包保留 B 未保存状态；检查范围就是上面这张表。模拟请求不涉及真实服务端，因此不能据此宣称生产幂等、离线恢复和版本冲突已通过。

## 如何记录验证结果

别只写“已测”。记录浏览器、设备或视口、主题、数据条件、操作、预期、实际。例如：“Windows / Chrome / 深色 / 键盘操作，Esc 关闭日期面板后焦点回到日期输入；通过。”失败时补复现步骤和影响。

标准类结论引用成功准则；平台类参数记录设计系统与版本；经验类数值记录采用理由。以后从 220ms 调到 180ms 时，团队才能知道改变的是项目取舍，而不是违反了某条不存在的规范。
