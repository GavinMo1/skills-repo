# 04 · 状态与动效

> **适用**：要交代每个异步动作的状态、区分空与失败、给动效定时长并降级、处理浮层生命周期，或用测量而不是感觉判断性能时。
> **本轮不可交付时**：若浮层容器还没选，停下并说明「容器未定，先定骨架」，改读 [01-结构与排版](01-结构与排版.md)；若这一轮只调单个控件的手感，改读 [02-控件与交互](02-控件与交互.md)。
> **读完能判定**：这一轮缺哪个状态；反馈强度是否匹配等待长度；空/无结果/无权限/失败/部分失败是否被混用；动效是否只服务理解、减少动效下是否仍可操作；浮层五阶段与外部关闭判定；性能结论是否有依据。

用户要能看见三件事：现在在等什么、为什么失败、接下来做什么。动画只服务于这个理解，不能替代它。

细则与理由：[06 状态、动效与性能](../detail/06-状态动效与性能.md)、[01 浮层的反馈形式](../detail/01-浮层.md)、[12 浮层的开合与定位](../detail/12-浮层的开合与定位.md)。

## 每个异步动作先画状态

- 默认 → 进行中 → 成功 / 失败 →（重试 | 修正）→ 回到进行中。缺哪个状态，就是缺哪段界面。
- 进行中立即反馈并阻止本页重复提交；超时不等于服务端没保存，付款与创建记录需要幂等或结果查询。
- 按感知区间选反馈强度：很快返回 → 只留按压反馈，不必闪加载图；短请求 → 按钮内 Loading 或局部状态，不用整页遮罩；首次加载 → 有结构依据的 Skeleton；长任务 → 进度 + 取消 + 后台执行 + 结果入口。
- 不知道总量用不确定进度，绝不编造百分比。上传完成后的解析阶段要单独说明。
- Skeleton 表达结构并占位，不会自动消除 CLS；图片尺寸、字体替换、异步插入内容仍会造成跳动。

## 六张不同的脸：空、无结果、无权限、失败、部分失败、离线

| 状态 | 文案必须给出 | 下一步 |
|---|---|---|
| 首次为空 | 还没有项目 | 创建项目 |
| 搜索无结果 | 没有找到"官网"相关项目 | 清除筛选 |
| 无权限 | 你没有此项目的访问权限 | 申请权限或联系负责人 |
| 加载失败 | 项目列表未能加载 | 重试 |
| 部分失败 | 成员列表暂时不可用 | 只重试该区域 |
| 离线 | 当前离线，显示上次同步内容与时间 | 恢复后同步 |

- 通用话术"出错了，请重试"不合格：必须写发生什么、影响什么、如何恢复。简短道歉符合语气，但不能替代这三项。
- 禁用动作的原因就近展示，不藏在不可聚焦的 Tooltip 里。
- 乐观更新只用于低风险、高成功率、可回滚的操作；失败要恢复并解释，且不覆盖用户等待期间的新改动。

## 动效

- 时长起点：颜色与按压 100–150ms、小面板 150–220ms、抽屉与对话框 200–320ms。进入用减速曲线，离开可更快。
- 动画只表达变化的来源与去向。先保证无动画时可正确操作，再加过渡。
- `prefers-reduced-motion: reduce` 下保留必要状态信息：关闭位移动画后开合仍清楚，进度与错误不随装饰动画消失。
- 不用逐项播放的入场动画拖住长列表；多元素错开只为表达顺序。
- 不用"超过 400ms 就卡"这类统一判断；距离、尺寸、设备与直接操作都会改变合适时长。
- 性能说法要有记录：`transform` 动画在合适条件下可能交给合成线程，但测量、缓存失效、坐标计算与 DOM 更新仍有成本。

## 浮层生命周期（开合与定位）

- 五个阶段：关闭 → 进入中 → 打开 → 离开中 → 关闭。焦点、背景阻断、可访问性、DOM 挂载不必同一刻切换。
- 进入中内容即可用，不等待整段动画结束才响应键盘。
- 新意图取代旧过渡：进入中按 Esc、离开中重新打开，旧回调不得卸载新浮层。
- 用 `transitionend` 收尾要过滤 target 与 property，并处理零时长、被取消、元素提前移除；减少动效时生命周期照常完成。
- 离场动画不延迟业务结果（保存成功不必等抽屉滑走才更新列表）。
- 关闭时先把焦点移到安全位置，再让旧内容失去交互能力；`aria-hidden` 不能加在仍含焦点的区域，`pointer-events: none` 不阻止键盘聚焦。
- 定位要持续更新：锚点在视口与滚动容器中的位置、面板实际尺寸、边缘翻转或平移、异步内容增长、字体变化、窗口缩放、锚点被移除。
- `getBoundingClientRect()` 是视口坐标；祖先 `transform` 会改变固定定位的包含块。不要只在首次打开时测一次，之后假设不变。
- 面板翻到上方后动画原点要跟着走，避免从错误方向长出来。
- 移动端软键盘：用 Visual Viewport 处理定位，`100dvh` 不等于键盘上方高度；底部面板留安全区，长内容内部滚动，主按钮不盖最后几个字段。
- 滚动锁要补偿滚动条宽度（`scrollbar-gutter: stable` 或等量 padding），并检查固定导航是否一起偏移；嵌套浮层关闭不得提前解除外层锁。
- Esc 由最上层、当前相关的浮层处理一次；不在应用各处拦截。
- 外部关闭识别整次手势：指针在外部按下、在外部松开、未被判为拖动/滚动/取消，才作为候选；记录 `pointerId`、处理 `pointercancel`。
- 不在 `pointerdown` 就卸载浮层（后续事件会打到背景造成误触）。
- 子浮层（对话框里的日期面板）不得被外层判为"点击外部"；Portal 后 DOM 祖先关系与视觉从属关系不同，外部判断要纳入所属浮层。

## 性能

- 参考线：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1，按移动与桌面分别看第 75 百分位。本地一次测试不能证明真实用户达标。
- 预留图片尺寸，首屏大图不懒加载，按需拆包；`font-display: swap` 要匹配后备字体度量，`optional` 是另一种取舍。
- 长列表虚拟化要同时检查键盘导航、浏览器查找与读屏，不能只看行数。
- `getBoundingClientRect()` 紧跟 DOM 写入可能触发同步布局，但看到函数名不等于每次都发生了强制布局——实测。
- 不给所有输入框永久加 `will-change`；额外图层也消耗资源，按真实瓶颈决定。
- 没有测量记录就写"未测量"，不虚构性能收益，也不把两次 rAF 间隔冒充 INP。
