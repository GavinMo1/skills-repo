# 写作与自检

撰写者开始写作前读取。初稿完成后检查下列适用项并直接修改；必要检查完成且没有新的实质发现时结束；缺证或资源不足的遗留问题随稿提交。自检不代替独立评审。

## 内容与解释

- 对照章节职责，确认核心问题已回答，读者目标所需的依据、机制、边界和例子已覆盖。
- 根据内容选择解释方法：机制展示因果过程；操作解释前提、步骤、结果和失败条件；比较说明维度与权衡；理论展示推理；历史主题区分记录与解释。不强套统一段落结构。
- 对影响判断或操作的事实，按 [资料与证据规则](research-protocol.md) 核对来源。说明推断、简化与未知。
- 深度取决于解释是否足以支持理解、判断或行动，不取决于篇幅、术语量或代码数量。

## 中文表达

- 同一概念使用一致术语；首次出现且目标读者不熟悉时解释。缩写需要时展开，保留有意义的领域区分。
- 明确动作、对象和适用条件。拆开存在歧义或同时承担多项要求的句子，不机械限制自然叙述的句长。
- 删除不推进理解的套话和重复，保留必要推导、对照、例外与限制。
- 结论适合先给时先给结论；需要铺垫才能理解时按推理顺序展开。主动语态和第二人称用于帮助理解，不设为统一句式。
- 文件名序号用于排序，正文标题不重复序号。标题表达实际问题或内容，层级反映逻辑关系。

## 示例与表现形式

- 代码只在帮助理解或操作时使用。邻近文字或注释解释用途、关键逻辑、适用环境和限制，不要求代码块前后重复解释。
- 示例输入、输出和结论相互一致；区分真实结果与预期结果，注明未执行的代码。
- 表格用于比较，图用于解释关系，列表用于并列或步骤。没有解释价值时用自然段，不设可视化密度。
- 使用 Mermaid 时检查代码围栏、图类型语法、节点标识和标签写法。按目标渲染器处理特殊字符与换行；不把某种图的规则推广到所有图。连线应表达真实关系，不强制所有节点从父节点引出。
- 无法渲染时检查源码并说明未验证渲染；复杂表达可改为更简单的图或文字。

## 章节关系

- 说明真正需要的前置知识。仅回顾理解本章所需的信息，链接完整解释，不要求固定句数。
- 结尾回答本章核心问题，说明必要限制。确有自然延伸时引出后续问题；末章收束系列，不制造悬念。
- 对照共享约定与已可用的相关章节，检查术语、数据、示例和依赖。无法读取的章节列为整合阶段待核对项。
- 检查未完成标记与交叉链接。原文或教学代码中的标记不等于未完成内容。

## 提交

提交章节路径、已覆盖内容、自检修改摘要、来源记录和未解决问题。不要只给自评分或声称“已完善”。
