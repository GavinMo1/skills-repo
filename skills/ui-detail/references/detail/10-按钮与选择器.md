# 10 · 按钮与选择器：动作有回应，选择不意外

> **适用**：保存按钮一转圈就变窄、连点两次建了两条、自绘下拉「点了但没选上」、Esc 关掉后值却变了，需要补从按下到完成这整段行为时。
> **本轮不可交付时**：若页面上只有同步完成的静态按钮、没有长请求、防连点或自定义选择器，停下并说明「无异步动作与自绘选择器」，回 SKILL.md 按对象重挑一篇。
> **读完能判定**：两段反馈是否都在（我收到了／任务进行到哪）；Loading 怎么不改变按钮尺寸；用原生 disabled 还是保留焦点的 aria-disabled、随之要自己拦哪些路径；主次与危险按钮怎么写、辅助按钮该不该 type=button；选择器属哪种模式、三个值何时才统一；失焦时列表能不能卸载、pointerdown 该不该 preventDefault；远程选项失败与多选删除后的焦点。

## 一、先判

1. **反馈至少有两段**：第一段是“我收到了你的操作”，例如按压颜色；第二段是“任务现在进行到这里”，例如保存中、已保存或失败。后端请求再快，也不应省略第一段；长请求也不能只靠按压颜色交代。
2. **按钮的每个状态都要有可看到的差异**（对照表见第四节）：Pending 仍可重复提交、Success / Error 转圈结束却没说成功还是失败，是最常漏的两格。
3. 颜色过渡可以先试 100–150ms（示例值）；轻微位移或缩放只在适合产品风格时使用，不要为了“有反馈”把每个工具栏按钮都做成弹簧。Hover 可以限制在支持悬停的精细指针设备上，触屏仍要有按压与结果反馈。
4. **Loading 不应改变按钮的位置**：把“保存修改”替换成一个小圆圈，按钮宽度就可能收缩 → 保留文字并在预留的图标槽内展示 Loading，或用布局让原文案继续占位；不要只按中文四个字硬编码宽度，多语言会暴露问题。
5. 加载图标通常可设为装饰，由按钮文字或旁边的状态区域说明“保存中”；如果隐藏原文字，按钮仍需要明确的可访问名称。减少动效时可以用静态进度图标加文字，不能让唯一的忙碌提示一起消失。
6. **选原生 `disabled` 还是保留焦点的 `aria-disabled`**：原生禁用会影响 Tab 顺序；`aria-disabled` 则需要自行阻止鼠标、键盘和提交路径。无论选哪一种，都要给出忙碌原因与完成反馈，并验证激活按钮后焦点是否仍处在合理位置。
7. **防连点只保护当前页面**：服务端幂等才保护重复请求，取消请求也不一定撤销已经执行的业务；刷新、双标签页和超时重试仍需要业务侧处理。
8. 主次关系表达任务优先级，不是每个区块都放一个鲜亮的主按钮；危险按钮应明确写对象和动作，确认对话中不要靠颜色区分“保留”和“删除”。
9. 表单里的辅助按钮，例如显示密码、清空、增加一项，通常应设 `type="button"`，避免意外提交；主提交使用表单的标准提交路径，保证点击按钮与适用的 Enter 提交行为一致，并处理中文输入法组合状态。
10. 图标加文字时让整个按钮成为一个热区，不要把图标和文案拆成两个可聚焦元素；Split button 则有两个不同动作，应有两个可辨识的入口和名称。
11. **原生 Select 能满足需求时，优先保留它已有的平台交互**；做自定义选择器，先决定是只选已有项、输入筛选、允许自由输入，还是多选——这些模式会影响键盘行为、输入值与选中值的关系。
12. **三个值可以不同**（见第四节示例）：输入查询是“李”，当前高亮建议是“李四”，已选负责人仍是“张三”。“方向键高亮了李四”不一定意味着负责人已经改成李四。应明确何时提交选中值、Esc 关闭后保留什么、失焦时未完成查询如何处理，不能由某个动画结束事件决定。
13. **可编辑 Combobox 按对应 APG 模式约定**：输入时筛选，方向键移动活动项，Enter 接受当前项，Esc 关闭建议；Tab 继续正常焦点路线，不强迫用户逐项 Tab 穿过所有候选。不同选择器变体存在差异，应按采用的模式完整实现。
14. 使用 `aria-activedescendant` 的模式中，DOM 焦点可能仍在输入框，活动项通过属性关联，并且需要存在于 DOM 并滚动可见；不要同时把每个选项做成独立焦点，再混用另一套焦点模型。
15. **输入框一失焦就卸载列表 = “按了但没选上”**：选项的点击事件还没执行，目标就消失了 → 把触发器与列表看作同一交互区域，协调内部焦点移动、指针选择与外部关闭。粗暴禁止所有 `pointerdown` 默认行为也可能破坏触屏滚动或焦点，不宜作为通用补丁。
16. 建议列表出现可使用短暂透明度或轻微位移过渡，但初次方向键导航不应等待动画；活动项、已选项、悬停项要能区分，不要只靠很接近的灰色。
17. **远程选择器要区分未输入、加载中、无匹配和请求失败**：请求失败不能显示“没有这个人”，否则用户会误以为数据不存在。
18. 多选标签增长时应让输入位置仍然可见；每个删除按钮有对象名称，如“移除张三”；Backspace 的删除规则要明确，不能在用户输入查询时误删已有选择；删除当前聚焦标签后，应把焦点交给相邻标签或输入框。
19. 禁用选项要说明原因，长名称要有完整阅读方式；大量选项如果虚拟化，需同步处理活动项挂载、滚动与读屏，不能只把普通列表套进虚拟滚动就认为完成。

## 二、做完的标准

- [ ] 慢网保存一次：按钮尺寸稳定、只提交一次、结束后明确告诉成功还是失败。
- [ ] 用键盘输入中文、选负责人、关闭再打开，确认当前值仍在；按 Esc 不误提交。
- [ ] 点击列表滚动条不关闭；触屏滚动候选不误选。
- [ ] 远程请求失败时可重试，且失败态与“无匹配”在界面上能区分开。
- [ ] 选择器归属的四种模式（只选已有项 / 输入筛选 / 自由输入 / 多选）写明了是哪一种，并按该模式验过键位。
- [ ] 忙碌态用的是 `disabled` 还是 `aria-disabled` 写明了理由，激活后的焦点位置验过。

## 三、依据与数值

- `100–150ms` 的颜色过渡是示例值（项目起点），不是标准要求；具体时长按产品风格定。
- 原生 `disabled` 会影响 Tab 顺序、`aria-disabled` 不改焦点但需自己拦全部激活路径：这是平台约定，两者不能互相当作等价开关。
- 可编辑 Combobox 的键位（Enter 接受当前项、Esc 关闭建议、Tab 走正常焦点路线）按 APG 模式约定；不同变体之间的差异要按所选模式补齐，不是标准里的可裁项。

## 四、控件、表格与示例

| 状态 | 应当明确 | 容易遗漏的地方 |
|---|---|---|
| 默认 | 将执行什么 | 文案只写“确定” |
| Hover | 可操作 | 只有悬停才出现关键动作 |
| Pressed | 正在按下 | 缩放让小按钮文字发糊 |
| Focus | 键盘操作位置 | 把焦点外圈当成悬停效果 |
| Pending | 操作正在处理 | 按钮变宽变窄、仍可重复提交 |
| Success / Error | 结果和下一步 | 转圈结束了，却没说成功还是失败 |

三个值分别是谁：

```text
已选负责人：张三
输入查询：李
当前高亮建议：李四
```

## 五、失败长相与边界

- **保存按钮转圈后变窄，旁边的取消按钮跳了一下** → Loading 用替换文字实现，宽度随内容收缩；改成预留图标槽。
- **连点两次建了两条** → 只有客户端防连点，没把服务端幂等当第二道。
- **自绘下拉“点了但没选上”（列表刚展开就关了）** → 输入框失焦就卸载列表，选项的点击还没执行；或粗暴禁止了所有 `pointerdown`，把触屏滚动也一起弄坏。
- **Esc 关掉后值却变了** → 选中值的提交时机由动画结束事件决定，而不是一条明确规则。
- **忙碌提示只剩一个转圈，读屏听不到“保存中”** → 加载图标被当纯装饰，也没有旁边的状态文字。
- **边界**：原生 Select 能做的事不要重写；`aria-disabled` 只是状态语义，点击、键盘与提交要自己拦；禁用选项的“原因”不能只靠 Tooltip；多选删除后的焦点不能落回文档开头；输入法组合、防抖与请求乱序的处理见 [09-输入框的手感](09-输入框的手感.md)。
