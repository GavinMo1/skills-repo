# 评审协议：快照、记录与工具恢复

冻结或派发时读“版本与快照”和“派发材料”。真正开跑前读“派发实施材料”。核实脚本／命令／工具类前提的运行时行为时读“可执行前提的隔离实跑”。需要审计、换人或故障恢复时读对应章节。路线选择、轮次和通过条件以 [SKILL.md](../SKILL.md) 为准。

## 版本与快照

为冻结正文指定唯一版本号，例如 v1、v2。版本与轮次分开记录：补路或换人不自动产生新正文版本。

将完整正文保存为冻结副本，或写入派发消息。将状态和评审记录与正文分开，不强制使用特殊标记。同一轮各路收到相同内容。如果派发消息引用可编辑的共享文件，另保留一份本轮不再修改的副本。在全部结果返回前，不覆盖正文。

影响行为、约束、前提、步骤或验收的修改必须新建版本。仅排版或错字修复可注明差异，但必须确认技术含义不变。用户中途改要求时保留已评版本，新要求进入下一版本，不混用不同版本的通过结论。

**实质修改**：影响行为、约束、前提、步骤或验收的修改，必须保存新版本并复评，交付前核对正文与最后被评版本一致。不改技术含义的**契约精度修订**（消歧、修引用与常量自洽、收紧断言）仍升版本、按普通复评处理，不设快速通道；操作性判据：改动若让某个既有断言从红变绿，或改变了任何默认值、阈值、拒绝条件，就按实质修改处理。两者都新建版本并重算哈希。

**逐轮存档**按项目约定执行。项目内明文写出、能指出**路径与行号**的落盘规则（`AGENTS.md`、`README.md`、`docs/CONVENTIONS.md` 等）即项目约定；指不出路径与行号的，按无约定处理。无约定时：

- 落在 `plans/<主题短名>/`，目录名用小写连字符；文件名前缀在同目录内首次确定后固定不变，默认等于主题短名。
- **本层每版落两份**：`<前缀>-v<版本>.md`（开工方案，读者是执行 Agent）与 `<前缀>-v<版本>-record.md`（评审记录，读者是主会话与用户）；记录每版一份，产出后不再修改。
- `archive/` 存此前每一版正文，**每产出一版新的就立刻把上一版移进去**。
- 版本号写在正文里，记录文件名用产生它的那一版，被评版本写在记录首行标题。**把文件名当版本号会系统性错位一版**。
- 用户要求不落盘或只要对话稿时，本节不适用，按[主文件](../SKILL.md)第 5 节「三条简化口径」处理。

两份的必备栏目见[主文件](../SKILL.md)第 1 节，本协议不复述。

## 审计快照与哈希

涉及多文件、异步交接或明确审计要求时增加 SHA256。用户要求不落盘时，使用完整对话快照，并写明未生成文件哈希。不得为满足本协议而违规写文件。

单文件可用各占一行的 `<!-- plan:start -->`、`<!-- plan:end -->` 分隔正文与记录。若使用标记，各出现一次且顺序正确。对标记行之间的正文计算哈希：CRLF 或 CR 统一为 LF，以 UTF-8 无 BOM 编码，不额外去除空白，并在记录里写明末尾换行口径。无标记时明确被哈希的正文范围，不强改已有格式。

多文件记录相对路径、版本及逐文件哈希，采用相同文本口径。向各路提供同一份清单和完整内容。将原始依据与方案文件分开记录。如果依据或环境改变，复核受影响的结论。

哈希只用于确认内容身份，不证明 Agent 已阅读或方案正确。不得只留版本号或哈希而丢失正文。

## 可执行前提的隔离实跑

**什么时候读这一节**：核心前提涉及脚本、命令、工具或配置的**运行时行为**，即 exit code、落盘字段、状态转移、报错路径、跳过分支。判据只有一句：**能不能用一条命令跑出来？能就跑；跑不通就标“待核实”，并写下那一条命令。** 只有源码锚点不算“已证实”：锚点只证明“代码这么写”，不证明“跑起来这么走”。纯静态事实（结构、契约、语义）不需要实跑。

### 建隔离环境

1. 新建临时目录（`mktemp -d`、`tempfile.mkdtemp()` 或客户端等效工具）。**不得**在被评对象目录里跑任何会写盘的命令。
2. 把被评对象的脚本连同运行所需的最小夹具复制进去：空账本、样例配置、样例输入。保持相对路径结构，脚本自带的相对引用才不会断。
3. 记录原件指纹：对原脚本及其会写入的目标目录取 SHA256（或 `git status --porcelain` 快照）。实验结束再取一次，两次一致才可写“未改动原始文件”。
4. 在记录里写下夹具内容摘要：“用一份手工伪造的 v2 账本”这类说明必须能被复核者判断代表性，不能只写“用样例数据”。

### 跑什么、记什么

- **每条前提一条能判真假的命令**，不为“摸清全貌”把全部子命令跑一遍。
- 需要覆盖整条链路时分两批：先跑只读的 check 类命令，核验现状、列出失败项。再跑会写盘的命令，例如登记、冻结、状态推进。每批都单独记 exit code。
- **证据四件**：①命令原文，可直接复制重跑。②exit code。③关键输出片段：截取含不符项的那几行，不写“成功”“正常”。④跑完后的落盘字段名清单，或状态差异（例如“落盘字段：actors／files／next_action／reviews／revision_limit”）。
- 最后一条命令若是带收尾校验的（如 `--final`），把它的 exit code 与失败项列表原样记下，这是判定的关键证据。

记录用一张表即可：

| 前提 | 命令 | exit | 关键输出／落盘差异 | 结论 |
|---|---|---|---|---|
| 前提 1：校验脚本能发现快照字段缺失 | `python scripts/check-state.py --final` | 2 | `缺少当前内容通过记录`；`unchecked: ['缺少当前内容通过记录']` | 明确不满足 |
| 前提 2：登记子命令会写入 actors 字段 | `python scripts/state.py actor ...` | 0 | 落盘字段含 `actors` | 已证实 |

### 判定与写回

- exit code 非 0、字段缺失、行为与前提不同：记“明确不满足”，并在备注里写清差在哪。**不得写“部分满足”“基本成立”“大致可用”**，这类措辞会让下游步骤带着假前提开工。
- 前提被证伪后按[主文件](../SKILL.md)「核心任务与核心前提」的两条出路处理：消除依赖，或降级为已披露残余风险并给可核查验收项。实跑证据进风险清单，不用于声称前提仍成立。
- 结论写进对应前提条目或决策登记表编号；正文只引编号与一句摘要，完整命令、输出与临时目录路径放实验记录区。
- 保留临时目录时把路径写进记录，便于复核者重跑；清理时在记录里注明已清理。

### 不得做的动作

- 不在原 skill／项目目录内跑会写盘或删文件的命令；也不为“验证一下”去改原目录里的样例数据。
- 不用读源码推断替代实跑，不用“代码里有这个 if”当作“运行时走到这一支”。
- 不为了让前提成立而调整夹具、放宽阈值或跳过收尾校验；夹具与参数如实记录。
- 无法隔离时（需真实数据、生产凭据、外部网络、不可恢复的写操作）不硬跑。此时标“待核实”，写明缺什么条件、最小验证命令、由谁在何时核实。
- 不把一次实跑结论外推到夹具未覆盖的状态（并发、异常恢复、旧版本残留）；这些仍按各自前提单独列。

## 派发材料

每路获得以下材料，并按本路职责检查：

```text
目标：用户要求、硬约束、已确认决策与授权。
职责：本路重点检查范围。
版本：轮次、冻结版本；适用时附哈希或文件清单。
方案：完整正文（含核心任务与结果验收口径、开工说明、步骤、禁区、验收、停工条件、盲区名）。
记录（决策部分）：决策登记表与取舍点清单、核心前提状态与锚点、未关闭项。
记录（评审史部分）：修订表、闭环表、沿革、各路限制——**只给复用路；扫描路不给，给了就不是盲评**。
**评审者读这两半里该给的那一半；执行 Agent 只读方案，两半都不给。见「派发实施材料」。**
原始资料：可读取的需求、实现、配置和文档入口。
复评材料：复用路附旧问题、修改说明、处置依据和影响范围；扫描路只附改动清单与改动面，不给旧意见。
输出：结论；**每条未关闭项的 ①② 取值**（成立／不成立），各附依据位置与判读依据；高/中/低计数（仅作摘要）；问题稳定ID、严重度、位置、触发条件、后果、证据及建议；旧问题处置**以闭环表给出（逐条：已关闭／部分关闭／未关闭 + 依据位置）**，这条义务归复用路；扫描路未收到旧问题时写“本路无旧问题”；未核实项、待决策项及限制。**本路不判收口、通过或部分交付**——那些由主会话按[主文件](../SKILL.md)第 4 节判，判据不复述在本协议。**不得照抄旧结论充作本轮结论**：未受影响部分可在注明原版本与覆盖范围后沿用证据，但不得原样复述已关闭条目的细节。
边界：只读评方案，不改文件、不执行拟议实现、不再派Agent，不代替用户授权。
```

派发时有五条硬要求：

1. **每路至少一个定向追问**，且必须能用具体输入构造（“请攻击：目标 busy 时投递是否会……”）。泛泛的“请评审”命中率明显更低。定向追问会收窄视野，所以最多三个，并同时写明“本路职责外的新发现同样必须报告”（复用路按[主文件](../SKILL.md)第 2 节的完成标准执行，不因这句话被要求全量扫描）。
2. **扫描路的复评消息必须写“请重新读取冻结文件全文，不要依赖你记忆中的版本”**；复用路至少读闭环表所引的位置，同样不得凭记忆。靠记忆的复评会漏掉条号漂移、常量不一致这类只有全文搜索才能发现的缺陷。
3. **复用的 Agent 不得声称盲评**。它对旧版本的记忆就是已暴露材料，记录里要写明“本路为复用评审者，已见历次版本”。
4. 复评时先给“**改动清单 + 改动面**”，再给全文。改动面是作者自报的改动量，口径见[主文件](../SKILL.md)第 3 节；评审者仍必须自行判断交界处的交叉。
5. **每条缺陷必须给证据锚点四件套**：①`文件 :: 符号名`（行号仅作提示，版本间会漂移）②该符号内的原文片段 ③**可证伪条件**，写成“若在该符号内找不到 X，则本条不成立”。④若结论依赖调用／引用／配置关系，给出足以判定该关系存在的锚点，不必穷举。要求强度按严重度分两种：**高／中问题必须齐 ①②③④**。作者的核验动作固定为“打开该锚点符号读全文，并逐个核对关系锚点”。片段只用于确认定位，**不替代阅读**：同文件相邻位置的代码完全可能推翻片段支持的结论。**低问题只需 ①③**，作者的核验动作是“看一眼锚点是否指对地方”。低问题不阻碍实施，不为它要求全文阅读与关系锚点，也不必逐条写进修订表。核验中若发现某个低问题其实会改变实施动作，就地按中问题补 ②④。**若缺陷的对象是运行时行为（exit code、落盘字段、状态转移、报错路径），锚点之外还必须附隔离实跑的命令与 exit code（见「可执行前提的隔离实跑」）；只有源码锚点的，标“方案推演”。**

替代路的**甲档**在首次启用时做一次盲评：只给候选方向所需材料，不提供当前方案；形成方向后再补共同正文与未决意见，此后复用同一评审者更新比较，不重复从零探索。**乙／丙档**不做隐藏：直接给完整正文与该决策点的候选列表。

## 复评与证据沿用

向本轮全部评审路提供新全文和修改说明。扫描路据全文判断改动影响，复用路据闭环表所引位置判断；都不只接受作者的影响判断。

对于受影响部分，检查新内容、关联前提、关键步骤之间的关系和旧问题。对于未受影响部分，可以沿用证据，但必须注明原版本、覆盖范围及仍适用的原因。

各路给出当前版本的完整检查结论，不只复制旧计数。尚未完成的首次检查不能记为证据沿用。不得缩小职责来避开本路完成标准内的新问题（两种完成标准见[主文件](../SKILL.md)第 2 节）。

为问题保留稳定 ID。关闭旧问题时说明依据；新问题另记 ID。未解决的事实或严重度争议记录双方依据、已做核实和缺少证据，不以作者裁定或反复要求重评代替解决。

**受影响落点的完整性由复评方核。** 本轮被改的每一条条文，作者给出检索命令与全部命中行，模式串必须同时含旧表述与其行为动词。作者逐行写处置，取值为改／合并／删除／指针化／声明不复述，一行一值。命中清单之外不得有未处置行。清单是否完整，由复评方用第三种相邻模式串再核一次，作者自证不算。轻评只检索被改文件所在目录。

## 最小记录

复用方案记录区或已有项目日志，不另建审批文件。**记录是决策的唯一源**：方案里引用决策只写编号，写全理由的只有这一份。读者按需读，不必通读：主会话恢复或判交付读「结论、轮次、未关闭项、偏离」，用户抽查读「结论、强度依据、未关闭项」。记录：

- **结论**：通过／部分交付／未收敛退出，加一句为什么。
- 当前版本、已完成轮次与进行中轮次；**评审强度、路数及选择依据**；`交付终点`（`只出方案`／`含实施`，旁注用户原话依据）；适用的哈希或清单；评审状态与实现状态分别记。
- **决策登记表**（四列：编号／选定实现／依据／什么证据会推翻·备选）与它的派生视图取舍点清单；替代解法的候选与被拒理由。这是"当初为什么这么定"的唯一住所。**方案里出现这类内容即不合格**，搬回来再交付。

  表体 3–5 个关键选择点，每点编稳定编号（`决策 1`…）。`依据` 列写两段，用 `；` 分隔：①依据本身（锚点，或"命令＋exit code＋结论"）②性质与级别，三选一，写成完整一句：

  - `性质：事实｜去向：正文／盲区／一条判定／常量`
  - `性质：偏好｜级别：阻塞／清单`
  - `性质：待核实｜核实：<跑什么或读哪里>｜结论：<结果>`

  不满足关键选择点定义、但仍影响产出的取舍点，作为**附录行**补在表末（编号 `附录 1`…，字段同上），不占 3–5 个名额。

  **取舍点清单是登记表的派生视图，不单独维护**。按三组摊开 `依据` 列即可，登记表改了清单跟着变：**已问你** `决策N｜你选了 Y｜放弃 Z`；**未问的默认** `决策N｜选了 X，放弃 Y，没问，因为 <清单级理由>`；**事实与待核实** `决策N｜选了 X，放弃 Y｜不问，性质是事实／待核实，去向 <正文／盲区／一条判定／常量>`，待核实的另附结论。
- **核心前提的依据与状态**（锚点或实跑证据）、未核实台账。
- **已知盲区四要素**：盲区名／为何暂不处理／代价／什么条件下必须回来。方案侧只留首尾两项。
- **本轮强度复检**（一行）：仍为原档／改判某档；改判必须写明哪几条判据变了、被撤那一路的职责由谁承接；扫描路是本轮新起、本路兼任还是缺失；本轮是否启用「达上限」例外（是／否，全程一次）。
- 各路身份、职责与状态（未开始／进行中／已完成／失败），附检查覆盖、沿用证据的原版本与限制、问题计数。
- 稳定问题 ID、处置依据、未决项及其归属。
- **实测记录**：哪些可执行类前提做了隔离实验，命令、exit code、关键输出、夹具摘要、临时目录路径，以及原文件指纹的前后复核结果。
- **本轮改动面**：按[主文件](../SKILL.md)第 3 节报三样：触及哪几个决策点；**新增位置清单**，写明哪几条规则被写到上一版没有它的地方；**删除或合并清单**，写明哪几条。两张清单分开列，**不合并计数、不相抵**。删除为零时写「删除 0」，并说明为何无法靠删除或合并解决、必须新增。新增位置不为零时，说明为何不能合并成一处。另写两笔：是否靠新增条款回应了新发现，本轮新增机制数。
- **未核实项台账**：每条写“谁发现的／为何不能核实／由谁在什么时候核实”。处置列只可取“转实施期必办（带验证步骤）／已代跑核实（附结果）／仍开放（附恢复条件）”三者之一。不得连轮原样重复。
- 下一步可执行动作，或退出原因与恢复条件。

记录区常在哈希边界之外：凡含影响信任的断言（“已执行”“主要修法来自评审”），必须附可核证据，否则标注“仅供参考”。

同一目标下换路不重置预算。用户实际替换核心任务时，记录新循环及依据，不通过改名重置轮数。

## 并发与故障恢复

按工具能力并发或顺序完成各路。如果 Agent 名额不足，先保存已完成的意见，再用客户端支持的方式释放资源。如果没有释放接口，顺序继续剩余评审，或报告能力限制。不得省略评审路，也不得把顺序执行说成并发。

某一路明确失败，或有限等待后确认无进展时：

1. 先核对实际状态，正常运行且有进展不算失败。
2. 同一路同一轮最多追加2次恢复尝试，换人和重连共用预算，不新增轮次。
3. 向接续的评审者提供原职责、共同快照、已完成检查和未决项。该评审者不能把他人未核实的结论记成已完成检查。
4. 恢复用尽或环境无法完成所需路线时，保存结果并按“评审未完成”退出。未完成不记为0问题。

完全没有独立 Agent 能力时，按[主文件](../SKILL.md)第 5 节「没有独立评审能力时」处理：只可标注“未独立评审”，不算通过，不伪造评审通过。

## 交付核对

确认最终正文与各路最新结论属于同一版本；纯排版或错字差异已注明且不改变技术含义。哈希模式重新核对正文范围、清单及哈希。变更后必须留下更新记录，不能冒称旧哈希匹配。

存在未经复评的实质修改时进入下一轮；预算用尽时按[主文件](../SKILL.md)第 4 节判交付形态。交付形态只有**通过／部分交付／未收敛退出**三种；判据见主文件第 4 节，本协议不复述。

**"本轮有没有可执行动作"的四种取值**（判据看效果，不看动作，也不看措辞）。①某项取值从"判不出"变成确定值；查清一处符号、跑通一条命令、读懂一节文档均算；②某个此前不合格的落点／锚点／验收核对动作变合格（"补了"不算，必须指出此前不合格、现在合格）；③某个缺口成因被删掉；④某个必须改项的处置要求被满足，能指出改前改后两段文本。**措辞替换本身不算动作。**

## 派发实施材料

通过后真正开跑时，派发内容与评审派发是**两件不同的事**，不得混用。

```text
目标：用户要什么（一行原话）、这次被授权做到哪一步。
方案：<前缀>-v<版本>.md 完整正文。
边界：按方案做；方案列出的停工条件成立时回来问，其余自行决定，不发明规格。
```

派发前逐项删掉下列内容，一条都不留：

- 评审记录、闭环表、修订表、未核实台账、各路限制；
- 评审历史与版本沿革、"第 N 轮才补上的"这类叙述；
- 分歧过程、被否决的候选、某条结论的论证；
- 高／中／低计数、轮数、路数与强度；
- 任何一句以"因为……"开头的解释。

判据一句：**方案正文里已经写了动作和判据，派发消息里就不需要理由。** 消息里出现理由，说明它要么该搬进方案的动作项，要么执行 Agent 根本用不上。

执行 Agent 中途问"当初为什么这么定"：主会话从记录里取答案，翻成"所以照第 N 步做"，**不回灌历史、不贴记录原文**。同一条理由被问第三次，说明方案的动作项或禁区写得不够，改方案，不改派发话术。

工具上无法阻止执行 Agent 读记录时，在派发消息里写明"记录中与决策历史有关的内容不作为你的判断依据"，并说明已暴露。

实施期偏离按[主文件](../SKILL.md)第 5 节写回记录。偏离若改变了执行 Agent 正在做的事，那属于新版本方案，重新交付一份；不得在旧方案上加旁注。
