# 设计理由与沿革

**这是维护者文档，不是运行时指令。** 日常评审不读它；读它的时机只有两个：要改本 skill 的某条规则，或觉得某条规则多余、想删掉它。

理由在这里，规则的正文在 [主文件](../SKILL.md)。两处不一致时以主文件为准，并回来更新本文件。

## 每条硬规则在防什么

改规则前先确认它防的失败还存不存在。不存在才删；只是“看起来啰嗦”不是理由。

| 规则 | 防的失败 | 删掉会发生什么 |
|---|---|---|
| 核心前提必须给锚点四件套 | 用“看起来有依据”代替有依据；片段支持结论而全文推翻它 | 评审变成措辞互评，谁也核实不了谁的断言 |
| 判别表（能否实测 × 失败重数） | 方案每轮都在长条款 | 每个新发现都变成一节新正文，方案越修越不可实施 |
| 已知盲区表 + 移入盲区不算新增条款 | 作者不能承认“这里我不知道” | 承认无知的成本高于加机制，删减永远停不下来 |
| 闭环表 + 位置证据 | 只转发“已修复”，不指到条款 | 复评退化成复述作者的说法 |
| 不按票数／平均分通过 | 用“多数路判低”掩盖真问题 | 最省事的收口方式变成默认方式 |
| 两路结论相反时要求最小验证 | 把可行性分歧当严重度分歧，用“取较高者”糊过去 | 分歧被数字消化，方向错误被计成“低问题” |
| 盲度由派发消息内容定义 | 换了 Agent 就宣称盲评，作者的理由混进消息 | “独立评审”退化成第二个复述者 |
| 每轮只一路全量扫描，扫描路读全文、复用路只读闭环表所引位置 | 每轮全路重读全文，成本与收益脱钩；“是否真做了全量检查”不可观察，会退化成口号 | 复用路被要求全量重读，成本回升，规则被绕过；或者复用路凭记忆判关闭，闭环表失去证据 |
| 作者不逐条枚举一致性结论 | 作者枚举的永远是他想到的那些 | 修补引入的新缺陷几乎总落在条款交界处，而作者的系统性自查正是从这里漏过去；交界处的交叉改由复评方按闭环表和锚点核对 |
| 替代解法分甲乙丙三档 | 用“要不要加一路”这一个开关处理三种不同尺度的改动 | 小事惊动整条路线重估，大事又被当成局部修补 |

## 已删除的规则与删除理由

这些规则曾经存在，删掉时各自的保护意图都还在，但换成了别的机制来实现。不要在维护时把它们改回来。

**固定三路（“简单方案也用三路，不为简化任务减少路数”）。** 防的是作者用“这个很简单”逃掉评审。意图成立，机制选错了：它取消了判断，而不是让判断留下痕迹。现由“两路／三路按失败代价选，依据写进记录，不得降到一路”承接——沉默跳过仍然被禁止，成本随风险变化。

**预算用尽后的 diff 复评（最多 2 轮）。** 防的是在“为一行修订重开整轮”和“把未收敛写成通过”之间做不诚实的记账。但它与“契约精度修订按普通复评处理”以及“预算用尽交付未复评状态”两处互相覆盖，同一个状态下出现三种答复，现场必然按最省的一种解释。现在改的是成本端：每轮只有一路做全量扫描，一轮本来就很便宜，不需要第二个出口。

**面积不增长（条款数＋参数数＋验收项数）。** 防的是方案膨胀。但计数会诱发合并与改写以规避计数，“条款”本身也没有可数的定义，最后变成一条被普遍忽略的规则。现由内容判据承接：“删掉这条，会不会有人因此做错决定？”不会就不要加。

**“第 3 轮两点满足即加第四路”的机械规则。** 只看方案是否通过，看不出问题性质，会把“方向正确、精度不足”的方案强制换路。现由“换不换路看改动尺度”承接。

**通过闸写成“各路高0／中0”。** 计数同时是终点线，又被禁止追求（“不得为计数归零开轮”），作者被迫在“优化计数”和“别优化计数”之间做隐性选择，最常见的结果是降严重度。现由闭环表承接：每条问题都要有开／关判定，关闭项要指到正文位置；计数降为摘要。

**路名写作 A／B／C。** 三档替代改用甲乙丙之后，字母与档位的对应关系已经消失，留着只会让“路 C”和“丙档”被读成同一件事。现在三路一律用中文全名。

## 为什么不评分、不投票、不设加权

评分把“能不能直接开工”替换成一个与它没有稳定关系的数。一旦有数，作者优化数，评审者优化数，而方案是否可实施无人负责。同理，多数票把“没人反对”当成了“没有问题”，而单路发现的真问题恰恰是票数最少的那类。

## 维护检查清单

改这个 skill 时逐条过一遍：

1. **这条规则防的失败，现在还发生吗？** 发生过就保留并写清触发条件；从没发生过、只是听起来稳妥的，删。
2. **它会不会和已有规则给出不同答复？** 同一个状态下出现两种答复，现场一定选省事的那个。先消除冲突，再加内容。
3. **判断依据是可观察的吗？** “是否真正独立”“是否理解了”不可观察，作者既不能设定也不能证明；“派发消息里有没有作者的理由”可观察。不可观察的判据会被绕过。
4. **完成标准可检查吗？** “覆盖充分”不可检查，“每条问题有开／关判定且关闭项有位置”可检查。
5. **删掉的规则其保护意图由谁承接？** 没有承接就不要删；有承接就在本文件记一笔，否则下一任维护者会把缺口当遗漏补回去。
6. **这次的改动能用一句话说清它改了什么判断吗？** 说不清就说明它只是措辞变动，别动结构。
7. **同一条规则只有一个维护点。** 详细分支放 references，主文件只留动作、条件、完成标准。

## 已知的残余风险

- 主文件仍是单页读完的体量，长方案评审时会占用可观上下文；若将来出现“读了主文件就急着开工”的案例，先检查每节的完成标准是否清楚，再考虑拆分，不要为字数拆。
- “两路”与“三路”的边界靠失败代价判断，作者仍有解释空间。锚点写成了可列举的四条（可逆／单模块／不改用户可见行为／无迁移），但组合判断仍可能偏差；出现偏差时改这四条，不要改成更抽象的原则。
- 替代路乙档的“换组件”与对抗路的“局部修复”在边界上可能重叠；重叠不构成缺陷，两路结论一致时按合并处理即可。
