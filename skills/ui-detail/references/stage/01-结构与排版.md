# 01 · 结构与排版

> **适用**：要定页面骨架时：选容器（Dialog/Drawer/Popover/Tooltip/Toast/Banner）、区分导航与 Tabs 与分段控件、定间距与字号档位、收敛对齐线、定断点与响应式行为。
> **不适用**：容器已定、只处理某个控件的交互手感（02），或只需核对颜色与对比度（05）时。
> **读完能判定**：本轮该先改结构还是先改控件；容器与切换控件该怎么选；间距字号落哪一档；对齐线收敛到几条；断点定在哪。

先定骨架，再写控件。这一层改起来最贵：容器选错、对齐线太多、字号阶梯混乱，后面每个组件都要返工。

细则与理由：[01 浮层](../detail/01-浮层.md))、[02 导航与表单](../detail/02-导航与表单.md))、[03 布局与排版](../detail/03-布局与排版.md))。

## 先选容器，再写组件

按顺序回答，答案决定容器：

1. 处理它时还要不要操作背后的页面？要 → 模态 Dialog / Drawer / Sheet。
2. 内容依附某个按钮或字段？是 → 可交互选 Popover 或菜单，不可交互选 Tooltip。
3. 不依附、持续展示？→ 页面区域 / Banner / 通知中心。
4. 不依附、短时反馈？→ Toast / Snackbar。

硬规则：

- 遮罩只是视觉表现；模态 = 阻断背景交互 + 焦点留在内部 + 通常 Esc 关闭。
- Tooltip 不接收焦点、不承载可聚焦内容；图标按钮必须有独立可访问名称，不能只靠 Tooltip 提供。
- 需要处理、需要回看的信息不做 3 秒 Toast；给它持续可见的入口。
- 可撤销的低风险操作用"撤销"代替确认框；不可逆或高后果操作要说明对象与后果，按钮写"删除项目"而不是"确定"。
- 开与关是一份契约：记录触发元素 → 打开后设初始焦点 → Esc 与关闭按钮 → 关闭后焦点回触发元素（对象已消失则回退到列表中合理位置）。
- 遮罩点击是否关闭要单独约定；有未保存内容时进入保存/放弃流程。
- `z-index` 无效先查祖先是否创建层叠上下文（`transform`、`opacity`、定位、`contain`）。原生 `dialog.showModal()` 与打开的 Popover 位于 top layer，靠更大的数字盖不过。
- 只约定层级义务（页面 / 浮层 / 全局反馈），不约定"Toast 永远最高"；模态期间的背景通知应延后或进入消息中心。

## 三种切换别混用

| 用户的问题 | 用 | 判定 |
|---|---|---|
| 我去哪个区域 | 导航链接 / Sidebar / Nav | 有 URL，可返回、刷新、分享 |
| 当前区域看哪一块 | Tabs | 有对应面板，键盘按标签模式 |
| 同一份内容换种看法 | Segmented / Radio | 互斥值，不产生导航 |

- 控件实际是导航就保留链接语义，不为了"切换"牺牲新标签打开与地址复制。
- 路由变化后：更新标题 → 焦点移到标题或主区域（`tabindex="-1"` 只供程序聚焦）→ 必要时播报一次，不与焦点移动重复朗读。
- 从列表进详情再返回：恢复原筛选、滚动与焦点；后台刷新不得抢焦点、不得一律滚回顶部。
- URL 已是项目 B、主体还是可操作的项目 A，属严重状态错误：显示明确加载区，或保留旧内容并标为暂不可操作。
- 深链对象已删除或无权限：说明原因 + 返回入口，不要静默跳首页。
- 步骤条允许回退不等于所有步骤都能重开；说明可改范围，别承诺付款、签署步能点回。

## 间距与字号

- 用父容器 `gap` 组织同级元素；Label 到控件 8px、字段间 24px、区块间 32–40px 是起点。
- 一屏内的间距档位控制在 4–6 个；出现 13px、27px 这类孤立值，说明在复制别处布局。
- 字号按角色定，不按倍数猜：辅助 .875rem / 界面正文 1rem、行高 1.5–1.7 / 中文长文 1.7–1.9 / 小标题 1.25rem / 页面标题 1.75rem。
- 中文行宽先试每行 30–40 汉字，用 `ic`/`ch` 近似 + `max-inline-size` 兜底。
- 金额、计时用 `tabular-nums`；小数点对齐靠布局，不靠字体。
- 紧凑行高、等宽数字、细字重都不是"通用更好"：触屏、多行、放大文字时复查是否被裁或难读。
- 长文留意孤行寡行；截断时提供可键盘与触屏使用的完整阅读方式，关键金额与错误原因不能只剩省略号。

## 几何对齐：先收敛对齐线

- 一个区块 1–2 条纵向对齐线。加新元素先问"贴哪条线"，不是"离左边多少"。
- 参照物优先级：容器内边距 > 栅格 > 相邻元素 > 各自居中。
- 长文本居中 = 右缘参差 + 每行起点漂移；居中留给短内容、成对元素、空状态、登录卡片。
- 对齐目标要选：Label 上置对齐左缘；左栏式表单可右对齐 Label；数值列向尾侧对齐；表头与数据同一条线。
- 行首有符号、序号、悬挂标点时，缩进对齐到正文首字，不对齐符号边缘。

## 视觉对齐：墨迹也要齐

判定顺序：这条边该不该存在（几何）→ 数值是否收敛到一条线（几何）→ 墨迹是否也齐（视觉）。跳过前两步的微调不算对齐。

- 盒子里装着看不见的空白：行盒的 ascent/descent、字母侧边距、图标 viewBox 留白、图形不铺满外接框。对齐包围盒不等于对齐墨迹。
- 字体自带的 overshoot（O、o、C、S 略超基线）不要自己再补；要补的是图标与自绘图形。
- 图标按视觉尺寸配字：20px 图标配 16px 正文、24px 配 20px 小标题；viewBox 留白要计入。
- 三角形、对勾、箭头、徽标的重心不在包围盒中心，需要 0.5–1px 补偿；同尺寸的圆在方形里显得更小，可略放大。
- 单行按钮/标签/输入框文字：上下 padding 相等 ≠ 视觉居中（ascent 与 descent 不对称）。先对称 padding + 固定 `line-height`，支持时用 `text-box-trim` 裁掉多余 leading。
- 圆角嵌套 `内圆角 = max(0, 外圆角 − 间距)`，间距含边框宽度；1px 与 2px 描边、有阴影与无阴影并排时，视觉重量要单独平衡（减 padding 或让描边向内）。
- 下划线、分隔线用 `padding-bottom` 定位，不用负 margin 拉。
- 偏移门槛：0.5–1px（约 0.02–0.05em），最多 2px，写成带注释的变量。超过这个量级就回去改布局或参照系。
- 补偿只改绘制：热区、焦点环、对比度不动。为"看着齐"缩小点击区域是严重问题。
- 不动的场合：数据密集表格逐列微调、多语言界面写死 px 偏移、字体与文案未定的早期阶段。

## 布局与响应式

- Grid 管行列、Flex 管主轴，可以嵌套；不需要为一致性只挑一个。
- 断点由内容挤压点决定，不由设备名单决定：把真实长项目名、长按钮文案放进去找位置。
- 组件在主区/侧栏复用时用容器查询；页面级导航与整体切换才用媒体查询。
- 视口：`dvh` 跟随动态视口，`svh` 更稳定；sticky 失效先查祖先进滚动容器与可滚动空间。
- 约 320 CSS px 宽仍可读，主要内容纵向重排；水平数据表可单独滚动，整页不得横向溢出。
- 验收用长项目名、空字段、200% 缩放与窄屏，不用整齐的占位文本。
