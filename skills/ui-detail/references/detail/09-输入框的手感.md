# 09 · 输入框的手感：聚焦、打字与反馈如何连续

> **适用**：输入框出现打字延迟、光标乱跳、中文输入法抢跑、搜索建议乱序、浮动标签盖字或报错时页面狂跳，需要把视觉状态、输入不中断与异步结果分开排查时。
> **本轮不可交付时**：若页面里没有任何文本输入，停下并说明「无输入框」，回 SKILL.md 按对象重挑一篇；若问题已定位到按钮、列表或浮层开合，改读 [10](10-按钮与选择器.md)、[11](11-表格与列表.md) 或 [12](12-浮层的开合与定位.md)。
> **读完能判定**：这个输入框有哪些状态会同时存在、错误态与聚焦态是否互相覆盖；焦点过渡缓到什么程度、边框该不该在聚焦时加粗；浮动标签的收起条件、自动填充与程序改值是否覆盖；错误提示该预留空间还是切换内容；输入值是否立即更新、只把请求延后；「40 个字符」按码元、码点还是字素簇算；防抖起点、请求代次、组合输入期间是否发请求。

## 一、先判

1. **分三层查**：视觉状态、输入过程、异步结果；只给输入框加一个 `transition` 只能解决其中一部分，三件事要分别检查，才知道「丝滑」究竟来自哪里。
2. **状态会叠加**：出错后再次获得焦点，要同时表达「有错误」和「你正在操作它」，不能用红边框把焦点标记覆盖掉。
3. **聚焦只缓颜色、背景或强调线**：约 120–180ms 是项目起点的试用值，不是标准；焦点位置仍需及时、清楚地可见，焦点环不参与渐变，错误边框与焦点外圈可以同时保留。避免 `transition: all`，它会把后来改动的宽高、内边距甚至错误提示布局都纳入动画。
4. **别在聚焦时把边框从 1px 改成 2px**：内容区或外部尺寸会变；确实需要粗边框就预留相同厚度，或用不占布局空间的轮廓表达。`box-sizing: border-box` 也不保证内部文字完全不动。
5. **浮动标签的收起条件是「聚焦或已有值」**，不能只判断 Focus；还要覆盖首次载入已有值、浏览器自动填充与密码管理器回填、程序重置或外部更新、长标签与放大字体与错误态不撞边框、不支持相关选择器的环境仍由真正的 `<label>` 提供名称。固定在框外的 Label 往往更简单可靠，浮动标签不是必选设计；`transform` 位移缩放不改变布局占位，不能指望它自动帮文字腾位置。
6. **错误提示要么预留一行空间，要么稳定保留辅助说明区再切换内容**；长错误自然换行，不能为固定高度裁掉。只改 `opacity: 0` 不会让内容退出可访问性树，也不一定取消内部交互——错误是否存在、是否播报与它怎么淡入要分别管理，高频输入时不要每个字符都重播同一条错误。必要时可以对高度变化做短过渡，但要考虑测量、缩放和滚动位置，并非每个表单都值得引入动态高度动画。
7. **显示值与请求分开**：输入值和光标立即响应，搜索、预览、统计和请求可以延后，不要把显示在框里的值也等 300ms 才更新。受控输入要在事件里及时同步当前值并保持 DOM 节点稳定，每输入一个字符就用新 `key` 重建组件，容易丢焦点、破坏选区、打断输入法。
8. **边输边格式化要维护选区与字符位置映射**：金额、手机号最容易造成光标跳到末尾，需要覆盖中间插入、选中替换、粘贴、删除和撤销，不能只测末尾连续输入。也不要为「键盘输入更整齐」拦截所有非数字按键，粘贴、辅助技术、输入法、负数和小数各有路径，`inputmode` 是键盘提示，不替代最终的数据校验。
9. **值变化的入口不只 `keydown`**：剪切、撤销重做、语音听写、浏览器拼写纠正、手机自动替换都会改内容，用 `input`、`beforeinput` 与 `inputType` 观察；`beforeinput` 并非所有环境与所有编辑方式下都能可靠取消，尤其要查输入法和自动填充；不能以「拦住所有 beforeinput」代替输入后的校验与状态修正。脚本直接设 `.value` 不会派发 `input`，程序回填、表单重置和外部状态更新也要走明确的同步入口。
10. **先定「40 个字符」的口径**：`length` 通常计算 UTF-16 码元，码点数与字素簇数又不同；前端显示的计数、原生 `maxlength` 与后端限制必须一致。按人眼看到的字符计数就用 `Intl.Segmenter` 并要求服务端兼容，接口按字节就说明，不伪装成同一个「字数」；超限不要任意 `slice` 切坏 Emoji，也不要在 IME 组合期间反复截断候选文本。
11. **组合输入期间不发搜索**：用 `compositionstart`、`compositionend` 与 `isComposing` 处理，并在目标浏览器与输入法上验证事件顺序；Enter 还可能用于确认候选词，不能一律解释为提交表单或选择建议。
12. **远程搜索按「新字符立刻作废旧代次」组织**：约 150–300ms 是防抖起点（项目起点，按任务和接口调整）；取消请求能节约资源，代次检查用于保证正确性，两者作用不同。
13. **尾部控件与自动增高各管一处**：清除按钮在有内容时出现、预留尾部空间、用真实按钮并给名称，不要只监听鼠标按下而漏掉键盘和触屏，清除后把焦点留在或交回输入框并同步筛选、校验与请求状态；密码显示切换要保留输入值与合理的焦点、选区，说明当前是显示还是隐藏，用合适的 `autocomplete`、`type` 和字段名帮密码管理器，不要用屏蔽自动填充来掩盖浮动标签错误。多行自动增高按内容测量并设定最大高度、之后改为内部滚动，注意 `scrollHeight` 与 padding、border 的盒模型关系；逐字输入应即时贴合内容，反复播放高度动画反而可能让光标追不上。

## 二、做完的标准

- [ ] 在搜索框里把真实输入路径走一遍：慢打、快速连续输入、从中间插入、选中替换、粘贴、撤销都对（不只测末尾连续输入）；再用中文输入法打「官网」——组合期间不发请求，选词结束后只按最终串发一次；把网络调慢让较早请求较晚返回，界面显示的是当前输入的结果。
- [ ] 自动填充后再编辑，浮动标签的收起状态与值一致；切到错误态时下一个控件位置不动或位移可解释；清空搜索后建议与默认列表同时恢复；贴多段文字到最大高度后转内部滚动，当前编辑位置仍可见。
- [ ] 关掉动效后重复一遍：字和光标是否跟手、周围布局是否稳定、结果是否对应当前输入、键盘和输入法是否正常——四件事都不依赖动画成立。

## 三、依据与数值

- `120–180ms`（聚焦过渡）、`150–300ms`（远程搜索防抖）与正文的 `300ms` 都是**项目起点**的示例值，不是标准；按任务与接口调整。
- 字符口径（UTF-16 码元 / 码点 / 字素簇 / 字节）没有跨端标准，由**项目约定**决定，前端显示、`maxlength` 与后端限制必须一致。本篇没有 WCAG 条号或对比度门槛要满足，焦点可见性与对比度的门槛不在本篇。

## 四、控件、表格与示例

状态可以同时存在：

| 状态 | 用户需要知道 | 合适的表达 |
|---|---|---|
| 默认、空值 | 在这里填什么 | 持续可见的 Label，必要时给示例 |
| Hover | 这里可以操作 | 轻微改变边框或背景，触屏不依赖它 |
| Focus | 现在输入到哪里 | 清晰可见的焦点指示，必要时配合强调线 |
| 已有值、未聚焦 | 填过什么 | 保留内容，标签不覆盖文字 |
| 校验中 | 正在查重或检查 | 局部状态，不冻结输入 |
| Invalid | 什么地方需要修正 | 就近错误文字、状态语义与视觉提示 |
| Readonly / Disabled | 能否修改、为什么 | 区分只读与禁用，不只调透明度 |

一个可实施的搜索时序如下；这里描述行为，具体事件接线由框架决定：

```text
每次输入变化：
  立即保留当前输入值
  让上一代请求结果失效，清除旧的防抖任务
  若为空：清空建议、恢复默认列表，结束
  若仍在组合输入：暂不发搜索请求，结束
  安排一次防抖搜索

组合输入结束：
  以最终输入值重新安排搜索，合并随后重复触发的输入事件

防抖任务执行：
  保存本次查询与请求代次；需要时取消旧请求
  返回后只接受仍属于当前查询、当前代次的结果
```

聚焦过渡的局部样式示例，仍需正确关联 Label、说明与错误，并验证主题下的对比度：

```css
.field-input {
  box-sizing: border-box;
  inline-size: 100%;
  padding: .625rem .75rem;
  border: 1px solid var(--border-control, #767676);
  border-radius: .5rem;
  background: var(--surface-panel, #fff);
  color: var(--text-primary, #1f1f1f);
  transition: border-color 140ms ease-out,
              background-color 140ms ease-out;
}
@media (hover: hover) and (pointer: fine) {
  .field-input:not(:disabled):hover {
    border-color: var(--text-secondary, #595959);
  }
}
.field-input:focus {
  border-color: var(--focus-ring, #005fcc);
}
.field-input[aria-invalid="true"] {
  border-color: var(--text-danger, #b42318);
}
.field-input:focus-visible {
  outline: 3px solid var(--focus-ring, #005fcc);
  outline-offset: 2px;
}
@media (prefers-reduced-motion: reduce) {
  .field-input { transition: none; }
}
```

## 五、失败长相与边界

- **字打出来比手慢、每按一下都卡** → 显示值被防抖或请求拖住了；值同步留在输入事件里，只把请求延后。
- **从中间插入或粘贴后光标跳到末尾** → 没有维护选区与字符位置映射；保存原始编辑文本失焦后再格式化，或边输边做字符位置映射。
- **错误文字一冒出来，下一个输入框和本来要点的按钮一起下移** → 没预留说明空间；预留一行或稳定保留辅助说明区再切换内容。
- **浮动标签盖住已填的字；自动填充后标签状态不对** → 收起条件只看 Focus，或只用 `:placeholder-shown` 判断空值；按「聚焦或已有值」判断并覆盖回填路径。
- **新输入下面是旧查询的建议** → 请求代次没有在新字符输入时就失效；先作废旧代次，再取消请求。
- **按 Enter 提交了半截拼音** → 没有覆盖组合输入中的按键行为。
- **边界**：只读与禁用要分开表达，不只调透明度；`opacity: 0` 不退出可访问性树，也不一定取消内部交互；`inputmode` 不替代校验。自绘平滑光标是另一层面的优化（见 [13-平滑光标](13-平滑光标.md)），`transform` 动画有机会降低移动阶段的开销，但不能因此把整个方案描述成「没有布局成本」，也不能用来修饰受控输入重建、输入法中断或慢计算造成的卡顿。
