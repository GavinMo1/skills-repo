# 09 · 输入框的手感：聚焦、打字与反馈如何连续

> **适用**：输入框出现打字延迟、光标乱跳、中文输入法抢跑、搜索建议乱序、浮动标签盖字或报错时页面狂跳，需要把视觉状态、输入不中断与异步结果分开排查时。
> **不适用**：页面里没有文本输入，或问题已定位到按钮、列表、浮层开合（10、11、12）时。
> **读完能判定**：这个输入框有哪些状态会同时存在、错误态与聚焦态是否互相覆盖；焦点过渡缓到什么程度、边框该不该在聚焦时加粗；浮动标签的收起条件、自动填充与程序改值是否覆盖；错误提示该预留空间还是切换内容；输入值是否立即更新、只把请求延后；「40 个字符」按码元、码点还是字素簇算；防抖起点、请求代次、组合输入期间是否发请求。

在项目搜索框输入“官网”，边框柔和地变亮，建议列表自然出现，打字时文字紧跟手指，清空后列表马上恢复。这里至少有三件事在配合：视觉状态平滑过渡、输入过程不中断、异步结果跟得上当前意图。

只给输入框加一个 `transition`，只能解决其中一部分。先把这三件事分别检查，才知道“丝滑”究竟来自哪里。

## 先列状态，避免几个效果互相覆盖

| 状态 | 用户需要知道 | 合适的表达 |
|---|---|---|
| 默认、空值 | 在这里填什么 | 持续可见的 Label，必要时给示例 |
| Hover | 这里可以操作 | 轻微改变边框或背景，触屏不依赖它 |
| Focus | 现在输入到哪里 | 清晰可见的焦点指示，必要时配合强调线 |
| 已有值、未聚焦 | 填过什么 | 保留内容，标签不覆盖文字 |
| 校验中 | 正在查重或检查 | 局部状态，不冻结输入 |
| Invalid | 什么地方需要修正 | 就近错误文字、状态语义与视觉提示 |
| Readonly / Disabled | 能否修改、为什么 | 区分只读与禁用，不只调透明度 |

这些状态可以同时存在。输入框出错后再次获得焦点，应同时表达“有错误”和“你正在操作它”，而不是用红边框把焦点标记覆盖掉。

## 聚焦过渡：颜色可以缓，位置不要跳

常见优化是让边框颜色、背景或强调线在约 120–180ms 内过渡。这只是试用起点；焦点位置仍需及时、清楚地可见。

```css
.field-input {
  box-sizing: border-box;
  inline-size: 100%;
  padding: .625rem .75rem;
  border: 1px solid var(--border-control, #767676);
  border-radius: .5rem;
  background: var(--surface-panel, #fff);
  color: var(--text-primary, #1f1f1f);
  transition: border-color 140ms ease-out,
              background-color 140ms ease-out;
}
@media (hover: hover) and (pointer: fine) {
  .field-input:not(:disabled):hover {
    border-color: var(--text-secondary, #595959);
  }
}
.field-input:focus {
  border-color: var(--focus-ring, #005fcc);
}
.field-input[aria-invalid="true"] {
  border-color: var(--text-danger, #b42318);
}
.field-input:focus-visible {
  outline: 3px solid var(--focus-ring, #005fcc);
  outline-offset: 2px;
}
@media (prefers-reduced-motion: reduce) {
  .field-input { transition: none; }
}
```

这是局部样式示例，仍需正确关联 Label、说明与错误，并验证主题下的对比度。焦点环不参与渐变，避免它慢慢出现；错误边框与焦点外圈可以同时保留。

不要在聚焦时突然从 1px 边框改成 2px，导致内容区或外部尺寸变化。确实需要粗边框时，预留相同厚度，或用不占布局空间的轮廓表达。`box-sizing: border-box` 也不保证内部文字完全不动。

避免 `transition: all`：它可能把后来改动的宽高、内边距甚至错误提示布局都纳入动画。明确列出要变化的属性，通常更容易控制。

## 浮动标签：为空、聚焦、已有值要一起考虑

有些输入框的标签初始位于框内，聚焦后向上移动并缩小，叫 floating label。它能把“提示位置”变成稳定的字段名称，但不是必选设计；固定在框外的 Label 往往更简单可靠。

若使用浮动标签，收起条件应该类似“**聚焦或已有值**”，不能只判断 Focus。还需覆盖：

- 页面首次载入已经有值、浏览器自动填充、密码管理器回填。
- 程序重置或外部更新值后，标签状态同步变化。
- 长标签、放大字体、错误态时，标签不撞上边框或输入文字。
- 不支持相关选择器的环境有可用退路，名称仍由真正的 `<label>` 提供。

`transform: translate… scale…` 可用于标签位移与缩放，预留好标签空间，并选择合适的 `transform-origin`。变换不改变布局占位，不能指望它自动帮文字腾位置。只用 `:placeholder-shown` 判断是否为空，对日期、自动填充等情况需要额外验证。

## 错误提示出现：既不突然跳，也不无限留空

错误文字冒出来时，下一个输入框瞬间下移，鼠标原本要点的按钮也移动了。这种跳动比边框是否有渐变更影响手感。

可以给短说明预留一行空间，或稳定保留辅助说明区域，再切换其中内容。长错误应自然换行，不能为了固定高度裁掉。必要时可以对高度变化做短过渡，但要考虑测量、缩放和滚动位置；并非每个表单都值得引入动态高度动画。

只改 `opacity: 0` 不会自动让内容退出可访问性树，也不一定取消内部交互。错误是否存在、是否播报与它怎么淡入，要分别管理。高频输入时不要每个字符都重播同一条错误。

## 打字跟手：不要把输入本身防抖

输入值和光标应立即响应。耗时搜索、复杂预览、统计和请求可以延后，不要把显示在输入框里的值也等 300ms 才更新。

受控输入要在事件里及时同步当前值，并保持 DOM 节点稳定。每输入一个字符就用新 `key` 重建组件、整块卸载再挂载，容易丢焦点、破坏选区，也会打断中文输入法。

金额、手机号等格式化尤其容易造成光标跳到末尾。需要处理从中间插入、选中替换、粘贴、删除和撤销，不能只测试在末尾连续输入。可以保存原始编辑文本，失焦后格式化；必须边输边格式化时，要维护选区与字符位置映射。

不要为了“键盘输入更整齐”拦截所有非数字按键。粘贴、辅助技术、输入法、负数和小数都有各自路径。`inputmode` 是键盘提示，也不替代最终的数据校验。

## 输入不只来自键盘

剪切、撤销与重做、语音听写、浏览器拼写纠正、手机自动替换，都可能改变输入内容。`keydown` 适合处理明确的快捷键，不适合作为“值变化”的唯一入口。值同步与派生处理应围绕实际输入状态展开。

`input` 表示编辑导致的值变化，`beforeinput` 可在某些编辑执行前观察意图，`inputType` 帮助区分插入、删除和历史操作。不过 `beforeinput` 并非所有环境与所有编辑方式下都能可靠取消，尤其要检查输入法和自动填充。不能以“拦住所有 beforeinput”代替输入后的校验与状态修正。

直接通过脚本设置 `.value` 不会自动派发 `input`。程序回填、表单重置和外部状态更新也要走明确的同步入口，避免正文已变化、标签或自绘光标仍停在旧状态。

## “40 个字符”究竟怎么算

JavaScript 的字符串 `length` 通常计算 UTF-16 码元；码点数、用户感知的字素簇数又可能不同。一个家庭 Emoji 可能由多个码点组成，带组合附加符的字母也不一定只占一个码元。前端显示的计数、原生 `maxlength` 的模型与后端限制必须采用清楚、一致的约定。

若产品按“人眼看到的字符”计数，可以用目标环境支持的 `Intl.Segmenter` 按字素簇分段，并让服务端采用兼容规则。若接口实际限制字节数，也应说明，不要把它伪装成同一个“字数”。

超限不应通过任意 `slice` 切坏 Emoji，也不要在 IME 组合期间反复截断候选文本。可以提示超出量并在提交时阻止，或在组合结束后按已约定的字符边界处理；保留可修正与撤销的路径。

## 中文输入法与搜索请求

拼音输入期间的中间字符串，不一定是用户打算搜索或提交的内容。通过 `compositionstart`、`compositionend` 和输入事件的 `isComposing` 等信息处理组合过程，并在目标浏览器与输入法上验证事件顺序。

一个可实施的搜索时序如下；这里描述行为，具体事件接线由框架决定：

```text
每次输入变化：
  立即保留当前输入值
  让上一代请求结果失效，清除旧的防抖任务
  若为空：清空建议、恢复默认列表，结束
  若仍在组合输入：暂不发搜索请求，结束
  安排一次防抖搜索

组合输入结束：
  以最终输入值重新安排搜索，合并随后重复触发的输入事件

防抖任务执行：
  保存本次查询与请求代次；需要时取消旧请求
  返回后只接受仍属于当前查询、当前代次的结果
```

约 150–300ms 可作为远程搜索的防抖起点，但应按任务和接口调整。新字符输入时就让旧请求失效，别等新请求真正发出才更新代次，否则防抖间隙里旧结果仍可能覆盖界面。取消请求能节约资源，代次检查用于保证正确性，两者作用不同。

Enter 还可能用于确认输入法候选词。不能一律把它解释为提交表单或选择搜索建议，必须覆盖组合输入中的按键行为。

## 清除、密码切换与自动增高

清除按钮适合在有内容时出现，预留尾部空间，避免文字区域突然变宽变窄。用真实按钮并提供名称；清除后通常把焦点留在或交回输入框，同时正确更新筛选、校验和请求状态。不要只监听鼠标按下，漏掉键盘和触屏。

密码显示切换应保留输入值与合理的焦点、选区，说明当前是显示还是隐藏。允许粘贴，使用合适的 `autocomplete`、`type` 和字段名称帮助密码管理器；不要用屏蔽自动填充来掩盖浮动标签错误。

多行文本自动增高可以按内容测量高度，并设定最大高度，之后改为内部滚动。注意 `scrollHeight` 与 padding、border 的盒模型关系。逐字输入时通常应即时贴合内容，反复播放高度动画反而可能让光标追不上。删除长段文本、从中间换行、粘贴大量内容时，都要保持当前编辑位置可见，避免页面跟着上下抽动。

## 进一步：让插入光标平滑移动

还有一种更细的优化：保留原生输入控件，隐藏它的插入光标，自绘一个装饰光标，让它在新旧插入点之间短促滑动，输入时保持可见、空闲后再闪烁。这与边框渐变、减少输入延迟是不同层面的优化。

它需要镜像测量、坐标与字体缓存、动画调度，以及选区、中文输入法和系统偏好的降级处理。`transform` 动画有机会降低移动阶段的开销，但不能因此把整个方案描述成“没有布局成本”。具体原理与适用边界见[第 13 篇：平滑光标](13-平滑光标.md)。

## 用这组动作检验“顺滑”

先慢打，再快速连续输入；从中间插入、选中替换、粘贴和撤销；用中文输入法选词并按 Enter；自动填充后再编辑；切换错误态；清空搜索；粘贴多段文字让输入框达到最大高度。把网络调慢，让较早请求较晚返回。

观察四件事：**字和光标是否跟手、周围布局是否稳定、结果是否对应当前输入、键盘和输入法是否正常。** 最后关闭动效再重复，核心交互仍应完整。
